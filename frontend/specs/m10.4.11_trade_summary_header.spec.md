# Spec: M10.4.11 Trade Summary Header (dashboard P&L + trade-state counts, per user, period switch)

Purpose: On the Trader dashboard (`/app/trading`, TradePane) show one full-width header with
the signed-in user's **total P&L** and the three trade-state counts (**active / closed /
rejected**), switchable across **day, week, month, year, all-years** periods.

Human directive 2026-09-30: "dashboard show trades info, active closed, rejected, at the
header total profit and loss etc for day, but we should week month and yr and yrs for each
user — lgtm lgtm go on". Standing LGTM recorded for Step 4; full slice ran §2 order.

Inputs:
- Period: local component state, `TradeSummaryPeriod = "day" | "week" | "month" | "year" | "all"`,
  default `"day"`, rendered with human labels Day (current day) / Week / Month / Year / All.
  **Amendment A1 (pre-impl, conflict found):** keys are lowercase period words, NOT `1D/1W/...`,
  because M10.4.10's app-wide ban on timeframe literals (`"1D"`, `"1H"`, `"4H"`) scans all of
  `app/` — established protection untouched, this newcomer adapts; the human's `1D = Day`
  directive is honored by the button label "Day" (current day).
- Data: `MOCK_TRADE_SUMMARY: Record<TradeSummaryPeriod, TradeSummary>` in `mock_trader_data.ts`
  — every value precomputed in the mock file (backend-owned aggregates, frontend displays only,
  `frontend_spec.md` money law). Field names cited from contracts: `user_id`/`broker`
  (`portfolio.py`), `Order.state` buckets (`order.py`).
- Formatters: `signedMoney` from `surface_ui.tsx` (shared, no local formatting).

Outputs (rendered):
- `Total P&L` — signed, 2dp, tone `is-positive` / `is-negative` (existing classes, no new colors).
- `Active` / `Closed` / `Rejected` — integer counts, shown even when 0.
- Period toggle: exactly 5 buttons, keys `day week month year all` (Amendment A1) rendered
  with human labels **Day (current day) / Week / Month / Year / All**, `aria-pressed`,
  `role="group"`, `title` reads `Current day` / ... / `All periods`.
- Mock provenance note (honesty law: mock data is labeled).

Invariants:
- Presentation only: **no aggregation math in the component** (no `.reduce`, no deriving from
  `MOCK_ORDERS`, no `toLocaleString` — use shared formatters). Counts/P&L are precomputed mocks.
- Zero I/O: no `fetch` / `WebSocket` / `EventSource` (mock law; payload wiring lands with M6/M7).
- Per-user: each record carries `user_id` + `broker`; header renders the record for the
  current period only. Real per-account wiring arrives with the M6/M7 endpoints (Out of scope).
- Layout: header is the first child of `.trade-pane` with `grid-column: 1 / -1` so the
  chart/ticket two-column grid is untouched below it; ≤900px the existing `.trade-pane`
  single-column rule stacks it.
- Privacy: rendered only inside TradePane (route already Viewer-gated via `AccessPreview`);
  HomeDashboard is the public Viewer surface and must NOT get this component.

Edges:
- Unknown/missing period key → fall back to the `"day"` record (`?? MOCK_TRADE_SUMMARY["day"]`),
  never render `undefined`.
- `total_pnl: null` → `—` (signedMoney's null handling), neutral tone, no crash.
- Count `0` → renders `0` (not hidden).
- Period set is closed: exactly the 5 keys in `TRADE_SUMMARY_PERIODS`, no others.
- Negative P&L month exists in mock (month is a losing period) → minus sign + `is-negative` tone.

Correct: display of backend-owned numbers (`signedMoney` 2dp, en-dash minus); buckets:
active = `Order.state` in pending/submitted/acked/partially_filled; closed = filled (trade
complete); rejected = `rejected`. Day counts hand-reconcile to `MOCK_ORDERS` (2 active
[pactly_filled+unknown], 1 closed [filled], 1 rejected) — larger periods are mock growth.

Adversarial: unknown period key fallback; banned-construct scan (aggregation/I/O/hex colors);
missing record fields would fail the record-shape test at mock-authoring time.

Tests: `frontend/tests/test_m10.4.11_trade_summary_header_spec.py` (9 tests, text-parses
app sources; `_REPO = Path(__file__).resolve().parents[2]` cross-tree convention).

Out of scope: real endpoint wiring (M6 order-result + M7 portfolio APIs), per-trading-account
breakdown, sparkline/history chart, HomeDashboard placement, export/CSV, admin cross-user view.

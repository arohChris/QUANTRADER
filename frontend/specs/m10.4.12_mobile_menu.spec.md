# Spec: M10.4.12 Mobile menu — hidden until clicked (small screen follows the big screen)

Purpose: At ≤900px the nav sidebar must START hidden and appear only when the header
toggle is clicked — "when we minimise to mobile size it doesnt show the menu unless it
been click" (human 2026-09-30), "the small screen should follow suit" (bigger screen's
click-to-collapse behaviour). Desktop behaviour is byte-for-byte unchanged.

Root cause recorded: `App.tsx` started `useState(false)` (expanded at every width) AND
≤900px rendered the sidebar visibly in BOTH states (expanded = list, collapsed =
horizontal band in `responsive.css`), so mobile could never hide the menu.

Inputs:
- Viewport: `window.matchMedia("(max-width: 900px)")` (client-only SPA, no SSR guard needed).
- Existing `sidebarCollapsed` state — one state, same semantics as desktop
  (collapsed = menu not showing).

Outputs / behaviour:
- Initial state: collapsed on mobile, expanded on desktop (today's desktop default).
- Breakpoint listener: crossing into ≤900px collapses; crossing back expands —
  listener registered and cleaned up in `useEffect`.
- Mobile collapsed rule: `.sidebar.is-collapsed { display: none; }` inside the ≤900px
  block of `responsive.css` (the old visible-band rules for that state are dead → deleted).
- Nav link tap on mobile closes the menu (`closeOnMobile` onClick on `<Link`);
  on desktop it is a no-op (route change does not force-collapse the rail).
- OPEN menu layout unchanged (band styling kept, just de-scoped from the dead
  collapsed selectors) — behaviour fix, not a redesign.

Edges:
- Desktop (>900px): expanded default, glyph-rail collapse + hover expand + short-window
  compaction all untouched (`shell.css` not edited; `.sidebar.is-collapsed .primary-nav a`
  short-height rule in `responsive.css` stays — it is live for desktop rail).
- `<aside` is NEVER unmounted (frozen law: `sidebarCollapsed ? null` banned).
- Outside click / Escape still close (existing effect untouched).
- Dead-CSS law: after `display: none`, every `.sidebar.is-collapsed …` descendant rule
  inside the ≤900px block is unreachable and must be deleted; the only surviving
  `.sidebar.is-collapsed` occurrences in `responsive.css` are the `display: none` rule
  itself and the max-height desktop-rail compaction rule.

Correct: parity with the desktop collapse model (click toggles, outside/Escape close);
no new visual design, no backend.

Adversarial: string-scan bans (never-unmounted, dead-rule survivors outside the allowed
two, missing cleanup listener).

Tests: `frontend/tests/test_m10.4.12_mobile_menu_spec.py` (7 tests, text-parses
App.tsx + responsive.css).

Out of scope: overlay/drawer animation, hamburger icon redesign, layout change of the
open menu, any strategy naming/location work (human directive 2026-09-30: "leave
strategy name alone" — the strategy-rename idea is cancelled, flagged Discrepancy stays
flagged, untouched).

## Inputs

- `topic: str` — non-empty, no spaces; Day-1 topics e.g. `market.ticks`, `system.health`
- `payload: dict[str, Any] | list[Any] | str | int | float | bool | None` — JSON-serializable only (reject others)
- Subscriber callback: `Callable[[BusMessage], None]` **or** injectable queue — Day-1 default: sync callbacks; async adapters later at transport
- Client resume: `last_seq: int` per topic (`0` or `None` = want snapshot only)

## Outputs — frozen `BusMessage` (in-module or `shared/contracts` if first external consumer)

```text
topic: str
seq: int >= 1          # monotonic per topic, never reused
type: "snapshot" | "delta" | "replay"
payload: <as published> # full topic value Day-1
```

- **Publish** → emit one `delta` with new `seq` to live subscribers (and append history).
- **Subscribe fresh (`last_seq` None/0)** → send `snapshot` = last retained message for topic (or empty snapshot `seq=0`, `payload=None` if never published) then live deltas.
- **Subscribe with `last_seq=N`**:
  - `N == current_seq` → no history; live only
  - `0 < N < current_seq` → `replay` messages for `N+1..current_seq` **in order**, then live
  - `N > current_seq` → **reject subscribe** with typed error (client ahead = corrupt) — safer than silent resync-to-0
  - `N == current_seq` after empty topic (`seq=0`) → treat as snapshot-empty

## Correct (definition of done for impl)

1. First publish on `market.ticks` → `seq=1`; second → `seq=2` (never reset while bus alive).
2. Two topics independent: `market.ticks` seq does not advance `system.health`.
3. Subscriber registered before publish receives delta; subscriber after publish gets snapshot then later deltas.
4. History buffer keeps last `history_limit` messages (default **256** per topic; older dropped from **replay only** — `current_seq` still grows).
5. Reconnect `last_seq=1` when current=4 → replay seq 2,3,4 then live; **no seq skip**.
6. Reconnect `last_seq=4` when current=4 → zero replay messages, then live 5+.
7. Reconnect `last_seq=99` when current=4 → subscribe fails `seq_ahead` (ErrorCode or dedicated exception — **name in tests**).
8. Publish non-JSON type (e.g. `object()`, `set`) → reject, **seq unchanged**, no partial fan-out.
9. Unsubscribe stops further callbacks (no zombie delivery).
10. Snapshot on never-published topic → `type=snapshot`, `seq=0`, `payload=None`.
11. Callback raising does not corrupt `seq` or skip other subscribers (isolate; log/re-raise policy: **continue other subs**, record failure).
12. Day-1: no `user_id` on message (market-data public); private tenant filter is transport-layer concern later.

## Edges

| Edge | Behavior |
|------|----------|
| empty topic name / whitespace | `ValueError` at publish/subscribe |
| empty payload dict `{}` | valid publish, seq advances |
| `payload=None` | valid |
| history_limit=0 | snapshot still works; replay always empty → live-only after snapshot |
| concurrent publish (single-thread asyncio) | seq strictly +1 per successful publish; no locks required Day-1 if sync single-thread tests — document **not multi-process safe** |
| unsubscribe unknown sub | idempotent, no error |
| duplicate subscribe same callback | **two entries** (or documented set — tests pin: Day-1 **allow list append**, deliver once per registration) |

## Adversarial (must be in tests)

- `topic=""`, `topic="  "` → ValueError  
- `payload={"x": {1,2}}` or `object()` → reject, seq frozen  
- `last_seq=-1` → treated as invalid (ValueError or treat as 0 — **tests pin: ValueError**)  
- `last_seq=current+1` → `seq_ahead` fail  
- subscriber that throws on message 2 → message 3 still delivered to healthy sub

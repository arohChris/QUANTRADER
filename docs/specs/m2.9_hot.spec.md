# Spec: M2.9 HOT Cache — Valkey latest-tick + forming-candle store (redis-py)

Purpose: Async HOT-tier cache: keep the latest `MarketData` tick and the forming candle per
`(provider, instrument[, timeframe])` in Valkey/Redis so live consumers read "right now"
without touching parquet. **Cache is NEVER the truth** — every I/O failure fails open
(sentinel + warning); WARM/parquet (M2.10) remains authoritative.

## Inputs

- `HotStore(url: str, *, client=None, default_ttl_seconds: int = 60, namespace: str = "hot")`
  - `client` — injected async client (tests: in-memory fake). `None` → real client created
    lazily on `connect()` via **redis-py** (`redis.asyncio`, `decode_responses=True`).
  - `default_ttl_seconds` — 1..86400 (sane-bounds §3.13); out of range → `ValueError` at construction.
  - `namespace` — key prefix, `^[A-Za-z0-9][A-Za-z0-9._-]*$`, default `hot`.
- `await store.connect()` — no-op if `client` injected; else lazy `import redis`, `from_url`.
- `await set_latest(md: MarketData) -> bool` — provider = `md.provider or md.broker`;
  requires non-empty `md.instrument_id` (else `ValueError`).
- `await get_latest(provider: str, instrument_id: str) -> MarketData | None`
- `await set_forming(provider, instrument_id, timeframe, candle: Candle) -> bool`
- `await get_forming(provider, instrument_id, timeframe) -> Candle | None`
- `await ping() -> bool` — `True` alive, `False` unreachable.
- `await close() -> None` — idempotent, never raises.
- Pure key builders (validate their parts): `latest_key(provider, instrument_id)` →
  `{ns}:{provider}:{instrument_id}:latest`; `forming_key(provider, instrument_id, timeframe)` →
  `{ns}:{provider}:{instrument_id}:{timeframe}:forming`.
- Pure `resolve_source_namespace(md) -> str` — **ONE canonical write-path rule [human 2026-09-25]:
  provider if present, otherwise broker.** The key builders are the **only** place keys are
  formed (set AND get call them — no per-method key strings → no read/write mismatch).
  Readers must pass the namespace the writer resolved (same md → same value).

## Outputs

- Writes: `True` stored / `False` not stored — either **stale-rejected** (monotonic law,
  info log, not an error) or swallowed I/O failure (fail-open, warning logged).
- Reads: exact frozen-contract roundtrip, or `None` (missing / corrupt / I/O failure).
- `ping`: `True`/`False`. Never raises for any I/O condition.

## Cache availability ≠ market-state validity [HUMAN LAW 2026-09-25]

- `ping()` reports **cache health only**. `cache_available=True` NEVER implies
  `market_state_valid=True` — a key's existence is not proof of valid market state.
  Validity comes from the authoritative market-data/candle pipeline (M2.1/M2.4).
- M2.9 unavailable → consumers **keep running** on the authoritative stream (fail-open);
  components that need authoritative state go STALE/INVALID per their own policy.
  **Valkey must never become a hidden dependency for trading.**

## Mutable vs immutable [HUMAN LAW 2026-09-25]

- A **forming candle is mutable state** — M2.9 caches it; overwrites are expected
  (last writer wins, per timeframe).
- A **finalized candle is immutable historical state** — produced by M2.4 finalization →
  WARM/Timescale. **M2.9 never stores finalized candles.**

## Monotonic writes — never replace newer with older [HUMAN LAW A33 2026-09-25]

- **M2.9 must NEVER replace a newer cached market state with an older state.**
- `set_latest`: compare `watermark` — incoming `<` stored → **reject** (`False`, info
  log, key untouched); incoming `>` stored → write; **incoming `=` stored → overwrite
  (ACCEPT)** — documented decision: same sequence re-delivered (at-least-once) is
  idempotent and self-heals a corrupt entry; NOT "ignore".
- `set_forming`: compare `interval_start` — older bucket → **reject**; same bucket →
  accept (mutable state, edge 21 unchanged); newer bucket → write.
- Stored value corrupt/unreadable during the check → treated as absent (replaceable —
  cache never truth). Read-fail during the check → best-effort proceed (fail-open;
  staleness unprovable, never raises).
- **Naive/aware temporal mismatch during comparison = INVALID temporal state, NOT
  permission to overwrite** [A33 r2] → **reject write (`False`) + warning; key
  untouched** (self-heals at TTL expiry when the malformed key falls off).
- **HARD ARCHITECTURAL INVARIANT (M2.1/M2.9)** [A33 r2 — not an implementation note]:
  *For each provider+instrument HOT key, writes are serialized through one ordered
  writer. No independent worker may concurrently perform `set_latest`/`set_forming`
  for the same key.* If this invariant is removed or violated, M2.9 monotonicity
  **MUST** be implemented with an atomic server-side CAS/Lua operation **before**
  multi-writer operation is enabled. (Anyone adding a worker that writes HOT keys
  breaks A33 silently otherwise — this is why the rule is stated as invariant law.)
- Cost: one `GET` precedes each `SET` (sub-ms; inside the tick→parquet <50ms budget).

## Canonical-source statement [HUMAN A33 — strengthened]

- **M2.4 produces canonical market-state events; the durable finalized 1-minute candle
  store (WARM/Timescale, m2.10) is the canonical persisted historical dataset.
  M2.9 is only a transient acceleration layer.**

```text
Provider → M2.1 → M2.4 ──→ durable finalized candles (canonical history)
                      └──→ M2.9 HOT (fast current state) → Analysis
```

## Forming-key ownership [HUMAN A33]

- **The key identifies the market context** (provider, instrument, timeframe);
  **the Candle payload represents the candle state for that context.** `Candle` must
  never gain its own provider/instrument identity — one source of identity, enforced
  here so a future contract edit cannot create two disagreeing identities.

## Consumer law [HUMAN A33]

- M2.9 is acceleration for the Analysis/Candle pipeline **only**. Strategy/Bot must
  **never** read M2.9 directly (`get_latest → indicator → trade` is BANNED — it
  recreates the architecture problem this design solved). Path:
  `M2.9 → Analysis Engine → AnalysisSnapshot → Strategy → Bot → TradePlan → M5`.
- Bot/strategy config must declare `analysis_mode: CLOSED | LIVE_FORMING` explicitly;
  a strategy may never silently switch modes. **Binding on all future strategy slices.**
- Final architecture law: *M2.9 accelerates the system. It never decides what the
  market means, whether a trade should happen, whether risk is acceptable, or whether
  an order should execute.*

## Staleness metadata — no age policy in M2.9

- Cached values carry their own `exchange_timestamp` / `received_at` / `watermark`
  (already inside `MarketData`) — M2.9 provides **data + timestamp + watermark**.
- M2.9 **MUST NOT** judge age/freshness (7s old ≠ bad here). `fresh / stale / invalid`
  is the **consuming component's policy** (e.g. scalping bot max age 500ms, swing bot 30s).

## Keys (tenant law §4.3)

- **No `user_id`, ever** — HOT is global market-data (`provider+instrument`), shared across tenants.
- `provider`/`instrument_id`: `^[A-Za-z0-9][A-Za-z0-9._-]*$` (rejects empty, space, `:`, `;`, `/`, newline).
- `timeframe`: `^[0-9]{1,3}(m|h|d)$` (`1m 5m 15m 40m 1h 4h 24h 1d` valid).

## Edges (one test each)

1. `get_latest` on missing key → `None` (never exception).
2. `set_latest` twice same key with **newer/equal watermark** → second overwrites first
   (monotonic law: last-writer-wins only within non-decreasing watermark).
3. `get_forming` on missing key → `None`.
4. Forming candles isolated per timeframe (`5m` write does not affect `15m` read).
5. Roundtrip: `set_latest(md)` → `get_latest(...)` returns contract **equal** to `md` (golden).
6. Roundtrip: forming `Candle` equality preserved (incl. tz-aware datetimes through JSON).
7. Default TTL applied on `set_latest` (`ex=60`); no TTL leak on overwrite without expiry.
8. `default_ttl_seconds=0` → `ValueError` (construction).
9. `default_ttl_seconds=-1` → `ValueError` (construction).
10. `default_ttl_seconds=86401` → `ValueError` (construction).
11. Invalid `namespace` (e.g. `"a b"`, `"x:y"`) → `ValueError` (construction).
12. Client raises on `set` → returns `False`, does NOT raise (fail-open + warning).
13. Client raises on `get` → returns `None`, does NOT raise.
14. `ping` while client down → `False`.
15. Stored value corrupt JSON (`"not-json{{{"`) → `get` returns `None`, no raise.
16. Stored value valid-JSON-but-wrong-type (`"12345"`) → `get` returns `None`, no raise.
17. Ops before `connect()` (no client) → `set` `False` / `get` `None` (fail-open, no raise).
18. `close()` twice → no raise (idempotent).
19. Key format goldens: `latest_key("deriv","FX.EURUSD") == "hot:deriv:FX.EURUSD:latest"`;
    `forming_key("deriv","FX.EURUSD","5m") == "hot:deriv:FX.EURUSD:5m:forming"`.
20. No key ever contains `user_id` (storage law §4.3).
21. Forming overwrite: second `set_forming` on same key replaces first (mutable state).
22. `resolve_source_namespace`: `provider` wins when both present; falls back to `broker`.
23. Cache fully unavailable (set+get+ping all failing) → all sentinels, zero propagation
    to the caller (never raises) — cache health never blocks the caller.
24. Stale watermark rejected: set wm=102 → set wm=101 → `False`, get → wm=102.
25. Same watermark accepted (documented): set wm=102 payload A → set wm=102 payload B
    → `True`, get → payload B (overwrite, not ignore).
26. Stale forming bucket rejected: current `interval_start` stored → older-bucket
    `set_forming` → `False`, get → current bucket retained.
27. Forming TTL applied on `set_forming` (same bounded default as latest).
28. Fallback namespace read symmetry: writer with `provider=None` resolved via broker →
    `get_latest(resolved_ns, instrument)` roundtrips the same value (one convention).
29. Temporal mismatch: stored naive `interval_start` vs aware incoming (or reverse) →
    `False` + warning, stored value unchanged (invalid state ≠ write permission).
30. **Monotonic matrix (A33 contract):** newer watermark replaces older · equal
    watermark overwrites (idempotent) · older watermark does not overwrite ·
    same-bucket forming updates · older forming interval does not overwrite.

## Adversarial (beyond edges — must fail TYPED, never silent)

- A1. `set_latest(None)` / `set_latest("str")` → `ValueError` — **validation errors are NOT
      swallowed by fail-open** (validation happens before the I/O try-block).
- A2. Key-part injection: `get_latest("deriv", "FX.EURUSD:evil")`, `set_latest` with
      `instrument_id="a b"` → `ValueError`.
- A3. Timeframe injection: `set_forming(..., timeframe="5m; DROP", ...)` → `ValueError`.

## Correct

- Roundtrip correctness = Pydantic frozen-model equality after `model_dump_json` /
  `model_validate_json` (string JSON; no `float` conversion of prices — payload roundtrips
  untouched; money math is N/A here — cache stores bytes, never recomputes).
- Fail-open rule: **validation → `ValueError` (caller bug, loud)**; **everything I/O →
  sentinel + `logger.warning`, never raise** (bible: "Redis is never the truth").
- TTL bounded 1..86400; UTC timestamps preserved (tz-aware datetimes survive JSON).

## Contract / consumers

- Consumes frozen `MarketData` v1.4 + `Candle` — **no shared-contract change, no bump**.
- No new contract. Written for consumers: m2.11 live pipeline writer/reader (and later M2b
  runtime cache if needed).

## Dependencies

- Step 5 adds `redis>=5.0` to `pyproject.toml` dependencies (human-locked driver: redis-py;
  server = Valkey 9.1 per `infra/docker-compose.yml`). Tests never import `redis`
  (client injection) — hermetic, no `fakeredis` dependency.

## Responsibilities — scope lock [HUMAN LGTM 2026-09-25]

M2.9 DOES: latest market-data cache · forming-candle cache · TTL · low-latency retrieval ·
serialization/deserialization · key isolation · validation · cache health (`ping`) ·
fail-open behavior · stale-data metadata (timestamps/watermark pass-through).

M2.9 does NOT: calculate indicators · generate signals · decide whether a trade is good ·
risk approval · become source of truth · permanently store historical/finalized candles ·
execute orders.

## Out of scope (later slices)

- M2.10 WARM store (asyncpg + hypertable) · m2.11 live pipeline wiring (Deriv→HOT→WARM→parquet) ·
  pub/sub fan-out · keys beyond latest/forming (orderbook, trades) · TTL policy config file.
- Bible numbering: M2 table ends at M2.8 — `m2.9/m2.10/m2.11` are project slice names for the
  HOT/WARM/live-e2e tier work (tier law: `System_Development_Manual.md` HOT/WARM/COLD §).

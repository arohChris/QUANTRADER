# Spec: M2.1 Tick Ingest (WebSocket) — Deriv frame format

Purpose: Maintain a live WebSocket connection to the broker tick feed, validate each raw Deriv tick frame, and emit an M2.1-internal raw tick/event downstream for M2.2 canonicalization. M2.1 does **not** emit canonical `MarketData` — normalization is M2.2's job.
Bible ref: System_Development_Manual/modules/02_M2_Data.md §3 (`broker_feeds/deriv/stream.py`).
Format source: Deriv WebSocket API `msg_type=tick` (human samples 2026-09-22 + developers.deriv.com Ticks / Ticks Comparison — **new API**: `tick` object required; required fields inside tick are only `epoch`, `quote`, `symbol`; `pip_size` optional; `id`/`bid`/`ask`/`echo_req` optional per current docs).
Review status: REV1 2026-09-22 — human CHANGES REQUIRED applied (Deriv required-field list corrected; see below).

## Layering (connection vs pure ingest)

Connection and frame ingestion are **separate layers**:

```text
broker_feeds/deriv/stream.py
  Connection layer        — WebSocket connect/reconnect/subscription/ping-pong keep-alive
  Frame ingestion layer   — ingest(raw_message, ...) → InternalTick | Drop
```

`ingest()` is a **pure-ish function**: deterministic given its injected clock/dedup/processing state. It does **not** own the WebSocket connection. Ping/pong is handled at the connection layer, outside `ingest`.

## Pipeline boundary (M2.1 → M2.2 → M2.3)

- **M2.1** = transport + raw schema validation + dedup on **broker-native frame**. Output: `InternalTick` or `Drop`. Symbol stays broker-native (`frxEURUSD`). **No canonicalization.**
- **M2.2** = normalization: native symbol → canonical `instrument_id`, epoch→exchange_timestamp lineage, produces frozen `MarketData`.
- **M2.3** = authoritative data-quality gate — final quality stamp before analytics.

## Canonical Deriv tick frame (input shape)

```json
{
  "echo_req": {"req_id": 101, "subscribe": 1, "ticks": "frxEURUSD"},
  "msg_type": "tick",
  "req_id": 101,
  "subscription": {"id": "a9b8c7d6-1234-5678-90ab-cdef12345678"},
  "tick": {
    "ask": 1.08542,
    "bid": 1.08538,
    "epoch": 1774208800,
    "id": "a9b8c7d6-1234-5678-90ab-cdef12345678",
    "pip_size": 5,
    "quote": 1.08540,
    "symbol": "frxEURUSD"
  }
}
```

### Field mapping (frame → InternalTick)

Two requirement levels are distinguished deliberately:

- **Deriv-API required** — required by the current Deriv new-API Ticks docs.
- **QUANTRADER2 required** — required for the `InternalTick` contract even when Deriv does not guarantee the field.

| Deriv field | Deriv-API | QUANTRADER2 | InternalTick | Notes |
|-------------|-----------|-------------|--------------|-------|
| `msg_type` | yes | yes | — | must be `"tick"` else `Drop(missing_field)` |
| `tick` (object) | yes | yes | — | missing/not object → `Drop(missing_field)` (**new API: always present**) |
| `tick.symbol` | **required** | yes | `symbol` | e.g. `frxEURUSD`, `cryBTCUSD`, `frxXAUUSD`; opaque string (see Adversarial) |
| `tick.epoch` | **required** | yes | `timestamp` | unix seconds int → UTC datetime; non-numeric → `Drop(invalid_timestamp)` |
| `tick.quote` | **required** | yes | `quote` | mid; M2.1 copies through |
| `tick.bid` | optional | **yes (Q2)** | `bid` | Decimal; **QUANTRADER2 requires bid/ask for `InternalTick`**; Deriv docs do not mark them required. Frame lacking bid/ask → adapter `Drop(missing_field)` |
| `tick.ask` | optional | **yes (Q2)** | `ask` | same as bid |
| `tick.id` | optional | no | `source_event_id` | **optional per current Deriv docs** — when present, primary dedup key; when absent, fingerprint fallback (see Identity) |
| `tick.pip_size` | optional | no | `pip_size` (optional int) | precision hint for M2.2 — existence-check before use |
| `tick.seq` | **not documented** | no | `source_sequence` | optional provider extension if actually supplied; **Deriv does not currently document it as a standard Ticks response field**; gap detection inactive unless a valid provider sequence field is present |
| `ask_size` / `bid_size` | **no** | no | optional | **not in Deriv tick** — do not require |
| `echo_req` | optional | no | — | ignored by M2.1 |
| `subscription.id` | optional | no | — | stream handle; **not** tick identity |

> **Why the two-level table:** Deriv example frames include `id`/`bid`/`ask`, but the docs' required-field list does not. QUANTRADER2 still rejects frames lacking bid/ask (Option A — safest for current architecture): the adapter rejects what `InternalTick` cannot carry, without claiming Deriv guarantees them.

## Inputs

- `raw_message: str | bytes` — full Deriv WS frame (JSON object above)
- `provider: str` — e.g. `deriv`
- `clock: Clock` — `now()` for future-epoch check
- Identity (see below): `source_event_id`, `source_sequence?`, `event_id`. **`correlation_id` is NOT a tick-identity field.**

## Outputs

- `InternalTick | Drop` — **not** `MarketData`. **Exactly one terminal result per input frame: either one `InternalTick` or one `Drop` — never both, never neither.**
- Accepted tick carries: `event_id`, `source_event_id?`, `source_sequence?`, `processing_sequence`, `observed_at` (clock), `provider`, `symbol`, `timestamp` (from epoch), `bid`/`ask` (+ optional sizes/quote/pip_size), `quality`.

## Identity fields (distinct, never conflated)

- `source_event_id` — `tick.id` **when present**; `None` when absent. When unavailable, M2.1 uses the defined deterministic fingerprint for deduplication/identity fallback (applies on Deriv too — `id` is optional).
- `source_sequence` — `tick.seq` if present (optional provider extension; **not a documented standard Deriv field**); gap detection only (not uniqueness alone). Deriv sequence-gap detection is inactive unless a valid provider sequence field is present.
- `processing_sequence` — M2.1 accept counter (recovery watermark uses this). **Increments only for accepted `InternalTick` outputs, not for dropped frames.** Example: frame 1 accepted → seq 1; frame 2 duplicate → Drop (no increment); frame 3 accepted → seq 2.
- `event_id` — deterministic id M2.1 assigns to each accepted tick.

### Dedup key / missing-ID fallback (exact algorithm)

```text
If source_event_id exists (tick.id present):
    dedup key = source_event_id
Otherwise:
    deterministic fingerprint over, in fixed field order:
      provider, symbol, epoch, quote,
      bid if present, ask if present,
      source_sequence if present
    Canonical serialized representation (stable field names, stable
    Decimal/None encoding) before hashing — never Python tuple/str repr
    whose formatting could change.
```

> bid/ask are part of the fingerprint only when present (QUANTRADER2 requires them for InternalTick, but the fingerprint definition stays defensive for partial frames that fail later validation).

## Processing order (mandatory — not implementation-dependent)

1. Decode bytes → text (non-UTF-8 → `Drop(invalid_json)`).
2. Parse JSON (malformed → `Drop(invalid_json)`; empty/whitespace → `Drop(empty)`).
3. Validate outer structure: JSON is object, `msg_type=="tick"`, `tick` is object (else `Drop(missing_field)`).
4. Validate required fields/types (Deriv required: `symbol`/`epoch`/`quote`; QUANTRADER2 required: `bid`/`ask`).
5. Build source identity (`source_event_id` or fingerprint).
6. Check dedup → duplicate → `Drop(duplicate_tick)` (no `processing_sequence` increment).
7. Validate timestamp/business constraints (aware UTC conversion, future-epoch tolerance).
8. Assign next `processing_sequence` (accepted only).
9. Construct and return `InternalTick`.

> **Dedup-before-business-rules:** a duplicate frame is reported as `duplicate_tick` even if it would also fail a later business check — step order above is binding so reason selection is never implementation-dependent.

## Edges

- Valid `msg_type=tick` frame → one `InternalTick`; `observed_at` from clock; `timestamp = utc(epoch)`.
- Empty / whitespace payload → `Drop(empty)`.
- Malformed JSON or non-UTF-8 → `Drop(invalid_json)`.
- JSON not an object, or missing `tick` object, or `msg_type != "tick"` → `Drop(missing_field)`.
- Missing `tick.symbol` / `tick.epoch` / `tick.quote` (Deriv-required) → `Drop(missing_field)`.
- Missing `tick.bid` / `tick.ask` (QUANTRADER2-required) → `Drop(missing_field)` (see field table).
- Non-numeric bid/ask → `Drop(invalid_price)`.
- Non-numeric epoch → `Drop(invalid_timestamp)` (**not** `invalid_price` — epoch is a timestamp).
- Non-positive bid/ask → `Drop(invalid_price)`.
- Future-epoch check on **converted UTC timestamp**: `timestamp > clock.now() + timedelta(seconds=1)` → `Drop(timestamp_ahead)`; **equality accepted** (exactly +1s accepted).
- Duplicate `tick.id` (or duplicate fingerprint) → `Drop(duplicate_tick)`; `processing_sequence` unchanged.
- `tick.id` absent → fingerprint fallback (Deriv-relevant — see Identity); not a Drop by itself.
- Sequence gap (`tick.seq` discontinuity per symbol) → still emit, `quality=gapped`; **inactive when `tick.seq` absent/not a valid provider sequence**.
- Frames that are not ticks (`msg_type` e.g. `subscription`, `error`, `ping`) → `Drop(missing_field)` at M2.1 tick path (transport may handle ping/pong outside `ingest`).

## Correct

- Connection layer (connect/reconnect/subscribe/ping-pong) is separate from pure `ingest` fn.
- Every valid tick frame → exactly one `InternalTick`.
- Every input frame → exactly one terminal result: one `InternalTick` **or** one `Drop`.
- Drops carry `reason` + `provider` + `detail` for dead-letter.
- Dedup uses `source_event_id` (`tick.id`) when present; deterministic fingerprint otherwise.
- `processing_sequence` increments only on accept.

## Adversarial

- `{"msg_type":"tick"}` (no `tick`) → `Drop(missing_field)`, never partial emit.
- Same `tick.id` twice → second `Drop(duplicate_tick)`.
- Far-future `epoch` → `Drop(timestamp_ahead)`, not accepted then fixed.
- `tick.ask = -1` → `Drop(invalid_price)`.
- `tick.epoch = "not-a-number"` → `Drop(invalid_timestamp)`.
- Hostile `tick.symbol` (`'; DROP TABLE`, `script`, etc.): **`tick.symbol` is parsed as an opaque broker-native string at M2.1. M2.1 must not execute, interpolate, or otherwise interpret the value.** A syntactically valid string may be accepted into `InternalTick`; unresolved/malicious symbols are rejected by M2.2/M2b downstream (`Drop(unknown_symbol)` there). Never crash at M2.1.

## Contracts touched

- Output: `shared/contracts/internal_tick.py:InternalTick` (sizes/quote/pip_size optional — Deriv omits sizes).
- Rejects: `shared/contracts/drop.py:Drop` / `DropReason` (shared vocabulary — see below).
- **Not** `MarketData` yet (M2.2).

## Drop vocabulary (shared — aligned with M2.2)

M2.1 and M2.2 share one `DropReason` enum (no M2.1-only names):

```text
empty
invalid_json
missing_field
invalid_price
invalid_timestamp   ← non-numeric / invalid epoch (M2.1); naive InternalTick timestamp (M2.2)
timestamp_ahead
duplicate_tick
unknown_symbol      ← unresolved native / unknown instrument (M2.2 gate)
```

# Spec: M2.3 Validation — MarketData quality bouncer

Purpose: Reject canonical `MarketData` that fails hard quality rules (future timestamp, non-positive price, inverted bid/ask) before M2.4/M2.6/M3 — all-or-drop; does **not** allocate watermarks, does **not** backfill gaps (M2.7).
Bible ref: System_Development_Manual/modules/02_M2_Data.md §5.
Connects: `M2.2 → M2.3 → M2.4 / M2.6`. Pure sync on frozen `MarketData` — no M2b, no clock, no side effects.
Review status: DRAFT 2026-09-22 — awaiting human LGTM (Step 1).

## Inputs
- `md: MarketData` — accepted M2.2 output (`kind="tick"`, frozen, aware `exchange_timestamp` / `received_at`, `payload=Tick`).
- **No dependencies** — no `clock`, no `reference`, no `watermark_registry` (watermark gap detection is M2.7 only).

## Outputs
- Exactly one frozen `MarketData` **OR** exactly one `Drop` — **all-or-drop, never partial, never mutate input**.
- Success: return the **same** `md` instance unchanged (identity pass-through — M2.3 does not re-round, re-stamp lineage, or rewrite quality unless a rule says so).
- Reject: `Drop(reason=…, provider=md.provider or md.broker, detail=…, raw_payload="")`.

## DropReason vocabulary (contract change if approved)
Existing `DropReason` lacks bible names. **Proposal — Drop 1.4 → 1.5.0 minor additive** (human LGTM required before code):

| Rule | New/existing reason | Notes |
|------|---------------------|-------|
| future exchange time | **`future_timestamp`** (add) | matches `ErrorCode.future_timestamp` + bible pseudocode |
| price ≤ 0 | **`negative_price`** (add) | matches `ErrorCode.negative_price` + bible |
| bid > ask (inverted) | **`inverted_quote`** (add) | matches `ErrorCode.inverted_quote`; M2.2 emits inverted; M2.3 rejects |

Existing `timestamp_ahead` / `invalid_price` stay for M2.1 frame-level rejects — **not reused** for M2.3 (different stage, different meaning).

## Processing order (mandatory)
1. `md.kind == "tick"` and `isinstance(md.payload, Tick)` → else `Drop(missing_field)` (M2.3 validates tick quotes only this slice; candle/book rules deferred).
2. `exchange_timestamp` and `received_at` both timezone-aware → else `Drop(invalid_timestamp)` (defensive; M2.2 should already guarantee).
3. **Future gate:** `exchange_timestamp > received_at + timedelta(seconds=5)` → `Drop(future_timestamp)`  
   - WHY `received_at` not `clock.now()`: pure, deterministic, testable; tolerance **5s** fixed (clock skew allowance, bible uses `+timedelta(seconds=5)`).
4. **Price gate:** `payload.price <= 0` → `Drop(negative_price)` (Decimal-compare on `Decimal(str(price))` before float artifacts matter — price is float at contract boundary; treat `<= 0` including `0.0` and negative).
5. **Inverted gate:** both `bid` and `ask` present and `bid > ask` → `Drop(inverted_quote)`  
   - If either is `None`, skip inverted check (M2.2 always sets them for Deriv path; optional fields stay optional).
6. **Spread sanity (derived):** recompute `spread = ask - bid` in Decimal; if inverted already caught in step 5, spread here is informational only — **no separate drop** for extreme spread (M5 risk owns `spread_too_wide`).
7. **Quality stamp (authoritative):**  
   - If current `quality` is `pristine` and all gates pass → leave `pristine`.  
   - If current is `gapped` → **pass through `gapped`** (M2.1/M2.2 sequence gap marker — M2.3 must not clear it).  
   - Unknown/other → leave unchanged (M2.6 remains free to refine later).  
   - **M2.3 does not invent `suspect`/`degraded` in this slice** (no spike/zscore rules yet — out of scope).
8. Return `md` unchanged.

**No watermark interaction.** Rejection or success never calls `watermark_registry` (already allocated in M2.2; M2.3 must not double-count or refund).

## Edges
- Valid EURUSD tick (exchange ≤ received+5s, price>0, bid≤ask) → same `md` returned, `quality` unchanged.
- `exchange_timestamp = received_at + 6s` → `Drop(future_timestamp)`.
- `exchange_timestamp = received_at + 5s` exactly → **accept** (boundary is `>`, not `>=`).
- `exchange_timestamp = received_at` or past → accept.
- `price = 0` or `price = -0.01` → `Drop(negative_price)`.
- `price = 0.00001` (positive tiny) → accept.
- `bid=1.09, ask=1.08` → `Drop(inverted_quote)` (M2.2 emitted it; M2.3 is the bouncer).
- `bid=None` or `ask=None` → skip inverted check; other gates still apply.
- `kind != "tick"` or non-Tick payload → `Drop(missing_field)` (this slice).
- Naive `exchange_timestamp` or naive `received_at` → `Drop(invalid_timestamp)`.
- `quality=gapped` input that passes numeric gates → still `gapped` output (not cleared to pristine).
- Input frozen: attempt `md.watermark = 999` after validate → still raises (same instance, still frozen).

## Purity / side effects
- **Fully pure and deterministic** — no clock, no I/O, no registry, no mutation.
- Same `md` in → same result out (pass-through identity or Drop).

## All-or-drop invariant
> No `MarketData` leaves M2.3 if any rule above fails; no partial field rewrites.

## Correct
- Future threshold: **strictly greater than** `received_at + 5s`.
- Inverted: **strict `bid > ask`** only (equal bid/ask / zero spread is valid).
- Price: **`<= 0` rejects**; no epsilon fudge.
- Does not re-validate symbol/identity (M2.2 already did `exists` gate).
- Does not perform watermark gap fill (M2.7).

## Adversarial (not in edges)
- `payload` is `Candle` while `kind="tick"` (corrupt union) → `Drop(missing_field)`, never attribute-crash.
- `exchange_timestamp` year 1970 with `received_at` 2026 → accept (past is fine; only future rejects).
- `price=float("nan")` if somehow present → `Drop(negative_price)` (`nan <= 0` is False in IEEE — **explicit**: treat non-finite as invalid → use `not math.isfinite(price) or price <= 0` → still `negative_price` for this slice? **Decision: non-finite → `negative_price`** to avoid a new reason; document here).
- `provider` empty/None on Drop → fall back to `md.broker` for `Drop.provider` (required field).

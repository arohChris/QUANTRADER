# Spec: M2.1 Tick Ingest (WebSocket)

Purpose: Maintain a live WebSocket connection to the broker tick feed, validate each raw tick against the frozen schema, and emit an M2.1-internal raw tick/event downstream for M2.2 canonicalization. M2.1 does **not** emit canonical `MarketData` — normalization is M2.2's job.
Bible ref: System_Development_Manual/modules/02_M2_Data.md §3.

## Pipeline boundary (M2.1 → M2.2 → M2.3)
- **M2.1** = transport + raw schema validation + dedup. Output: `M2.1 internal tick/event` (raw validated tick with identity fields) or `Drop`. Symbol is still broker-native / partially mapped at this stage.
- **M2.2** = normalization / canonicalization: native symbol → canonical `instrument_id`, unit/type normalization, produces frozen `MarketData`.
- **M2.3** = authoritative data-quality gate (gaps, staleness, outlier checks) — final quality stamp before analytics.

## Inputs
- `raw_message: str | bytes` — broker WS frame
- `provider: str` — broker/provider name (e.g. `deriv`)
- `clock: Clock` — source of `now()` for future-timestamp check
- Identity fields **on the tick itself** (parsed from payload or envelope): `source_event_id` (provider's event id if present), `source_sequence` (provider sequence if present), `event_id` (deterministic id M2.1 assigns). **`correlation_id` is NOT a tick-identity field** — it traces one logical trade/pipeline run (tick→signal→order) and is attached at higher layers (M4/M5+), not used for ingest dedup.

## Outputs
- `M2.1 internal tick/event | Drop` — validated raw tick if schema passes; `Drop` if rejected. **Not** `MarketData | None` (that is M2.2's output type).
- Every accepted tick carries: `event_id`, `source_event_id?`, `source_sequence?`, `processing_sequence` (M2.1's own monotonic accept counter), `observed_at` (from clock), `provider`, raw price fields.

## Identity fields (distinct, never conflated)
- `source_event_id` — provider-assigned unique event id (primary dedup key when present).
- `source_sequence` — provider's monotonic sequence for gap detection (not a uniqueness key alone).
- `processing_sequence` — M2.1's own counter of accepted ticks (ordering within this process; recovery watermark uses this, not `source_sequence`).
- `event_id` — deterministic id M2.1 assigns to each accepted tick (fallback identity when `source_event_id` absent).

## Edges
- Valid tick → internal tick/event emitted with `observed_at` from clock.
- Malformed JSON → `Drop(reason=invalid_json)`, not crash.
- Missing required field (ask/bid/ask_size/bid_size) → `Drop(reason=missing_field)`.
- Non-numeric price → `Drop(reason=invalid_price)`.
- Timestamp in future (> 1s ahead of clock) → `Drop(reason=timestamp_ahead)`.
- Duplicate tick → `Drop(reason=duplicate_tick)` (alias: `duplicate_event`). **Dedup key = `source_event_id`** when present; when absent, fall back to a **documented deterministic fingerprint** of `(provider, symbol, timestamp, bid, ask, source_sequence?)` — hashed/stored, documented in code WHY comment. **Not** bare `(symbol, timestamp, sequence)` alone.
- Empty payload → `Drop(reason=empty)`.
- Sequence gap detected (`source_sequence` discontinuity) → still emit, but quality marker = `gapped` (M2.7 recovery handles backfill via `processing_sequence` watermark).

## Correct
- WebSocket connection established with ping/pong keep-alive.
- Every valid frame emits exactly one M2.1 internal tick/event.
- Drops logged with reason and sent to dead-letter.
- Dedup uses `source_event_id` (or documented fingerprint fallback) — see Identity fields.

## Adversarial
- Payload = `{"symbol":"EURUSD"}` (all fields missing) → `Drop(missing_field)`, never partial emit.
- Same `source_event_id` delivered twice → second is `Drop(duplicate_tick)`.
- `timestamp` far in future → `Drop(timestamp_ahead)`, not accepted then fixed later.

## Contracts touched
- Output type is M2.1-internal (to be defined as contract when M2.2 boundary freezes) — **not** `shared/contracts/market_data.py:MarketData` yet.
- Drop/reason vocabulary: `shared/contracts/drop.py:Drop` (module to be created; reason enum includes `duplicate_tick`, `invalid_json`, `missing_field`, `invalid_price`, `timestamp_ahead`, `empty`).
- No `ErrorCode` import from `shared.contracts.base` — drop reasons are their own enum, not the global `ErrorCode`.

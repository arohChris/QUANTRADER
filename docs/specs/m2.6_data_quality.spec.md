**Out:**
- Watermark allocation / gap backfill (**M2.7** owns; M2.6 must not touch `watermark`)
  - **AMENDED 2026-09-27 — M2.6 now *reads* `watermark` to detect gaps, but still never
    *allocates* it.** Allocation remains exclusively M2.2's frozen `WatermarkRegistry.next()`.
    When an incoming tick's `watermark` jumps forward by more than 1, the intervening
    sequences never arrived, so the tick is downgraded to `DataQuality.gapped` and the hole
    is recorded on `QualityGate.watermark_gaps`. *Why here:* a gap is a quality fact, and
    this is where quality is decided. The candle builder **cannot** do it — from the tick
    stream alone, "no ticks" is indistinguishable from "no trading". A tick arriving after
    a hole stays `gapped` and is **never promoted**; a silently repaired bar is precisely
    the failure this mechanism exists to prevent (`AGENTS.md` §3.3). Bounded by
    `max_watermark_span` (default 1,000,000) so a corrupt watermark cannot be expanded.
  - **AMENDED 2026-09-27 — the pipeline now CALLS this gate.** `LivePipeline.push` runs
    `ingest → normalize → validate → **QualityGate.on_md** → CandleBuilder`, and the gate is
    constructed **by default** (injectable, but not opt-out). Previously it was implemented
    and unit-tested but never invoked, so dedup, spike detection and gap detection were all
    dead code on the live path. **That omission is what allowed the two defects above to
    ship unnoticed.**

## Inputs

- `md: MarketData` — M2.3 **accepted** tick (`kind="tick"`, payload=`Tick`, aware timestamps, finite prices).
- **No deps:** no `clock`, no `reference`, no `watermark_registry`, no network.
- **Dedup store (unified — one model):** default is **per-instance** state on `QualityGate`: `seen: set` of keys + `prev_map: dict[(instrument_id, broker), tick facts]` for the spike rule. Optional `dedup_store: set | None = None` constructor inject for pipeline-shared identity only (caller owns lifetime; pipeline uses **one** gate). `prev_map` stays per-instance either way.

## Outputs

Exactly one:

1. **`Drop(reason=duplicate_tick, provider=md.provider or md.broker, …)`** — second sighting of same identity.
2. **`MarketData`** — same instance if quality unchanged; **or** `md.model_copy(update={"quality": …})` if classifier upgrades quality. **Never mutate frozen input in place.**

**Never writes `watermark`.** Identity fields (`source_event_id`, `watermark`, `reference_snapshot_id`, timestamps) pass through unchanged.

## Dedup key (mandatory)

```text
provider = md.provider or md.broker          # same fallback as Drop.provider — avoid false miss
if md.source_event_id:                        # None OR "" → fingerprint (empty id is not a unique key)
    key = ("sei", instrument_id, md.source_event_id)
else:
    key = ("fp", instrument_id, provider, exchange_timestamp.isoformat(), price, bid, ask)
```

- `instrument_id` **must** be in the key (bible: `source_event_id + instrument_id`) — same provider id on two instruments is **not** a duplicate.
- **provider fallback** (`md.provider or md.broker`): `deriv` vs `deriv` must not false-miss when one field is None.
- Fingerprint path reuses M2.1 field order spirit: provider + instrument + time + quote fields — pure, no hash-of-raw required Day-1 (tuple as set member; prices as `Decimal(str(x))` to avoid float identity bugs).
- Seen-key registry: default **per `QualityGate` instance** `seen` set (`add` on accept, membership check before classify). Optional `dedup_store` replaces that set when injected. First accept stores key; second → `Drop(duplicate_tick)`.
- **No dedup if both event id and fingerprint inputs unusable** (e.g. `source_event_id` empty/None and timestamps naive — M2.3 already dropped naive; defensive: if timestamp None → fall through to classifier only, no KeyError).

## Quality classifier (mandatory order)

Apply **after** dedup accept (duplicates never classified):

1. **Pass-through `gapped`** → stay `gapped` (**never clear** — same law as M2.3 step 7).
2. **Pass-through `suspect`** → stay `suspect` (upstream already flagged; never silently promote to pristine).
3. **Pass-through `degraded` / `delayed`** → unchanged (not produced Day-1 on this path; defensive).
4. **Local spike rule (Day-1 suspect promotion)** — only if current is `pristine` **and** previous accepted tick for same `(instrument_id, broker)` exists in gate `prev_map`:
   - **prev-map key:** `broker = md.broker or md.provider` (fallback like provider — demo `frxEURUSD+deriv` ≠ `frxEURUSD+mt5`; no false spike across brokers)
   - `Δprice = |price - prev_price|`
   - `mid = (bid+ask)/2` if both present else `price`
   - if `prev_mid > 0` and `Δprice / prev_mid > spike_ratio` → **`suspect`**
   - default **`spike_ratio = Decimal("0.05")`** (5% mid-to-mid jump between consecutive accepted ticks) — constructor arg for tests; validate `0 < spike_ratio < 1` else `ValueError` at init.
5. Else remain **`pristine`**.

**Why local not rolling z-score:** no clock/history deps; G0 needs a deterministic classifier without a window buffer. Rolling z-score deferred (TODO Day-2 in status Open Questions if needed).

## Correct

1. Fresh gate: first md → accept, quality rules as above, key stored.
2. Same `source_event_id` + same `instrument_id` twice → second `Drop(duplicate_tick)`.
3. Same `source_event_id` + **different** `instrument_id` → both accept.
4. `source_event_id is None` → fingerprint key; exact same fingerprint twice → second drop.
5. Input `gapped` → output `gapped` (never pristine).
6. Input `suspect` → output `suspect`.
7. Consecutive pristine ticks, 6% mid jump → second (or the jumping tick) → `suspect`.
8. Consecutive pristine ticks, 1% jump → stays `pristine`.
9. First tick ever (no prev) → no spike check → `pristine` if already pristine.
10. Output never contains a different `watermark` than input.

## Edges

- Empty / non-tick / non-Tick payload → `Drop(missing_field)` (defensive; M2.3 should have dropped — M2.6 still fails safe).
- Naive / None `exchange_timestamp` → `Drop(invalid_timestamp)` (defensive).
- `prev_mid == 0` → skip spike rule (no div-by-zero) → leave quality as step 1–3 left it.
- `spike_ratio` out of range at construction → `ValueError` (config fail-loud).
- Duplicate detected **before** any quality rewrite — drop wins over suspect.
- Same instance reprocessed by a **new** gate (no shared store) → treated as first again (caller owns gate lifetime; pipeline uses one gate).

## Adversarial

- `source_event_id = ""` → treat as None → fingerprint path (empty id is not a unique key).
- Hostile huge price on first tick alone → no prev → not spiked (no history abuse).
- `spike_ratio=0` or `>=1` → constructor `ValueError`.
- Duplicate with different quality field on raw copy → still `duplicate_tick` (identity first).
- Fingerprint with `bid=None` vs `bid=1.0` → different keys → both accept (not false duplicate).

> Verify: `scripts/verify_m2.7_backfill.py`.

> exist in `modules/m2_market_data/recovery.py`, and the engine already takes **injected**
> `choose_source` / `fetch` / `write_backfill`. M2b.6 already classifies a window into four
> states, and `GapLedger` already owns terminal records. This slice supplies the two missing

> ledger → engine — and adds no new engine (`AGENTS.md` §4.5).

## 1. Purpose

Repair real data loss, and **refuse to repair what is not loss**. A backfill that fills
everything is more dangerous than one that fills nothing: it invents bars on weekends and
before an instrument was listed, and that corruption is permanent and silent.

## 2. The requirement, stated precisely

> "any type of hole" means **every hole shape is handled correctly — classified, then routed.**

It does **not** mean "fill every hole". Three outcomes exist, and confusing them is the
failure this slice exists to prevent:

| Outcome | Meaning | Applies to |
|---|---|---|
| **FILL** | the venue has the data, restore it | genuine loss |
| **SKIP** | the market was shut, nothing to restore | closures |
| **TERMINAL** | the venue cannot supply it, ever | outages, pre-listing, post-delisting, past retention |

And a fourth, which is neither: **`UNKNOWN`** — we could not find out. Never `CLOSED`, never
terminal. That distinction is the single most important rule in this spec.

## 3. Hole taxonomy — the routing table

This table IS the contract. One test per row.

| # | Hole type | State in | Action | Never |
|---|---|---|---|---|
| T1 | Contiguous multi-minute hole, venue has it | `FILLING` | **FILL**, chunked | — |
| T2 | Isolated single missing minute | `FILLING` | **FILL** | — |
| T3 | Venue returns only part of a chunk | `FILLING` | fill what arrived, **re-scan the remainder** | mark the window filled |
| T4 | Weekend / holiday / session closure | `CLOSED` | **SKIP** | issue a broker request |
| T5 | Venue outage — well-formed response, no bars | `CLOSED` (broker) | **TERMINAL** `PERMANENTLY_MISSING`, `source=learned` | retry forever |
| T6 | Window predates the instrument's listing | `FILLING` | **TERMINAL** | invent pre-listing bars |
| T7 | Window beyond broker retention depth | `FILLING` | **TERMINAL** | retry past the cap |
| T8 | Broker error / timeout / rate-limit / unreachable | `FILLING` | **`UNKNOWN`** → retry with bounded backoff | terminal, or `CLOSED` |
| T9 | Bar present but corrupt | not a gap | repair + flag provenance | treat presence as correctness |
| T10 | Window mixes fillable hole and closure | both | **split**, fill only the fillable part | fill across a closure |

**T8 is the highest-risk row.** A broker hiccup recorded as "market shut" permanently hides a
real gap, and the error is invisible. It is asserted explicitly.

## 4. Invariants

1. **No request is ever issued for a `CLOSED` window.** Counted, not merely asserted.
2. **A terminal window is never re-enqueued.** Enforced by `GapLedger.enqueueable`.
3. **Broker failure never produces `CLOSED` or `PERMANENTLY_MISSING`.** Only a well-formed
   response with no bars does.
4. **A partial fill never marks its window complete.** The remainder is returned for re-scan.
5. **Idempotent.** Re-running any backfill is safe and produces no duplicate rows.
6. **Bounded.** No unbounded loop and no unbounded retry; every escalation terminates.
7. **Isolated from the live path.** Separate pool, one broker request in flight, never on the
   `<50ms` tick route (`AGENTS.md` §4.1).
8. **The watermark does not leap** after a repair (`AGENTS.md` §3.9) — a defect already fixed
   in M2.7 and must not regress.
9. **Provenance retained.** A repaired bar records that it was repaired and from which source.
10. **Chunked to the venue's cap.** ~1001 minutes per request; a 30-day hole is ~44 calls.

## 5. Interfaces

```python
class HistoryBar(BaseModel, frozen):        # what the fetcher returns
    instrument_id: str; broker: str
    interval_start: datetime; interval_end: datetime
    open: Decimal; high: Decimal; low: Decimal; close: Decimal
    tick_count: int

class HistoryFetcher(Protocol):
    async def fetch(self, instrument_id, broker, start, end) -> list[HistoryBar]
    @property
    def max_span(self) -> timedelta: ...    # the venue's per-request cap

class BackfillOutcome(BaseModel, frozen):
    filled: tuple[tuple[datetime, datetime], ...]
    skipped: tuple[tuple[datetime, datetime], ...]   # closures - never requested
    terminal: tuple[tuple[datetime, datetime], ...]
    unresolved: tuple[tuple[datetime, datetime], ...] # UNKNOWN - retry later
    remainder: tuple[tuple[datetime, datetime], ...]  # partial fills
    broker_requests: int
```

`unresolved` and `remainder` are **separate on purpose**: a remainder is our bug to re-scan, an
unresolved window is the broker's to serve later. Conflating them loses the distinction between
"we did not finish" and "we were not told".

## 6. Edge cases

| # | Case | Required |
|---|---|---|
| E1 | no holes at all | zero broker requests |
| E2 | single `CLOSED` window | zero broker requests |
| E3 | one `FILLING` window, full data returned | filled; remainder empty |
| E4 | `FILLING`, venue returns nothing | terminal, learned, not retried |
| E5 | `FILLING`, fetcher raises | unresolved; **not** terminal, **not** closed |
| E6 | `FILLING`, partial return | remainder non-empty and disjoint from filled |
| E7 | window already terminal in the ledger | zero requests |
| E8 | window mixing fillable + closed | only the fillable part requested |
| E9 | 30-day hole | chunked; request count == ceil(span / cap) |
| E10 | zero-length or reversed window | `ValueError` |
| E11 | naive timestamps | `ValueError` (`AGENTS.md` §3.8) |
| E12 | window in the future | `ValueError` — the future has nothing to repair |
| E13 | fetcher returns bars outside the requested window | dropped, not written |
| E14 | duplicate bars in one response | deduplicated, one write |
| E15 | bars not sorted by time | sorted before write |
| E16 | re-run after a full success | zero requests, zero writes |
| E17 | `tick_count` 0 on a returned bar | rejected as corrupt (T9) |

## 7. Adversarial

| Input | Must |
|---|---|
| 10-year window | chunked, bounded, no OOM, no single giant request |
| fetcher returns 10× the expected bars | deduplicated and clipped |
| fetcher hangs | bounded by the injected timeout, becomes `unresolved` |
| broker returns malformed JSON | `unresolved`, never `CLOSED` |
| broker returns a huge `adjust_start_time` | treated as broker-side truncation, `unresolved` |
| retry counter at its ceiling | terminal with an explicit reason, then stops |
| concurrent backfills for one instrument | serialized, no double write |

## 8. Correctness definition

- Across the ten taxonomy rows, a single test each asserts the routed outcome **and** the
  negative — e.g. T4 asserts not just "skipped" but **`broker_requests == 0`**.
- A 341-minute real hole is repaired from recorded broker responses with the store afterwards
  reporting **zero** missing minutes.
- Re-running that repair issues **zero** further requests.

## 9. Honest limits (recorded, not hidden)

- The Deriv fetcher's **live** behaviour — real chunk edges, real partial fills, real
  rate-limit bodies — **cannot be proven in this environment**: `DERIV_DEMO_API_TOKEN` is an
  empty placeholder and the Deriv WebSocket is network-blocked. It is unit-tested against
  recorded response shapes and verified live in the joint Deriv session.
- Broker retention depth is **measured, not assumed** (earlier probe: at least 19h, 30d ≈ 44
  requests, ~1001 min/request cap). T7 uses that measured cap.

## 9b. MONEY-PRECISION BOUNDARY — human-authorised spec supersession (2026-09-27)

> **Human directive:** *"if a contribution is truly more valuable than what the spec says,
> supersede the spec while the changes are noted."* Recorded, not applied silently.

### What changed

`AGENTS.md` §3.1 lists `price` among the monetary-settlement fields that must never be `float`.
That is **correct for settlement and over-broad for market data.** The boundary is now drawn
explicitly:

| Data | Representation | Authority |
|---|---|---|
| **Quotes / candles / ticks** — `MarketData.price`, `candles_1m.open/high/low/close` | `double precision` is acceptable | **superseded** — this section |
| **Settlement money** — PnL, fees, commission, slippage cost, balances, margin, positions, ledger postings | **`Decimal` / `NUMERIC`, mandatory, no `float` even as an intermediate** | §3.1 unchanged, in full force |

### Why this is better, not a loosening

Measured 2026-09-27 against the broker's real ticks (`pip_size`, authoritative):

| Instrument | Price | Significant digits | `double` provides | Margin |
|---|---|---|---|---|
| `CRYPTO.BTCUSD` | 84296.692 | 8 | ~15 | **7 orders** |
| `FX.EURUSD` | 1.08542 | 6 | ~15 | 9 orders |
| `COMMODITY.XAUUSD` | 3351.45 | 6 | ~15 | 9 orders |
| `COMMODITY.XAGUSD` | 38.1234 | 6 | ~15 | 9 orders |

A `double` carries roughly **seven to nine orders of magnitude** more precision than the
smallest price increment we can observe, and every one of those four values round-trips
exactly. Forcing `NUMERIC` on candle storage would cost write throughput and a migration while
adding **no** accuracy at these magnitudes.

The arithmetic that actually matters is unaffected and still strictly `Decimal`:

```python
Decimal("0.1") + Decimal("0.2") == Decimal("0.3")   # True  <- required
0.1 + 0.2 == 0.3                                     # False <- why money is never float
```

### The rule this replaces

> ~~No `float` anywhere, including market-data price fields.~~

**Replaced by:** no `float` in **settlement money**, at any depth, including intermediates.
Market-data quotes may be `double` where the tick is coarser than the representation's
resolution by a wide margin — and that margin must be **measured per instrument**, not assumed.

### Consequence, and the trap

The `float()` cast in `scripts/verify_m2.7_repair_real_hole.py` is now **schema-forced and
sanctioned**, not a violation. The trap this creates is real and must be named: a repaired
candle's price is a `double`, and any future code that does arithmetic on it to produce money
would import a float into the settlement path. **So the boundary is enforced where it matters —
`normalize.py` parses prices as `Decimal` from the quoted tick string before any money is
derived, and PnL/fee/commission paths take `Decimal` inputs, never the stored `double`.**

If a future instrument ever needs more than ~12 significant digits, or a value beyond the
`double` range, this exemption is void for it and the column must become `NUMERIC`.


## 9a. The Deriv `ticks_history` fetcher (added 2026-09-27, human "go")

### 9a.1 Contract

`modules/m2_market_data/history.py`. A `ticks_history` call is
`{ticks_history: <native symbol>, start: <epoch>, end: <epoch>, count, style: "candles"}`
and answers `{history: [...], adjust_start_time: <epoch>}`.

- **`Transport` is injected.** `Callable[[dict], Awaitable[dict]]`. This is what makes the
  fetcher testable against recorded response shapes with no network and no token, and it is
  the seam the joint Deriv session will exercise for real.
- **`max_span` = 1001 minutes** (measured, not assumed). A request wider than this **raises**
  rather than being silently clamped: a silently truncated response would look like a
  complete one and would leave lost minutes queued forever.
- **Prices are `Decimal` built from the JSON string.** Deriv sends `"1.08542"`, which is
  exact. A **float** price is **rejected** under the same money law as M2b.3/M2b.5 — one law
  for the whole system.
- **`adjust_start_time` is a retention signal, not noise.** If it is later than the requested
  start, the venue truncated the window. The fetcher surfaces that so the caller can mark the
  pre-retention part **terminal (T7)** instead of re-requesting it forever.

### 9a.2 Rules

| # | Rule |
|---|---|
| H1 | one call per window; the coordinator owns chunking |
| H2 | a request wider than `max_span` raises — never silently truncated |
| H3 | every price parsed as exact `Decimal` from a string; a float is rejected |
| H4 | `tick_count <= 0`, `low > high`, or non-positive price → the bar is dropped as corrupt |
| H5 | an `error` member raises a typed `BrokerHistoryError` → coordinator maps to `UNRESOLVED`, **never** to closed or terminal |
| H6 | a response with no `history` key raises; an **empty** `history` list is a valid "no data" answer |
| H7 | `adjust_start_time` later than the request start is surfaced as truncation |
| H8 | epochs are seconds → tz-aware UTC; a bar at exactly `end` is excluded |
| H9 | bars are sorted ascending and deduplicated on `interval_start` |
| H10 | the broker-native symbol is resolved through the reference master, never string-built |

**H5 and H10 are the two that matter most.** H5 is why a broker error can never become a
permanent closure. H10 is `AGENTS.md` §3.2: the adapter is the only place that knows
broker-native protocol, so an M2 core must never assemble `frxEURUSD` itself.

# Spec: M4.9 Approval UI — admin section control loop (API + Admin Trading panel)

Purpose: Give the Admin workspace a working approval control — list every registry
strategy with its effective M4.8 approval state, and perform legal state transitions —
through a new thin gateway endpoint and the existing `/admin/trading` surface.

Human directives: 2026-10-07 "go on" (draft this spec after M4.8 `complete` + the
question "have you implemented the approval ui in the admin section in the frontend").

## 1. Scope — one slice, two halves

- **A. Backend:** `modules/experience/api/v1/approval_router.py` — two routes, thin
  (validate → service → frozen envelope), following `market_router.py` law (no
  arithmetic, no invented error codes, no store imports outside the seam).
- **B. Frontend:** `frontend/services/approval_api.ts` (single network choke point,
  the `market_data_api.ts` pattern) + wire the **Strategies** panel of
  `frontend/app/AdminTradingSurface.tsx` from mock-empty to real data.

No new frozen contract: the slice consumes the frozen `StrategyApproval` /
`StrategyState` (contracts pkg 2.3.0), the frozen envelope (`envelope.py`), and the
frozen `ErrorCode` enum as-is. §2 Step 2 = n/a.

## 2. Backend contract

### GET /api/v1/strategy-approvals

- **Auth:** `X-Role` header, normalized exactly as `build_account_router._require_role`
  (strip + lowercase) then `can(role, "strategy.approve")` — `admin` has `*` so it
  passes; viewer / trader / missing / unknown → **403** envelope `permission_denied`,
  **zero store calls**.
- **List construction (one read per registry entry, no cache):** iterate the strategy
  registry (same iteration the M4.8 verify script uses); per entry
  `row = await store.get(sid, version)`:
  - row present → effective `state = row.state`, metadata from the row;
  - row absent → **implicit draft**: `state = "draft"`, `changed_by = changed_at = note = null`
    (the API must NOT expose the store's display-only synthetic sentinel — the
    frontend renders `—` for null metadata).
- **Response (envelope_success):** `data = {strategies: [{name, strategy_id,
  version, state, changed_by, changed_at, note}]}` — `name` = registry display name;
  `strategy_id` is echoed so the UI can build the POST body; `meta.as_of` is the
  authoritative timestamp (no duplicate data-level `as_of`); `state` is server-truth
  only, never client-computed. No pagination (registry ~12 entries; pagination
  is a later concern, flagged not solved).

### POST /api/v1/strategy-approvals/state

- **Body:** `{strategy_id: str, version: str, new_state: StrategyState,
  note?: str | null (<=200), changed_by?: str (non-empty after strip, default
  "admin:ui")}`. `changed_at` is **server-stamped by the store** — a client timestamp
  is ignored, never read.
- **Auth:** same `strategy.approve` check as GET (403 before body parsing of store
  effects — FastAPI parses the body, but the store is never touched).
- **Call:** `store.set_state(sid, version, new_state, changed_by=..., note=...)` →
  reply `envelope_success(approval as read back from the store)` (the store's
  read-back proof is the response body).
- **Error map — frozen codes ONLY, nothing invented:**

| Failure | HTTP | ErrorCode |
|---|---|---|
| role cannot `strategy.approve` | 403 | `permission_denied` |
| body invalid (state literal, note>200, changed_by blank, unknown extra field) | 422 | `capability_not_supported` (malformed-input precedent, market_router) — ALL replies go through the envelope; the handler parses the body itself (Pydantic inside the handler) so body-validation failures are envelope-shaped, never FastAPI's `detail` dialect |
| `UnknownStrategyApprovalError` (registry gate, before SQL) | 404 | `unknown_symbol` — **FLAG Q2:** market-flavoured name; a truthful `unknown_strategy` member would be an AGENTS §5 contract addition (minor bump) — human call at LGTM; default = reuse |
| `ApprovalTransitionError` (matrix gate) | 409 | `illegal_transition` (message carries from→to) |
| `ApprovalStoreError` (unwired / read / write failure) | 503 | `unknown_state` — semantics: state undeterminable ⇒ fail-closed, retryable (market_router comment: this code maps to 503) |
| anything else | re-raise (FastAPI 500) — same defensive posture as market_router / `_gate_errors` | — |

## 3. Frontend contract

- **`services/approval_api.ts`:** the ONLY frontend module allowed to call these
  endpoints. Functions `listApprovals(role)` / `setApprovalState(role, input)`; every
  call sends `X-Correlation-Id` (crypto.randomUUID, existing pattern) and `X-Role`
  (explicit `role` argument — fail-closed: no argument ⇒ no header ⇒ backend 403;
  no module-global role). Components never call `fetch`.
- **`AdminTradingSurface.tsx` Strategies panel** (App passes `role` as a prop; the
  route already refuses non-Admin):
  - **States:** `loading | ready | empty | unavailable(503) | forbidden(403)`.
    First-load failure → banner `approval store unavailable — no state shown` and
    **zero rows** (never fabricate; M10.4.4 honesty rule). Later 503 → keep last rows
    with the banner visible (dataState philosophy: an enum the UI is forced to switch
    on, not a boolean it can forget).
  - **Table:** display name, version, state chip (all 5 states styled distinctly),
    changed_by / changed_at / note (`—` when null = implicit draft), actions.
  - **Action buttons = computed, never hardcoded:** mirrored constant
    `LEGAL_TRANSITIONS` in the TS, equal to the backend `_LEGAL` matrix — pinned by a
    cross-tree parity test (the `m10.4.10` timeframe-parity precedent). Only legal
    targets render as buttons; illegal ones do not exist in the DOM (not merely
    disabled).
  - **Every transition requires an explicit confirm** — entering `approved` makes the
    strategy runnable by traders (runner gate), so no silent clicks. In-flight:
    buttons disabled (no double-submit). Success → row replaced **only from the
    response body**; 409 → inline error, row untouched; 503 → banner, row untouched
    (no optimistic local mutation anywhere).
  - `NoContractNote` is removed **only** from the Strategies panel (the contract now
    exists); the other panels keep theirs unchanged.

## 4. Edges (each edge = one test)

- E1 missing / viewer / trader / unknown `X-Role` on GET and POST → 403
  `permission_denied`, store untouched.
- E2 store unwired or DB down → GET and POST → 503 `unknown_state`; UI first-load →
  banner + no rows.
- E3 implicit draft (no row) → listed `state="draft"`, metadata null; no synthetic
  sentinel fields leak into the API output.
- E4 empty registry → `200 {strategies: []}`; UI renders its honest empty state.
- E5 legal transition (e.g. `draft→testing`) → 200; response body equals a fresh
  `store.get()` (read-back proof).
- E6 illegal transition (`draft→approved`, `testing→discontinued` REV3-legal set
  re-checked) → 409 `illegal_transition`; store unchanged (get() proves it).
- E7 contract violations (`new_state="APPROVED"`, 201-char note, `changed_by="  "`)
  → 422 envelope; zero SQL (fake connection counts).
- E8 unknown / injection `strategy_id` (`x'; DROP TABLE`) → 404 `unknown_symbol`,
  zero SQL (registry gate fires before any statement).
- E9 REV3: two strategies in `testing` simultaneously both appear as rows.
- E10 concurrent admin writes → last committed write wins (M1.5 precedence), no
    error; refresh shows the committed state.
- E11 POST 503 mid-session → no local mutation; banner up; row still shows last
    server-confirmed state.
- E12 non-Admin navigation to `/admin/trading` → existing App route gate
    (`AccessPreview`) unchanged — this slice touches no routing logic.

## 5. Definition of correct

- Every reply is the frozen envelope; the frontend branches on `error.code` only.
- `LEGAL_TRANSITIONS` (TS) == `_LEGAL` (backend) — parity test, not eyeballing.
- Effective state comes from the store on every GET; the UI never derives state.
- `changed_at` rendered exactly as returned (UTC); nothing re-rounded client-side.
- Store unreadable ⇒ the UI shows nothing new (fail-closed display), never a guess.

## 6. Adversarial

- `X-Role: root` / `Admin` (case variant) / `""` → normalization matches account
  router; only `admin` passes, everything else 403.
- Body: unknown id, SQL-ish strings, note with markup, oversized note → 404/422 with
  typed codes, zero SQL, rendered text is React-escaped (no `dangerouslySetInnerHTML`).
- Client-supplied `changed_at`/unknown fields in the body → **rejected 422**
  (`extra="forbid"` on the request model); the handler reads only the declared fields.

## Components

### 1. `strategy_registry.py` — the discoverer (P22 gate)
- `StrategyRegistry.load()` — sync `def` (startup, before the event loop —
  mirrors M1.3 config-load precedent; no I/O beyond imports). Walks
  `modules/m3_analytics/strategies` via `pkgutil.itermodules`, **skips
  `_`-prefixed** (same discovery rule m4.2 tests lock), and for each module
  validates the frozen contract: `NAME` non-empty snake_case == module stem;
  `FEATURE_SLOTS` non-empty, values `(str, dict)`, analytic names **distinct**;
  `PARAM_DEFAULTS` all finite floats; `evaluate` signature exactly
  `["features", "params"]`; no `provider`/`clock`/`as_of`/`candles` attributes
  (Isolation flavor). **Any violation → `StrategyContractError` — fail startup,
  never skip-and-continue** (a silently missing family is a business failure).
- Duplicate `NAME` across modules → `StrategyContractError`.
- Re-entrant: `load()` rebuilds then swaps atomically (second call = same set).
- API: `get(name) -> StrategyEntry` (raises `UnknownStrategyError`),
  `names() -> tuple[str, ...]` sorted, `entries() -> tuple[StrategyEntry, ...]`.
- Manual §3 `@register_strategy` decorator maps to this discovery+validate path;
  families are D4 function-modules, not classes (Discrepancies flagged below).

### 2. `parameter_registry.py` — yaml + version + precedence
- Reads `config/strategies/{NAME}.yaml` if present (trend_following exists;
  the other 6 Day-1 absent → defaults path, tested). Known keys:
  `strategy_id` (optional, else `NAME`), `version` (optional, else `"1.0"`),
  `params` (mapping str→number), `valid_until_seconds` inside params.
  `entry_model`/`stop_model`/`target_model` keys are **parsed-ignored** (M4.5
  owns them — recorded, not silently dropped from the file format).
- Shape violations (yaml parse error, `params` not a mapping, `version` not str,
  non-number param) → `ParameterConfigError` **at load, not at signal time**.
- Precedence (one definition): **request `strategy_params` > yaml `params` >
  `PARAM_DEFAULTS`**, merged into one dict, then runner-validates
  `valid_until_seconds` (default 60, bounds 1..3600 else ValueError).
  Unknown keys pass through (m4.2 evaluate ignores them — ema_fast etc. in the
  existing yaml are exactly this case).

### 3. `base_strategy.py`
- `BaseStrategy(ABC)` — sync pure `generate(self, analytics: AnalyticsResult,
  market: MarketData, now: datetime) -> Signal | None`; `name: str`,
  `version: str` class attrs. WHY `now` explicit: no clock reads → deterministic
  + M8 SimulatedClock-compatible. D4 function files are adapted into entries by
  the registry (they are not subclasses — see Discrepancies); the ABC stays the
  documented shape the bible mandates and the runner's output contract.
- `StrategyEntry` as above (frozen).

### 4. `lifecycle.py` — enable/disable per user
- In-memory: `default enabled = True` for every discovered strategy (capability
  gate does the real Day-1 filtering; Tier-3 stays disabled via M3.0 law).
- API: `disable(name, user_id: str | None = None)`,
  `enable(name, user_id: str | None = None)`,
  `is_enabled(name, user_id: str | None = None) -> bool`.
  Unknown name → `UnknownStrategyError` (loud). user_id `None` = platform
  default scope. Persistence → M10 (`POST /strategies/{id}/enable`), out here.

### 5. `shadow_mode.py` — the promotion bouncer
- Pure: `apply_shadow(signal, *, env: Literal["prod","paper"],
  allowlist: frozenset[str]) -> Signal` with key
  `f"{strategy_id}@{version}"` (e.g. `trend_following::ema_trend@2.1`).
- Rules: `env="paper"` → never shadowed (paper allows all); `env="prod"` and
  key **not** in allowlist → `shadow=True` (WHY fail-closed: nothing reaches M5
  live until a human promotes the exact version — M12 canary promotes later);
  prod + allowlisted → unchanged. Invalid env → ValueError.
- Allowlist source: `config/strategies/shadow_allowlist.yaml`
  (`prod: ["trend_following::ema_trend@2.1", ...]`); **missing file → empty prod
  allowlist = everything shadows in prod** (fail-closed, tested). `paper:` key
  read-ignored day-1 (paper never shadows anyway) — kept in schema for M12.

### 6. `runner.py` — async glue, the only Signal constructor
```python
class StrategyRunner:  # deps injected (engine, capability, registries) → testable with fakes
    async def run(self, name: str, *, market: MarketData, instrument_id: str,
        broker: str, timeframe: str, asset_class, as_of: datetime, now: datetime,
        env: str, user_id: str | None = None,
        strategy_params: dict[str, float] | None = None) -> Signal | None
```
Pipeline (each gate fail → `None` + structured log reason; contract breach → raise):
1. **Validate loud before I/O**: `as_of`/`now` tz-aware UTC, non-empty
   broker/instrument/timeframe, `asset_class` in forex|crypto|commodity,
   `env` in prod|paper → else ValueError.
2. `registry.get(name)` → `UnknownStrategyError` propagates.
3. **Capability gate**: `is_strategy_eligible(entry.name, broker)` → `False`
   → return `None` (log reason — normal state: Tier-3 on deriv). This is how
   `microstructure_flow` can never fire on deriv (bible §9: M3.0 UNAVAILABLE →
   M4.1 keeps strategy DISABLED).
4. **Lifecycle gate**: `is_enabled(name, user_id)` → `False` → `None`.
5. **FeatureRequest**: `features` = tuple of the distinct slot analytics;
   `param_overrides` = `{analytic: overrides}` built from `FEATURE_SLOTS`
   (runner's job per m4.2 contract); `as_of` = PIT boundary (WHY distinct from
   `now`: as_of = what data existed, now = freshness clock); `timeframe`
   explicit passthrough (no hidden default).
6. `await engine.get_features(request)` → `AnalyticsResult`. Engine errors
   propagate (I/O fail-open behavior is the engine's law, not re-wrapped here).
7. **Slot map**: `{slot: result.features[analytic]}` — missing analytic key →
   ValueError naming slot+analytic (fail loud, never a silent 0.0 signal);
   `None`/non-finite slot value → ValueError.
8. **Params**: merge per §parameter_registry precedence; runner validates
   `valid_until_seconds`.
9. `value = entry.evaluate(features, params)` — its `ValueError` **propagates**
   (wiring bug, loud). Return value: non-float / `None` / `abs(value) > 1.0`
   → `StrategyContractError` (**never clamp** — contract breach, §3.14).
10. `value == 0.0` → return `None` (no intent).
11. **Signal construction (hand-verified mapping)**: `signal_id=uuid4()`;
    `strategy_id` = yaml `strategy_id` else `NAME`; `version` = yaml version
    else `"1.0"`; `symbol=market.symbol`; `direction = "long" if value > 0
    else "short"`; `strength = abs(value)` (contract guarantees ≤1.0);
    `timeframe` passthrough; `valid_until = now + valid_until_seconds`;
    `analytics_refs=[analytics.correlation_id]`; `shadow` computed in step 12;
    `user_id` passthrough; `provenance = Provenance(producer=
    f"m4.alpha/{strategy_id}@{version}", analytics_ids=[correlation_id],
    market_watermark=market.watermark, signal_strength=value)`;
    `explainability=None` day-1 (no weight model exists yet — honest, not
    faked; M4.4 owns).
12. `apply_shadow(signal, env=..., allowlist=...)` → final Signal.
    Shadow signals are still **returned** (M4.3 drops them later — never
    converted to `None` here).

## Correctness (definition of done per rule)

- Strength mapping is exact float pass-through: `evaluate → +1.0` ⇒ long
  strength `1.0`; `−0.75` ⇒ short `0.75`. No rounding, no clamping, no floor
  (m4.2 ramp already sets its own floor; runner adds none).
- Precedence hand: trend_following yaml `rsi_threshold: 60`, request override
  `{"rsi_threshold": 55}` ⇒ effective `55`; request absent ⇒ `60` (yaml);
  yaml absent (mean_reversion) ⇒ `PARAM_DEFAULTS`.
- Validity hand: `now=2026-09-26T12:00:00+00:00`, window `60` ⇒
  `valid_until=2026-09-26T12:01:00+00:00` exact (UTC, no clock read).
- Shadow hand: prod, key `trend_following::ema_trend@2.1`, allowlist empty ⇒
  `shadow=True`; same run env=paper ⇒ `shadow=False`; allowlist contains key in
  prod ⇒ `False`.
- Determinism: two runs, same inputs ⇒ equal Signals on every field except the
  generated ids/timestamp (`signal_id/trace_id/correlation_id/timestamp`).
- Capability hand: `microstructure_flow` @ deriv ⇒ `None` (real
  `capabilities.yaml`, reason `order_book_imbalance UNAVAILABLE`).

- B2 `evaluate` returns `None`/`"x"` ⇒ `StrategyContractError`.

- B4 hostile extra feature keys from engine ⇒ ignored (only slots read).
- B5 runner `env="live"` ⇒ ValueError; `broker=""` ⇒ ValueError (before I/O).
- B6 after a B1/B3 failure, next run with good inputs still succeeds

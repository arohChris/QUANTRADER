# Spec: M2.12 News Ingest

Purpose: fetch **primary-source** news (central banks and regulators) over RSS, normalise
it to a frozen contract, and serve it read-only to the UI. Nothing else.

This slice exists because the Overview was showing invented headlines. That was removed,
and this is the honest replacement: a real source, or an honest "not connected".

## Scope

**In:** RSS fetch → parse → validate → normalise → store → serve. Read-only display data.

**Out, deliberately:**
- **No sentiment, no scoring, no "momentum improving".** A judgement about an asset is an
  analytic, and analytics are M3. M2 moves bytes; it does not interpret them.
- **No third-party news copy.** Primary institutional sources only (see Licence). We store
  a title and a link, never a republished body.
- **Not a trade input.** No M3/M4 code may read a `NewsItem` as a signal until a strategy
  manifest declares the requirement and a DependencyReport says `ELIGIBLE`. Until then it
  is display data, exactly like `HistoryRequest` is display data.
- **Not on the tick path.** A feed refresh is a background task with jitter. A slow or dead
  feed must never delay or fail a tick.

## Sources and what we may reproduce

Sources are **not** all the same kind. Central banks are one case; reputable commercial
publishers are another, and the difference is legal, not stylistic: an RSS feed being
public does not make its contents redistributable. So every source carries a **licence
class**, and the contract carries that decision through to the UI.

| `redistribute_text` | Meaning | What the UI may show |
|---|---|---|
| `true` | Open licence / public domain — reuse permitted (attribution) | title + link + publisher + time |
| `false` | Copyrighted publisher feed — link out only | publisher + section + item count + time, **no reproduced text** |

This means a Reuters or FT item can appear in the Overview *as a source with a link*,
without us republishing their headline. That is the only defensible way to include them.

### Tier 1 — open licence, text may be reproduced

Primary institutions and public-data publishers:

| id | publisher | category | class |
|---|---|---|---|
| `ecb` | European Central Bank | `monetary_policy` | open |
| `fed` | Federal Reserve | `monetary_policy` | open |
| `boe` | Bank of England | `monetary_policy` | open |
| `cftc` | CFTC | `regulation` | open |
| `sec` | SEC | `regulation` | open |
| `bis` | BIS | `macro` | open |
| `imf` | IMF | `macro` | open |
| `oecd` | OECD | `macro` | open |
| `worldbank` | World Bank | `macro` | open |
| `federalregister` | Federal Register | `regulation` | open (US GovInfo, public domain) |
| `arxiv` | arXiv (econ.GN, q-fin) | `research` | open (CC BY) |

### Tier 2 — reputable commercial publishers, link out only

Configured, fetched, counted — but **not reproduced**:

| id | publisher | class |
|---|---|---|
| `reuters` | Reuters | link-only |
| `ft` | Financial Times | link-only |
| `marketwatch` | MarketWatch | link-only |

Adding either tier is **config, not code**: `config/news_sources.yaml` gains
`id, publisher, feed_url, category, enabled, redistribute_text`. A source whose licence
class is unknown defaults to `redistribute_text: false` — fail closed, so forgetting the
field can never cause a leak.

**Commercial APIs are still a separate later decision** — an API key is a vault secret and
its licence may permit fuller redistribution than the public feed does.

We never republish an article **body** from any source.

| `image_url` | `str \| None` | per-item media enclosure; `null` is a supported state |
| `image_alt` | `str \| None` | **required whenever `image_url` is set**; never a placeholder |

**Images are copyrighted exactly like headlines**, so `image_url`/`image_alt` obey the
same `redistribute_text` rule: for a link-only source they are **omitted from the API
response** alongside the title. A publisher that will not let you quote the headline will
not let you hotlink their photograph either.

Image rules:
- `image_url` must be `https://`; a feed offering `http://` gets no image, not a broken one.
- `image_url` set with `image_alt` missing → the **item is rejected**, because an image
  with no alt text is unreadable for a screen reader. Never default the alt to the title
  or to "image".
- The `alt` is the publisher's own title text, so it names the subject rather than the
  asset ("ECB holds rates steady", not "ECB press release image").
- We link the image the publisher serves rather than proxying or re-hosting it, so the
  traffic and the copyright position stay where they belong. A hotlink that fails must
  degrade to the text row, never to a broken frame.

## Contract — `shared/contracts/news.py`

`NewsItem` (frozen, `extra="forbid"`):

| field | type | rule |
|---|---|---|
| `item_id` | `UUID` | `uuid5(NEWS_NS, f"{source_id}:{guid}")` — deterministic |
| `source_id` | `str` | must exist and be enabled in the registry |
| `publisher` | `str` | from the registry, never from the feed |
| `category` | `Literal["monetary_policy","macro","regulation","market"]` | from the registry |
| `title` | `str` | bounded length, HTML-escaped on render |
| `url` | `str` | must be `https://` |
| `published_at` | `datetime` (UTC) | **from the feed only — never our clock** |
| `fetched_at` | `datetime` (UTC) | our clock |
| `availability_time` | `datetime` (UTC) | `= published_at`; the §6a PIT field |
| `summary` | `str \| None` | feed-provided text only, never generated |
| `reference_snapshot_id` | `str \| None` | lineage |
| `redistribute_text` | `bool` | from the source registry; **`False` for every link-only source** |

When `redistribute_text` is `False`, `title` and `summary` are **not** exposed through the
serve layer at all — they are stored for internal de-duplication and link resolution, and
the API omits them. Storing-then-hiding would leak through any future serialiser, so the
omission happens at the boundary, every time.

`NewsSnapshot` (frozen):

| field | type | rule |
|---|---|---|
| `status` | `Literal["fresh","stale","degraded","unavailable"]` | roll-up over source health |
| `items` | `list[NewsItem]` | ordered `(published_at DESC, item_id ASC)` |
| `as_of` | `datetime` (UTC) | our clock at snapshot time |
| `source_health` | `dict[str, Literal["ok","failed","stale"]]` | per source |
| `last_good_at` | `datetime \| None` | when the last fully-successful cycle ran |

**Money law: not applicable.** `NewsItem` carries no price, qty or balance field, so
`Decimal`/fixed-point does not apply here. Stated explicitly so it is a decision, not an
oversight.

## Correctness

- `item_id` is deterministic, so re-polling a feed **cannot** duplicate an item — the
  uniqueness is structural, not a cleanup step.
- `published_at` comes from the feed. If it is absent or unparseable the item is
  **rejected**, never backfilled with `fetched_at`: substituting our own clock would
  manufacture freshness and break PIT.
- Ordering is a total order (`published_at DESC`, then `item_id ASC`) so paging and
  snapshot diffs are stable.
- `availability_time = published_at`, so a replay at `as_of T` cannot see a release
  published after `T`.

## Edges

| # | Case | Expected |
|---|---|---|
| 1 | One feed unreachable | that source `failed`; **last good items for it retained**; `status=degraded` |
| 2 | Every feed fails | `status=unavailable`; `last_good_at` preserved; `items` = last good (may be empty) |
| 3 | Item has no `published_at` | item rejected; other items from the same feed still accepted |
| 4 | `published_at` in the future | rejected (`availability_time > fetched_at` is a clock/feed fault) |
| 5 | Same `guid` on re-poll | same `item_id`; upsert is a no-op; no duplicate |
| 6 | Same title, different `guid` | both kept — they are different items |
| 7 | Malformed XML | typed `NewsParseError`; source `failed`; **no partial parse** |
| 8 | Valid XML, zero items | source `ok`, contributes nothing; not a failure |
| 9 | Feed body over the byte cap | typed `NewsFetchError`; source `failed`; body never buffered whole |
| 10 | `http://` feed or link | refused — HTTPS only, including after redirects |
| 11 | Item count over the per-source cap | capped deterministically, newest first, and the drop is counted |
| 12 | `guid` missing | fall back to `url`, then `title + published_at`; if all missing, reject |
| 13 | Source disabled in config | skipped entirely; not reported as failed |
| 14 | `category` not in the `Literal` | item rejected, feed kept — a config error is not a feed failure |
| 15 | `summary` longer than the cap | truncated on a word boundary and marked as truncated |
| 16 | Source with `redistribute_text: false` | item stored, but `title`/`summary` omitted from every API response |
| 17 | Source missing `redistribute_text` in config | treated as `false` — fail closed |
| 18 | Link-only source is the only source that updated | snapshot is **not** `fresh`; the UI shows the open sources' age, not a false "new" |
| 19 | A tier-2 source dominates the item count | the UI must not imply its headlines are visible; it shows the source and a link |
| 20 | `image_url` present, `image_alt` absent | item rejected — an image with no alt is unreadable |
| 21 | `image_url` on `http://` | image dropped, item kept; the row renders as text |
| 22 | Image URL 404s at render time | row degrades to text-only; no broken frame, no layout shift |

## Adversarial (not in the normal path, must fail safely)

- 10 MB feed body → byte cap trips, typed error, no OOM, source `failed`.
- `published_at` two days in the future → rejected as a boundary violation.
- `<script>` inside a title → stored bounded, escaped at render, never injected.
- `guid` present but empty string → treated as missing, falls through the fallback chain.
- Feed returns HTTP 200 with an HTML error page instead of a feed → parse error, **not**
  an empty snapshot presented as "no news".
- A source whose feed returns the same 25 items for a week → `stale`, not `fresh`; the
  UI shows the age rather than implying newness.

## Storage

- Timescale hypertable `news_items`, hypertable column `published_at`, `UNIQUE(item_id)`.
  Separate from `candles_1m` — news is not a candle and must not pollute the market-data
  schema or the `interval_start` indexes.
- Valkey may hold the last-good snapshot **as acceleration only**, never as the source of
  truth, consistent with "Valkey is hot state only".
- No parquet lake write. News is not replayed as market data.

## Serve

`GET /api/v1/news` — Viewer, Trader, Admin. Read-only, no tenant scope, no `user_id`
(news is global, like market data). Response is `NewsSnapshot`.

## Tests (written before code)

One test per edge above, plus every adversarial case, each asserting a **specific value
or a specific typed error**. No test may assert only "does not raise". Fixtures use
`SimulatedClock` — no wall-clock, no network: every fetch is a stub returning a byte
fixture, and re-polling the same fixture must be provably idempotent.

Verification: run the real ECB/Fed feeds once, manually, and record the parse result —
the fixtures alone cannot prove a real feed parses.

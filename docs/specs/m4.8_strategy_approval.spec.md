# Spec: M4.8 Strategy Approval (persisted lifecycle state + fail-closed visibility + multi-strategy testing [REV3])

Purpose: One authoritative, persisted state machine per `(strategy_id, version)` that
answers two questions for every strategy — **may this role see it?** and **may it run?** —
fail-closed: an unknown strategy is trader-invisible and unrunnable by default (an admin
still sees it as `draft` — visibility is role-dependent, REV1).

Human directives (binding, 2026-10-03):
- **"let the strategy state include discontinued which can later be approved"** — the
  state set is `draft | testing | approved | rejected | discontinued`, and
  `discontinued -> approved` is a legal transition (explicit human law).
- ~~Admin control so **only a single strategy runs for testing** (one global testing
  slot).~~ **REV3 (2026-10-07, human directive: "we should be able to test multiple
  strategies at a time") — the single platform-wide testing slot is REMOVED**; any number
  of strategies may hold `testing` concurrently. Risk posture is unchanged: the REV2
  runnability table still confines `testing` to admin + paper only (never prod, never
  trader) — THAT confinement, not the slot count, is the safety boundary.

  disapproved and no user sees it"** — **trader**-visible = `approved` only; NOT approved

  (a) admin may paper-test `approved`, `rejected`, `discontinued` (not only `testing`);

## State machine

States: `draft | testing | approved | rejected | discontinued`.
Key: `(strategy_id, version)`. `set_state(...)` is the ONLY writer.

State meanings (human law, 2026-10-03):
- **`draft` = NOT FULLY BUILT** — work in progress; runnable by NOBODY, ever, anywhere
  (admin included); admins see it only to track build progress.
- `testing` = built, **under refinement** (human 2026-10-03: "testing is for
  refinement") — the admin iterates on it in paper until it is good enough to approve.
  **REV3 (2026-10-07):** MULTIPLE strategies may hold `testing` simultaneously (the
  former one-slot limit is removed); admin + paper confinement remains the control.
- `approved` = validated; trader-visible and trader-runnable.
- `rejected` = failed evaluation; admin-retestable in paper, trader-hidden.
- `discontinued` = retired; admin may paper-test it (e.g. before a restore) and may
  restore it directly (`-> approved`), trader-hidden.

Transition matrix — ✓ legal, ✗ typed `ApprovalTransitionError`, same-state = idempotent
no-op (row returned unchanged, `changed_at` NOT bumped, no SQL write):

| from \ to | draft | testing | approved | rejected | discontinued |
|---|---|---|---|---|---|
| (missing = draft) | no-op | ✓ | **✗** | ✓ | ✓ |
| testing | ✓ (undo) | no-op | ✓ | ✓ | **✗** |
| approved | **✗** | ✓ (rework) | no-op | ✓ (revoke) | ✓ (retire) |
| rejected | **✗** | ✓ (retest) | **✗** | no-op | **✗** |
| discontinued | **✗** | ✓ (retest) | ✓ (restore) | **✗** | no-op |

Rationales (each ✗ is a deliberate rule, not an omission):
- `draft -> approved` **✗**: `draft` = not fully built (human 2026-10-03) — it must be
  built, then pass `testing` before traders ever see it (dry-run-first §3.10; admins
  see it as `draft` throughout). The one-time legacy seed bypasses this via
  migration DDL (`seed_legacy_approved`, ON CONFLICT DO NOTHING), never via `set_state`.
- `rejected -> approved` **✗**: a quality rejection must re-enter through `testing`.
- `discontinued -> approved` **✓**: **human law 2026-10-03** — a retired strategy may be
  restored directly (admin judged its history sufficient); `discontinued -> testing`
  remains available when a retest is wanted.
- `approved -> rejected` **✓** (emergency revoke) vs `approved -> discontinued` **✓**
  (clean retire): both end visibility; admin chooses by intent.
- `* -> draft` only from `testing` (undo a start) — `draft` means "never reviewed";
  moving an approved/rejected/discontinued row there would erase that meaning while the
  row (and its audit fields) survive — the matrix refuses it instead of lying.
- `testing -> discontinued` / `rejected -> discontinued` **✗**: those states have their
  own exits (`rejected` / nothing changed); discontinued means "was live, now retired".

## Store — `shared/core/strategy_approval_store.py`

Async class `StrategyApprovalStore`, mirroring `TradingPrefsStore` laws:
connection injected (`conn=None` = unwired -> `ApprovalStoreError`, never AttributeError);
all SQL parameterized; writes registry-checked against `known_strategies: set[str]`
(unknown id -> `UnknownStrategyApprovalError` **before** SQL); `changed_at` system-stamped
with monotonic clamp (`max(now, last+1µs)` per instance); every DB exception wrapped as
`ApprovalStoreError` (fail-closed both directions); single-statement upsert = no partial
writes.

Methods:

- `async state(strategy_id, version) -> StrategyState` — row lookup, else `'draft'`.
  DB failure -> `ApprovalStoreError` (never a guessed state).
- `async get(strategy_id, version) -> StrategyApproval | None` — full row or None
  (caller decides implicit-draft display).
- `async set_state(strategy_id, version, new_state, *, changed_by, note=None) -> StrategyApproval`
  — validates `new_state` (Literal) and `changed_by` (non-empty) and `note` (<=200) via
  contract **before** SQL; registry check; reads current row (implicit `draft` when
  missing); applies the matrix; same-state -> returns current row, no write; legal flip
  -> upsert + structlog INFO line with `strategy_id, version, from, to, changed_by, note`
  (§3.12); entering `testing` is an ordinary legal flip — no slot constraint (REV3: the
  unique-violation -> `TestingSlotOccupiedError` path and its class are REMOVED).
- `async list_visible(audience: Literal["trader","admin"]) -> tuple[StrategyApproval, ...]`
  — `trader`: rows WHERE `state='approved'` only; `admin`: all rows (explicit rows only —
  implicit-draft strategies are surfaced by iterating registry names through `state()`,
  which admin UIs must do; see Correct #4). Audience Literal is exact — the roles are
  `trader` and `admin` (REV1 vocabulary); `"user"`/`"root"`/unknown -> ValidationError.
- `async seed_legacy_approved(entries: Iterable[tuple[str,str]], *, changed_by: str) -> int`
  — one-time migration helper: `INSERT ... state='approved' ... ON CONFLICT DO NOTHING`,
  returns rows inserted; idempotent re-run never clobbers a later admin flip.

Errors (typed, all but one subclass `ApprovalStoreError` so callers catch one):
`ApprovalStoreError` (base: unwired/DB failure) · `UnknownStrategyApprovalError` ·
`ApprovalTransitionError` (illegal matrix move; carries `from`/`to`).
(~~`TestingSlotOccupiedError`~~ REMOVED by REV3 — there is no slot to occupy.)

## Runner gate — additive, default OFF

`StrategyRunner.__init__(..., approvals: ApprovalGate | None = None)` where `ApprovalGate`
is an in-module `Protocol` (`async def state(strategy_id, version) -> str`) — the store
satisfies it structurally; tests inject fakes.

Gate placement in `run()` (runner.py order: validate -> **approval** -> lifecycle ->
capability -> ... -> shadow last):

1. `_validate(...)` unchanged (pure input gates first) + rejects unknown `audience`
   values (typed `ValueError`, never a permissive default).
2. **NEW:** `run()` gains `audience: Literal["admin","trader"] = "trader"` (REV1 —
   default `trader` = fail-closed §3.3: a caller that forgets to authorize gets the
   strictest behavior). Resolve `sid/ver` from the parameter registry (available
   pre-I/O), `await approvals.state(sid, ver)`, apply the runnability matrix below with
   that audience. `ApprovalStoreError` -> log + `return None` (**fail-closed §3.3**: a
   store we cannot read is a store that says NO; `UNKNOWN -> REJECT`).
3. lifecycle -> capability -> params -> evaluate -> contract check -> `apply_shadow`
   unchanged (shadow allowlist stays the last prod gate for APPROVED strategies).

Runnability = **state x environment x authorization** (REV2 as amended by the human
LGTM 2026-10-03; `live` never reaches the runner):

| state | paper + admin | paper + trader | prod (any audience) |
|---|---|---|---|
| draft | BLOCK (not fully built) | BLOCK | BLOCK |
| testing | **RUN** (the refinement test) | BLOCK | BLOCK |
| approved | RUN | RUN | RUN (then shadow-per-allowlist, unchanged) |
| rejected | **RUN** (admin retest/review) | BLOCK | BLOCK |
| discontinued | **RUN** (admin review, e.g. pre-restore) | BLOCK | BLOCK |

- REV2 (human LGTM): admin may paper-test `testing`, `approved`, `rejected` AND
  `discontinued` — every state except `draft`. **`draft` runs for NOBODY, ever,
  anywhere** (not fully built).
- `testing` is refinement: it never runs in prod, never in a trader context — with any
  number of strategies in `testing` (REV3), THIS confinement is the entire control.
- `approved` is the only state any audience may run in prod; prod additionally passes
  the existing shadow allowlist (unchanged).
- Trader contexts run `approved` only — in paper AND prod.
- Authorization honesty: the runner receives `audience` from its caller — mapping a
  principal to a role (authn/authz) is the API layer's duty (M10.2 follow-up). This
  gate makes the state+env+role decision fail-closed given the audience it is told;
  verification scripts and admin testing paths pass `audience="admin"`, trader-facing
  surfaces pass nothing (= `trader`).

`approvals=None` (default): gate absent, byte-identical legacy behavior — the 5 existing
`StrategyRunner(` construction sites (2 verify scripts, 3 test files) keep working
untouched; production wiring = follow-up slice together with the seed.

No caching: fresh PK read per run (a revocation takes effect on the very next run; a
cached state could let a revoked strategy run — cache = fail-open). Budget: single
indexed SELECT, advisory <10ms (§4.1 risk-hop class); measured in verify, not gated.

## Visibility — role-dependent (REV1, human 2026-10-03)

```text
              STRATEGY
                 │
       ┌─────────┴─────────┐
       │                   │
   VISIBILITY          RUNNABILITY
       │                   │
  Role-dependent      State + environment
 Admin → all states      + authorization
  Trader → approved   (see Runner gate)
```

| state | Admin | Trader / ordinary user |
|---|---|---|
| draft | **visible** (not testable — not fully built) | hidden |
| testing | **visible (and testable — refinement)** | hidden |
| approved | **visible / usable** | **visible / usable** |
| rejected | **visible (and testable in paper)** | hidden |
| discontinued | **visible (and testable in paper)** | hidden |

Laws:
- **Approved = trader-visible. Not approved ≠ invisible to administrators.** The earlier
  gloss "visibility = approved only, for every user" is WITHDRAWN (REV1) — it would make
  the admin blind to the very lifecycle they manage.
- A future trader-facing `GET /strategies` MUST filter through `list_visible('trader')`;
  admin surfaces MUST show every strategy, iterating `registry.names() x state()` so an
  implicit (no-row) strategy displays as `draft` (locked here, wired at M10.2).
- Visibility and runnability are separate layers: `draft` is admin-visible but runnable
  by NOBODY (not fully built); `testing` (refinement), `rejected` and `discontinued`
  are trader-invisible AND trader-unrunnable, but admin-visible AND admin-runnable in
  paper; `approved` is visible and runnable by both roles.

## Edges (one test each, named after the edge)

State reads:
- no row -> `state()` == `draft`; `get()` == None
- row exists -> round-trip exact (all 6 columns)
- DB failure on read -> `ApprovalStoreError` (never a default state)
- store unwired (conn=None) -> `ApprovalStoreError`

Transitions (matrix-driven):
- each of the 25 (from, to) pairs asserted: legal -> new state + `changed_by` recorded +
  `changed_at` strictly increased; illegal -> `ApprovalTransitionError` + row unchanged
  (pre/post read equal)
- same-state set twice -> idempotent: one row, `changed_at` unchanged, no error
- `discontinued -> approved` -> legal (human law 2026-10-03, explicit named test)
- `draft -> approved` -> `ApprovalTransitionError` (dry-run-first)
- `rejected -> approved` -> `ApprovalTransitionError` (must retest)
- second strategy enters `testing` while another already holds it -> ALLOWED (REV3):
  both rows persist; the first row is unchanged by the second's entry
- version bump 1.0 -> 2.1: new key has no row -> `draft` -> trader-hidden + blocked in
  every env (admin sees it as draft); old key's row untouched
- concurrent double-`testing` (two `set_state` in `asyncio.gather`) -> BOTH commit
  (REV3), independent rows, no torn writes

Writes & validation:
- unknown `strategy_id` on `set_state`/seed -> `UnknownStrategyApprovalError`, no SQL
- `changed_by=""` -> ValidationError before write
- `note` 201 chars -> ValidationError before write
- `new_state="approved "` / `"APPROVED"` / `"unknown"` -> ValidationError (Literal is
  exact; no case folding, no trimming)
- seed run twice -> second run inserts 0 (ON CONFLICT DO NOTHING), never downgrades an
  admin's interim flip
- write failure mid-`set_state` (injected execution error) -> `ApprovalStoreError`,
  row unchanged (single-statement claim verified)
- non-UTC `changed_at` impossible for callers: system-stamped; caller-supplied stamp on
  incoming contract ignored (M1.5 law)

Runner gate:
- each of the 20 (state x env x audience) runnability cells -> run or None exactly as
  specified (incl. `testing+paper+admin` RUN vs `testing+paper+trader` BLOCK; REV2:
  `rejected+paper+admin` RUN, `discontinued+paper+admin` RUN, `draft+paper+admin` BLOCK)
- default audience: `run()` called without `audience` -> trader -> `testing+paper`
  BLOCKED (fail-closed default proven by test)
- unknown audience `run(audience="root")` -> `ValueError` in `_validate`
- gate raises `ApprovalStoreError` -> `run()` returns None (fail-closed), engine never
  called (`engine.requests == []` — blocked BEFORE I/O, same test idiom as capability)
- `approvals=None` -> legacy behavior (a paper run on a `discontinued` fake state still
  succeeds because the gate is absent — proves default-off)
- gate fires before lifecycle: fake approvals blocks + lifecycle enabled -> None, log path
  proven by return value
- approved+prod still reaches `apply_shadow` (gate does not replace the allowlist)

## Adversarial (beyond the edge list)

- SQL/registry injection: `strategy_id = "x'; DROP TABLE strategy_approvals; --"`,
  `version = "' OR '1'='1"` -> rejected `UnknownStrategyApprovalError` (or parameterized
  no-op for reads); table intact, no foreign row returned.
- `state`/audience fuzzing: `"approved;--"`, `None`, `1` -> ValidationError/TypeError at
  the contract boundary, never enters SQL; `list_visible(audience="user")` / `("root")`
  -> rejected (exact Literal: the only roles are `trader` and `admin`, REV1).
- Concurrent writers (2 connections, interleaved `set_state`) -> last committed write
  wins per row (§3.6), never a torn/duplicated row; multiple `testing` rows may coexist
  (REV3).

## Correct (definition of done for behavior)

1. Transition matrix is the single source of truth: tests enumerate all 25 pairs —
   no pair is untested, no legal move is missing, no illegal move is allowed.
2. Runnability = the state x environment x audience table exactly; visibility = the
   role table (state x admin/trader) exactly.
   Runner gate and `list_visible` agree by construction (both read `state()`).
3. Multi-testing (REV3): the store never claims success it cannot prove — single-
   statement upsert + read-back of the persisted row; the former unique-index /
   `TestingSlotOccupiedError` path is removed with the slot law.
4. Fail-closed everywhere it matters: missing row -> draft; unreadable store -> no run;
   unwired store -> typed error; unknown strategy -> rejected before SQL.
5. Version is part of identity: approvals never leak across a version bump.
6. All timestamps UTC and system-stamped; `changed_at` strictly increasing per store
   instance (monotonic clamp); caller cannot forge or backdate.
7. Structlog INFO on every successful flip (from, to, changed_by, note) — transitions
   reconstructable without a history table (§3.12); history table = follow-up.
8. Hand-calc: n/a (no money in this sub-module).

## Frozen path law (market-data = GLOBAL — never invent `user_id` in path)

```text
{lake_root}/market-data/provider={provider}/instrument={instrument_id}/date={YYYY-MM-DD}/data_type=ticks/ticks.parquet
{lake_root}/market-data/provider={provider}/instrument={instrument_id}/date={YYYY-MM-DD}/data_type=candles/interval={interval}/candles.parquet
```

- **`provider`** = `md.provider or md.broker` (same rule as M2.6).
- **`instrument_id`** = canonical (`FX.EURUSD`, `COMMODITY.XAUUSD`) — **required**, non-empty.
- **`date`** = `md.exchange_timestamp.date()` UTC calendar date — **required** (fail loud if `exchange_timestamp is None`).
- **`user_id` is NEVER a path segment** for market-data — even if `md.user_id` is set (global shared copy; M1.4 / bible §9).
- `lake_root` injectable (default `data/lake`); tests use `tmp_path`.
- Path segment rules (frozen interpretation): any segment that equals `.` or `..`, **or** contains `/`, `\`, or `=` → `ValueError`. (Stricter than “only exact `..` component”; freeze keeps rejection of any substring `..` plus separators/`=`.)

**Private lake is OUT of M2.8:** `private/broker=…/user_id=…` (signals/orders/ledger) stays M5/M6/M7.

## Partition identity (frozen — catalog upsert key)

```text
partition_key = (provider, instrument_id, date, data_type, interval)
interval = None for ticks; canonical Candle.interval string for candles (no conversion)
```

- Catalog upsert **MUST** replace the existing entry having the **same `partition_key`**.
- Identity is the five logical fields — **not** merely `relative_path` (path is derived from key; key is authoritative for upsert).
- Day-1: durable JSONL may be rewritten/compacted on upsert; after successful upsert there is **exactly one logical catalog entry per `partition_key`** (physical file may have only that one line for the key — no hidden historical duplicates for same key).

## Inputs

- `write_batch(mds: Sequence[MarketData])` — non-empty after filtering? **empty sequence → no-op `[]`**
- Each `md` must have: `instrument_id`, `exchange_timestamp`, `broker`, `watermark >= 1`, finite prices in payload (MarketData contract already enforces most; partitioner re-checks path-critical fields only)
- `kind`: `"tick"|"quote"|"trade"` → ticks file; `"candle"` → candles file (needs `Candle.interval` as **canonical upstream string — no normalize/convert**, e.g. do not map `60m`→`1h`); **`kind="order_book"` MUST raise `ValueError`** — never silently skip (M2.5 deferred).

## Atomicity (frozen wording)

- **Parquet file:** atomic replacement only — write temp then `os.replace` onto final `.parquet`. No half-written final file on failure.
- **Catalog:** separate step **after** successful replace. **M2.8 does NOT provide cross-file transactional atomicity between parquet and catalog.** A successful parquet replace followed by catalog failure may leave parquet updated while catalog remains previous state. Day-1: atomic parquet replacement, **not** a two-phase parquet+catalog transaction.
- **Batch:** `write_batch()` is **not transactional across partitions**. Each partition independently atomic; failure of one partition **MUST NOT** roll back previously committed partitions.

## Outputs

1. **`partition_path(md) -> Path`** (relative under `lake_root`) — exact formula above.
2. **`write_batch` → `list[CatalogEntry]`** — one entry per partition written (may be >1 if batch spans dates/instruments).
3. **`CatalogEntry`** frozen (`extra="forbid"`), in-module only (no `shared/contracts` bump until M8/M9 consume):

| Field | Type | Rule |
|-------|------|------|
| `provider` | `str` | path provider |
| `instrument_id` | `str` | path instrument |
| `date` | `str` | `YYYY-MM-DD` |
| `data_type` | `"ticks" \| "candles"` | |
| `interval` | `str \| None` | candles only — **canonical `Candle.interval` as-is, no conversion**; ticks → `None` |
| `relative_path` | `str` | POSIX relative path under `lake_root` |
| `rowcount` | `int` | **== parquet row count** (P14 gate) |
| `watermark_min` / `watermark_max` | `int` | min/max of rows in file |
| `source_sequence_min` / `source_sequence_max` | `int \| None` | min/max of **non-None** `source_sequence`; all-None → both `None` |
| `reference_snapshot_id` | `str \| None` | unique non-None value; **>1 distinct → `ValueError`** (fail loud mixed lineage) |
| `checksum` | `str` | `sha256` hex of deterministic row digests (see Correct) |
| `schema_version` | `str` | **all rows in partition must have exactly the same `MarketData.version` string**; mixed → `ValueError`; `CatalogEntry.schema_version` equals that exact value |

4. **`read_partition(...)` → `list[MarketData]`** round-trip equal to written rows (identity by full model dump for verify).

**`read_partition` signature (frozen):**

```text
read_partition(lake_root, provider, instrument_id, date: str | date, data_type, interval: str | None = None) -> list[MarketData]
```

- Explicit named-partition read: missing file → **`FileNotFoundError`** (not silent `[]`).
- Only `write_batch` creates directories.

## Checksum (frozen)

- **`rows_in_write_order`:** the exact ordered sequence of `MarketData` rows used to construct the parquet table for that partition. M2.8 **MUST NOT** sort, deduplicate, or reorder rows solely (or at all) for checksum generation — input order into the write is write order.
- **Write-time checksum:** `sha256` hex of `"\n".join(md.model_dump_json() for md in rows_in_write_order)`.
- **P14 recompute MUST reconstruct `MarketData` from the parquet file** and apply the **same** `model_dump_json()` algorithm and **same row ordering** used at write; only then compare to `catalog.checksum`.
- Verification invariant:

```text
CatalogEntry.rowcount == number of MarketData rows read from parquet
CatalogEntry.checksum  == sha256("\n".join(md.model_dump_json() for md in rows_from_parquet_in_write_order))
```

## Correct

1. Path **exactly** matches frozen formula (golden string asserts).
2. Batch with two dates / two instruments → **two** files + **two** catalog upserts; no cross-contamination of `rowcount`.
3. **Atomic parquet only:** simulated write failure mid-batch → no half-written final `.parquet` (only `.tmp` cleaned); catalog **not** updated for failed partition; earlier successful partitions may remain (**not** cross-partition 2PC — see Atomicity section).
4. **P14 gate:** `catalog.rowcount == len(read_partition)` and checksum **recomputed from file (same `model_dump_json` + write order) == catalog.checksum**.
5. Catalog **upsert** by **`partition_key`** (not path-only, not append-duplicate): rewrite same partition twice → **exactly one** logical entry per key (last write wins); physical JSONL must not retain a second line for the same key after successful upsert.
6. `write_batch([])` → `[]`, no dirs created.
7. `user_id="42"` on input must **not** appear in path.
8. Async: writer methods are `async def`; path building is sync pure.
9. Checksum = sha256 over `"\n".join(md.model_dump_json() for md in rows_in_write_order)` — **stable, no `float` re-rounding**; order = write order (no sort for checksum).

## Edges

- `md.instrument_id is None` or `""` → `ValueError`
- `md.exchange_timestamp is None` → `ValueError` (no fallback clock)
- `md.provider` empty string → use `md.broker`; both empty → `ValueError`
- Path segment contains `=` or `/` or `\` or `..` → `ValueError`
- Mixed `reference_snapshot_id` in one partition write → `ValueError`
- Mixed `version` in one partition write → `ValueError`
- `kind="order_book"` → `ValueError` Day-1 (M2.5 deferred)
- `kind="candle"` missing/malformed `Candle.interval` → `ValueError`
- `lake_root` missing → writer **creates parents** before replace
- Read path that does not exist → empty list or typed `FileNotFoundError` — **pick `FileNotFoundError`, no silent `[]`** for explicit read of a named partition; `write_batch` create is the only mkdir path

## Adversarial

- `instrument_id="../../etc"` or `"FX=EURUSD"` → `ValueError`, no file outside `lake_root`
- `watermark` non-int / `0` → `ValueError` before I/O
- Batch of 1000 rows same partition → one atomic file, `rowcount=1000`
- Concurrent `write_batch` same partition Day-1: **last writer wins** (no file lock) — noted, not tested as multi-process

# Spec: M2.2 Normalization — InternalTick → canonical MarketData

Purpose: Translate one accepted `InternalTick` into frozen canonical `MarketData` — broker-native symbol → namespaced `instrument_id`, stamp `reference_snapshot_id`, allocate scoped `watermark`, round canonical price to instrument `tick_size`.
Bible ref: System_Development_Manual/modules/02_M2_Data.md §4.
Connects: `M2.1 → M2.2 → M2.3`. Consumes M2b facade **synchronously** (no await in hot path).
Review status: REV1 changes applied 2026-09-22 (human CHANGES REQUIRED → all points addressed).

## Inputs
- `tick: InternalTick` — accepted M2.1 output (aware UTC `timestamp`, Decimal prices, native `symbol`).
- `broker: str` — provider id from `tick.provider` (`deriv | mt5 | headway`).
- Dependencies (injected, sync — **no unused deps**):
  - `reference.to_canonical(native, broker) -> str`
  - `reference.exists(instrument_id, broker) -> bool`
  - `reference.get_instrument(instrument_id) -> dict`
  - `reference.current_snapshot_id() -> str` (exactly once per successful attempt)
  - `watermark_registry.next(instrument_id, broker) -> int`
- **No `clock` dependency** — M2.2 does not call `clock.now()`; future-epoch validation is M2.3's boundary.

## Outputs
- Exactly one frozen `MarketData` **OR** exactly one `Drop` — **all-or-drop, never partial**.
- On success:
  - `instrument_id` — **canonical namespaced ID from M2b** (not display symbol):
    - `frxEURUSD` → `FX.EURUSD`
    - `frxXAUUSD` → `COMMODITY.XAUUSD`
    - `cryBTCUSD` → **`CRYPTO.BTCUSD`** (namespace required; bare `BTCUSD` is only `canonical_symbol`)
  - `symbol` — `canonical_symbol` from instrument master (`EURUSD`, `XAUUSD`, `BTCUSD`)
  - `provider_symbol=tick.symbol` — exact original native, **never mutated**
  - `broker=tick.provider`, `provider=tick.provider`
  - `kind="tick"`, `payload=Tick(price, bid, ask, spread)`
  - `quality`: InternalTick `ok→pristine`, `gapped→gapped` (M2.3 remains authoritative gate)
  - `watermark` — see definition below
  - `exchange_timestamp=tick.timestamp`, `received_at=tick.observed_at` (M2.1 capture)
  - `reference_snapshot_id` — one snapshot ID captured during this attempt, stamped unchanged
  - `source_sequence=tick.source_sequence` (may be `None`), `source_event_id=tick.source_event_id`
  - `schema_version="canonical_quote_v1"`, `user_id=None` (global market-data — no tenant)

## Watermark semantics (unambiguous)
> `watermark` is a **process-wide / global market-data sequence counter scoped independently by `(instrument_id, broker)`**. It is **not** per-user, per-tenant, and **not** the provider `source_sequence`.

Independent counters (each starts at **1**, +1 per successful normalize):

| Key | Sequence |
|-----|----------|
| `FX.EURUSD` + `deriv` | 1, 2, 3, … |
| `FX.EURUSD` + `mt5`  | 1, 2, 3, … |
| `COMMODITY.XAUUSD` + `deriv` | 1, 2, 3, … |

**Allocation timing (blocking invariant):** `watermark_registry.next()` **MUST** be called only after **all** M2.2 rejection conditions have passed and immediately before successful `MarketData` construction. A rejected tick must **never** consume a watermark (no gap from failed attempts).

## Processing order (mandatory)
1. Validate `tick.timestamp` is timezone-aware → else `Drop(invalid_timestamp)`
2. Resolve canonical identity: `to_canonical(tick.symbol, broker)` (catch typed reference errors → `Drop`)
3. Verify `exists(canonical_result, broker)` (broker-specific mapping check, not master-membership only) → else `Drop(unknown_symbol)`
4. Load `get_instrument(canonical_result)` (catch `UnknownInstrumentError` → `Drop(unknown_symbol)`)
5. Validate `current_snapshot_id()` non-empty → else `Drop(missing_field)`; call **exactly once**, stamp returned value unchanged
6. Calculate price (quote or Decimal mid; round once — see rule)
7. **Allocate watermark only now** — `watermark_registry.next(instrument_id, broker)`
8. Construct and return frozen `MarketData`

## Identity / unresolved-native contract
- M2.2 accepts a canonical result **only when `exists(canonical_result, broker)` is true**.
- **Frozen broker-specific `exists` semantics (M2b.1 contract):** `exists(instrument_id, broker)` MUST verify that the canonical instrument has an explicitly mapped native symbol for the specified broker. It MUST return False when the instrument exists in the master but has no mapping for that broker (e.g. `exists("FX.GBPUSD", "headway")` is False; `exists("FX.EURUSD", broker=None)` is True regardless of broker).
- A passthrough native value that does not resolve to a broker mapping **must always produce `Drop(unknown_symbol)`**.
- M2b deliberately returns unknown natives unchanged; M2.2 does **not** infer success from string shape alone — `exists(..., broker)` is the acceptance gate.
- Adversarial: unknown native that **resembles a canonical ID** (e.g. `CRYPTO.FAKE`, `FX.EURUSD` sent as a native with a broker that has no such mapping edge, or a string equal to some other instrument's id but not mapped for this broker) → still `exists` check decides; if `exists(result, broker)` is False → `Drop(unknown_symbol)`.

## Price rounding rule (arbitrary tick multiples — Option B)
Support **any positive `tick_size`**, including non-powers-of-ten (e.g. `0.25`):

```text
rounded = (price / tick_size).quantize(Decimal("1"), ROUND_HALF_UP) * tick_size
```

- `price` source: `tick.quote` if present, else Decimal midpoint `(bid + ask) / 2`.
- Round **exactly once**, after choosing quote/mid — never per-input then again.
- All arithmetic in `Decimal`; no `float` until frozen `Tick` boundary.
- `tick_size` must be a positive Decimal (from instrument master YAML); non-positive → `Drop(missing_field)` (master invalid — fail safe).

### Hand-checkable examples (Decimal exact, HALF_UP)
| Input price | tick_size | Result | Note |
|-------------|-----------|--------|------|
| quote `1.08540` | `0.00001` | `1.08540` | already on tick |
| mid of `1.08538`/`1.08542` | `0.00001` | `1.08540` | mid lands on tick |
| quote `1.085405` | `0.00001` | `1.08541` | HALF_UP, not banker's |
| quote `64248.0` | `0.01` | `64248.00` | crypto |
| quote `2380.3` | `0.01` | `2380.30` | commodity |
| price `10.10` | `0.25` | `10.00` | **arbitrary tick: 10.10/0.25=40.4 → 40 → 10.00** |
| price `10.40` | `0.25` | `10.50` | 10.40/0.25=41.6 → 42 → 10.50 |

## bid / ask / spread (explicit — only `price` is rounded)
- **Only `payload.price` is rounded** to tick_size (canonical display/mid price).
- `payload.bid` = original `tick.bid` **unrounded** (Decimal → float at contract boundary).
- `payload.ask` = original `tick.ask` **unrounded**.
- `payload.spread` = `Decimal(ask) - Decimal(bid)` computed in Decimal, **then** converted to float — no float intermediate in the subtract path. Spread is **raw ask − raw bid** (not rounded components).
- Rationale: M2.2 does not invent or reshape broker prices; M2.3 is the quality bouncer for inverted/spread anomalies.

## Edges
- Mapped forex → `instrument_id=FX.EURUSD`, `symbol=EURUSD`.
- Mapped commodity → `COMMODITY.XAUUSD`, `symbol=XAUUSD`.
- Mapped crypto → **`instrument_id=CRYPTO.BTCUSD`**, `symbol=BTCUSD`.
- Unresolved native (`exists` False) → `Drop(unknown_symbol)`.
- `InternalTick.quality=="gapped"` → `quality=gapped`.
- `quote is None` → mid `(bid+ask)/2` then round once.
- `pip_size` absent → irrelevant; rounding uses YAML/master `tick_size`.
- `bid > ask` (inverted) → still emitted (M2.3 rejects inverted; out of M2.2 scope).
- Naive `tick.timestamp` → `Drop(invalid_timestamp)`.
- Empty/`None` snapshot id → `Drop(missing_field)` (lineage mandatory — not nullable).
- Watermark unseen key → 1; same key again → 2; other `(instrument, broker)` → independent.

## Purity / side effects (precise wording)
- M2.2 is **synchronous and deterministic except for the intentional monotonic watermark allocation side effect** — not a mathematically pure function.
- **For unchanged reference/master/snapshot state, repeated normalization produces identical output fields except `watermark`.**
- **Caller owns exactly-once invocation of `normalize()` for each accepted `InternalTick`.** M2.2 does **not** deduplicate repeated calls and must **not** add hidden caching to "fix" double-invocation; a second call consumes a second watermark by design.

## All-or-drop invariant
> M2.2 has an **all-or-drop output contract**. No `MarketData` instance may be emitted if any mandatory M2.2 identity, lineage, timestamp, or reference requirement fails.

## Correct
- Canonical mapping via M2b YAML only — no `if symbol=="frxEURUSD"` in M2.2.
- `instrument_id` (namespaced) ≠ `symbol` (`canonical_symbol`) ≠ `provider_symbol` (native) — three distinct fields, never conflated.
- `current_snapshot_id()` called **exactly once** per normalization attempt that reaches lineage resolution; returned value stamped unchanged (no second call around snapshot rotation).
- Watermark never consumed on a path that returns `Drop`.

## Adversarial (not in edges above)
- `symbol="'; DROP TABLE ticks;--"` → `Drop(unknown_symbol)`, never executes / never matches master.
- Unknown native resembling canonical id (e.g. `CRYPTO.NOTREAL`, `FX.EURUSD` with inconsistent mapping) → `exists(..., broker)` gate → `Drop(unknown_symbol)`.
- `to_canonical` raises `UnknownBrokerError` (corrupt provider) → `Drop(missing_field)` with detail, never uncaught crash.
- `get_instrument` raises `UnknownInstrumentError` → `Drop(unknown_symbol)`.
- Rejection **before** step 7 → **watermark counter unchanged** (assert registry state).
- Double `normalize()` on same tick → two watermarks; all other fields equal.
- `tick_size=0` or negative in master → `Drop(missing_field)`, no ZeroDivision / no silent pass-through.

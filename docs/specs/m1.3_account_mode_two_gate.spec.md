# Spec: M1.3 Account Mode + Auto-Trade — 2-Gate (Day-1)

Purpose: Two independent process-wide gates — **GATE 1 `MODE` (`demo`|`live`)** selects which ledger/credentials; **GATE 2 `AUTO` (`OFF`|`ON`)** whether the bot may call M6. Fresh process → **`DEMO + AUTO OFF`** (fail-closed). **`LIVE + OFF` = armed but paused** — professional default, never `LIVE` alone means trading.

## Contracts

### GATE 1 — ACCOUNT MODE
- Values: `demo` | `live`. Default **`demo`**.
- Perm: **`account.switch`** — `trader` | `admin` (`admin` via `*`). Viewer / missing / empty / unknown role → **403** on POST.
- Arm (A2): `live_armed == any(b.live.enabled for b in accounts.brokers)` — evaluated **at response / set time**, independent of current mode.

### GATE 2 — AUTO-TRADE
- Values: `OFF` | `ON` (case-insensitive input normalized). Default **`OFF`**.
- Perm: **`trading.enable`** — `trader` | `admin`. Same deny matrix as Gate 1 on POST.
- AUTO ON at **DEMO** → allowed (A3) — paper path only.
- AUTO ON at **LIVE** → requires **`live_armed`** else **409** `LiveNotArmedError` (cannot enable auto when live not armed).
- Switching MODE **never** writes AUTO; switching AUTO **never** writes MODE.

### GATE 3 — KILL SWITCH (reference only)
- Owned by M5.5 (`POST /risk/kill_switch`). M1.3 does **not** implement.
- Full Day-2+ bot predicate (documented, not implemented Day-1):

```text
can_place_order = (mode == "live" && auto == "ON" && !kill_active && risk_ok)
```

- Day-1 exposure (what this API returns):

```text
bot_will_trade = (mode == "live" && auto == "ON")
# LIVE+ON without M5/M6 checks is NOT sufficient to place — M5/M6 still gate
```

### Response JSON (GET — no `account.switch` / no `trading.enable` required)

```json
{
  "mode": "demo",
  "auto": "OFF",
  "source": "default",
  "auto_source": "default",
  "live_armed": false,
  "bot_will_trade": false
}
```

| Field | Meaning |
|-------|---------|
| `mode` | `demo`\|`live` |
| `auto` | `OFF`\|`ON` |
| `source` | Mode provenance: `default`\|`env`\|`api` |
| `auto_source` | Auto provenance: `default`\|`api` (no env seed Day-1 unless later added) |
| `live_armed` | Hard gate satisfied **now** (not “is live”) |
| `bot_will_trade` | `mode==live && auto==ON` |

### `source` / `auto_source` transitions

```text
Boot, ACCOUNT_MODE unset / invalid / empty   → mode=demo  source=default
Boot, ACCOUNT_MODE=demo                      → mode=demo  source=env
Boot, ACCOUNT_MODE=live + armed              → mode=live  source=env
Boot, ACCOUNT_MODE=live + NOT armed          → mode=demo  source=default   # env seed ignored, no crash
POST /mode  any valid mode (incl. same)      → source=api  (after arm check + role)
POST /mode  live + NOT armed                 → no state change + 409
POST /auto-trade  successful                 → auto=requested  auto_source=api
POST /auto-trade  invalid body               → 422, no state change
POST /auto-trade  ON + live + NOT armed      → 409, no state change
```

**Idempotent POST demo when already demo** → still **`source=api`** (successful API write). Same for AUTO ON→ON → **`auto_source=api`**.

### Boot `ACCOUNT_MODE` (fail-safe)

```text
ACCOUNT_MODE value (normalized lower, strip)
  in {demo, live} → apply decision tree above
  else (invalid/empty/unknown) → treat as unset: mode=demo, source=default
```

Never bypass live-arm gate via env. Never raise on invalid boot enum (deterministic fall-back, test #12).

### Permissions matrix

| Endpoint | Method | Required | Deny → |
|----------|--------|----------|--------|
| `GET .../status` (or `.../mode`) | GET | none (read-only) | — |
| `POST .../mode` | POST | `account.switch` | missing/empty/unknown/viewer → **403** |
| `POST .../auto-trade` | POST | `trading.enable` | same → **403** |

`X-Role` header Day-1; default when **missing header on POST** must be **explicit deny 403** (do not silently default to trader). Prefer `Header(default="")` + treat `""` as unknown → 403.

### Errors (typed — not bare `ValueError` as public contract)

Reuse `shared/core/exceptions.py` `BaseAppError` pattern; **`error_code=ErrorCode.config_error`** (no new ErrorCode members — no contract bump).

| Exception | HTTP |
|-----------|------|
| `InvalidAccountModeError` | 422 |
| `InvalidAutoTradeError` | 422 |
| `LiveNotArmedError` | 409 |
| role deny (permission) | 403 |

API maps by exception type. Service callers catch typed classes.

### Concurrency (critical section)

Single `threading.Lock` (or RLock) covers:

```text
lock:
  validate requested field
  arm check if required
  update that gate field
  update that gate source
unlock
```

`snapshot()` / GET reads **`mode, auto, source, auto_source, live_armed, bot_will_trade`** under the **same lock** — no torn pair (e.g. never `mode=live` + `source=default` mid-write).

Concurrent POSTs: last-write-wins per field; second idempotent POST → 200.

### JSON-only proof

1. Behavioral: `GET /` → **404**, body not HTML (`content-type` not `text/html`).
2. Structural: app has **no** `StaticFiles` / `Mount` static / `FileResponse` / `HTMLResponse` route handlers installed (assert on `app.routes` / router dependencies).

## Correct (numbered)

1. Fresh process → `mode=demo`, `auto=OFF`, `source=default`, `auto_source=default`, `bot_will_trade=false`.
2. `set_mode("demo")` idempotent → still demo; `source=api` after API call.
3. `set_mode("live")` not armed → `LiveNotArmedError` / 409; mode stays demo; auto unchanged.
4. `set_mode("live")` armed → live; bot `get` sees live without restart; auto **unchanged**.
5. Switch live→demo → demo; `source=api`.
6. `set_auto("ON")` at demo → ON; `auto_source=api`; mode unchanged.
7. `set_auto("ON")` at live + armed → ON; `bot_will_trade=true`.
8. `set_auto("ON")` at live + **not** armed → 409; auto stays OFF.
9. `set_auto("OFF")` always allowed (trader/admin).
10. MODE switch does not flip AUTO; AUTO flip does not flip MODE.
11. Viewer POST either endpoint → 403. Missing/unknown X-Role POST → 403.
12. GET requires neither switch nor enable perm.
13. Boot `ACCOUNT_MODE=live` + armed → live+env. Boot live + not armed → demo+default. Boot invalid → demo+default.
14. `live_armed` independent: `mode=demo, live_armed=true` valid.
15. No secrets in any response.

## Edges

- Concurrent POSTs → per-field last-write-wins; snapshot always consistent pair.
- Idempotent same-value POST → 200, source/auto_source become `api`.
- Invalid mode / auto string → 422, no partial write.
- AUTO ON on unarmed live → 409, mode and auto unchanged.
- Env seed never flips AUTO ON.

## Adversarial

- Viewer cannot switch either gate.
- Live without `live.enabled` cannot enter live; cannot AUTO ON while live+unarmed.
- Double-click both buttons → second POST idempotent 200, no double state machine corruption.
- Missing X-Role header cannot default to privileged.
- `ACCOUNT_MODE` env cannot arm live alone.

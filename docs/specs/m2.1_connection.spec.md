Bible: `System_Development_Manual` P08 — gate: **WS heartbeat + reconnect**; `02_M2_Data.md` §3 (`connection_manager`, `ingestion_manager`, `broker_feeds/deriv`).

## Layering (unchanged from m2.1_ingestion)

```text

ingestion_engine/connection_manager.py — per-broker singleton WS + heartbeat + reconnect
```

Connection = async I/O. `ingest()` stays pure sync — this slice never changes it.

## Scope

- In: `ConnectionManager`, `IngestionManager`, `broker_feeds/deriv/{stream,models}` minimal wiring; config keys; tests.
- Out: M2.2 fan-out/Live broadcast UI, M6 private streams, order books, `platform_token` vault integration.

## Inputs / Outputs

- **Config:** `config/brokers/deriv.yaml` gains `app_id: str` (platform app id for public feed — **not** a per-user vault token). `ws_url` already present.
- **API (async):**
  - `ConnectionManager.get_or_create(broker) -> ConnectionHandle` — singleton pool `{broker: ws}`; never keyed by `user_id`.
  - `ConnectionManager.close(broker)` / `close_all()` — cancel heartbeat, close WS, drop from pool.
  - `IngestionManager.start(broker, symbols: list[str])` — connect, subscribe, spawn recv loop + heartbeat task.
  - `IngestionManager.stop(broker)` — graceful stop, no orphan tasks.
- **Emit:** each `msg_type=tick` frame → existing `TickIngestor.ingest(raw, ...)` → `InternalTick | Drop` handed to injected `on_tick` / `on_drop` callback (pipeline glue only; no normalize here).
- **Status:** `ConnectionHandle.state ∈ {connecting, connected, degraded, reconnecting, closed}`; `consecutive_failures: int`; `last_heartbeat_at: datetime | None`.

## Connection behavior (Correct)

1. **Singleton:** one WS per broker for market-data (public). Second `get_or_create("deriv")` returns same handle. No `vault.get(user_id, broker)`.
2. **Subscribe:** after open, send Deriv subscribe JSON for each symbol (`{"ticks": "<native>", "subscribe": 1, "app_id": ...}` per symbol or multi — builder in `broker_feeds/deriv/stream.py` only).
3. **Heartbeat:** application-level ping task every `heartbeat_interval_s` (default **20s**, config-overridable); if no inbound message (any type) for `heartbeat_timeout_s` (default **35s**), mark `degraded`, force-close WS, enter reconnect. Deriv server ping/pong at protocol level is also accepted as inbound traffic.
4. **Reconnect:** exponential backoff **base 1s → cap 30s**, full jitter (`sleep = random(0, min(cap, base * 2**attempt))`), max_attempts = ∞ while `start()` active (stop cancels). On successful reconnect: re-subscribe all symbols, reset `consecutive_failures`, state `connected`, log `ingestion.reconnected` with `broker` + attempt count.
5. **Recv loop:** `async for frame in ws` → if `msg_type == "tick"` → `TickIngestor.ingest`; `msg_type == "error"` → log + optional resubscribe (no crash); `subscription` ack → log. Malformed JSON is already a `Drop` from ingest — connection layer does not re-validate.
6. **Stop:** cancel recv + heartbeat tasks with `asyncio.CancelledError` handled; close WS; state `closed`. Idempotent (double-stop safe).
7. **Pure calc stays sync:** no `await` inside `ingest`.

## Edges

- `get_or_create` while `connecting` → same handle (no parallel connects for one broker).
- Heartbeat timeout with live socket but silent feed → reconnect (false-degraded accepted; safer than stuck).
- Server closes WS cleanly → recv loop ends → reconnect if still started.
- `start("deriv")` twice → second is no-op or raises `RuntimeError` if already running (pick one — **no-op + log**, prefer idempotent start).
- Unknown `broker` with no `config/brokers/<b>.yaml` → raise `ValueError` at start (fail loud, no silent connect).
- Missing `app_id` → raise `ValueError` at start (fail loud).
- Frame with `msg_type != "tick"` (e.g. `ping`/`pong`/`subscription`) → not passed to tick path; still counts as inbound for heartbeat freshness.
- During `reconnecting`, `start` again → no second loop (guard with state).
- `symbols=[]` → connect + heartbeat only, no subscribe messages (edge: valid empty subscription).

## Adversarial

- Fake WS that never sends → after timeout, state goes `degraded` then `reconnecting` (not hung forever).
- Fake WS raising `ConnectionError` on recv → counted in `consecutive_failures`, backoff schedule advanced.
- Hostile/corrupt frame (`"{{{"`) → `Drop(invalid_json)` from existing ingest, connection stays up.
- Task leak: after `stop()`, no live asyncio tasks referencing the manager (test cancels).

## Test plan (written before impl — Step 3)

Mock transport (`FakeWS` scripted receive/send) — no real network in unit tests:

1. Singleton: two `get_or_create("deriv")` → same handle.
2. Heartbeat timeout → state `degraded` → reconnect attempt with backoff.
3. Recv error → `consecutive_failures` increments; backoff capped at 30s.
4. Reconnect success → resubscribe message sent for each symbol; state `connected`.
5. `start` twice → no second loop.
6. Missing `app_id` / unknown broker → `ValueError`.
7. `msg_type=ping` → no `ingest` call; heartbeat still refreshed.
8. Corrupt tick frame → `Drop(invalid_json)` callback once; connection stays `connected`.
9. `stop()` → tasks cancelled; `stop()` again → safe.
10. `symbols=[]` → no ticks subscribe frames, still connected.
11. Adversarial: WS silent forever → reconnect loop still terminates on `stop()` (no hang).

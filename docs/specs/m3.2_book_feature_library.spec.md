## §2 Timeframe & Window Law (how strategy → analysis carries time)

Human requirement 2026-09-30: *strategy declares the timeframe, passes the start
time; all analysis for one evaluation uses the same timeframe.* This is already
law in the engine — this slice adds NO engine change; it pins compliance:

1. **Strategy (M4) declares both time inputs in ONE `FeatureRequest`**
   (`feature_engine.py:90-116`): `timeframe` (validated against
   `INTERVAL_MINUTES`, `None` → resolver decides, no hidden default) and
   `as_of: datetime` (tz-aware UTC, PIT boundary "when am I evaluating the
   market?"). Also `features: tuple[str, ...]` — the exact analytic names.
2. **The engine resolves ONE timeframe per request** (`_resolve_timeframe`,
   Calculation Timeframe Law) → **ONE window** derived by the Temporal Resolver
   (`resolve(requirements, as_of, timeframe) → window_start, window_end`; bible §6a,
   A65: no depth tables in callers — the strategy passes `as_of`, the resolver
   derives the start, so window derivation has exactly one source) → **ONE
   `provider.get_candles(...)` call** → the **same `candles` list** is handed to
   every requested analytic (`feature_engine.py:192-247`). All analyses for one
   slice therefore share one timeframe and one window start — mixed-timeframe
   comparison is structurally impossible.
3. **Isolation Law:** `compute(candles, params)` exactly
   (`analytics_registry.py:61-67` rejects any `provider`/`clock`/`as_of`
   parameter). An analytic never selects its own timeframe, never fetches, never
   sees `as_of`. **Window materializes the strategy's start time as the candle
   list boundary** — bar index `i = len(candles)-1` is `as_of` by construction.
4. **`minimum_history`/`warmup` are denominated in bars of the resolved
   timeframe** (`DataRequirement` docstring) → the planner widens `window_start`
   per timeframe automatically (263 bars of `1m` = 263 minutes, of `1h` = 263
   hours). **Verified DB-request math** (`shared/temporal/temporal_resolver.py:74-88`):
   `needed_bars = max(min_history + warmup)` over the closure (union — Planner
   Dependency Law), `window_end = as_of`, `window_start = as_of − needed_bars ×
   INTERVAL_MINUTES[tf]`, overflow → ValueError fail-closed. The §5
   `minimum_history` pins are therefore literally the "what data does this
   analysis need" contract — a wrong pin = wrong DB window = wrong result;
   the REQUIREMENTS pin-table test (§8) locks them.
5. **Verified strategy-side timing** (`modules/m4_alpha/strategy/runner.py:54-84,
   122-143`): `StrategyRunner.run()` takes `timeframe` and `as_of` as **mandatory**
   parameters; `_validate` rejects empty/naive/non-UTC before any engine I/O
   (`engine.requests == []` tested), `FeatureRequest`'s field validator rejects
   unknown timeframes, and the same `timeframe` is stamped onto `Signal.timeframe`
   (runner.py:107). The strategy cannot call analysis with missing or local time.
6. **Backtest/prediction correctness:** M8 replays with historical `as_of` →
   identical window derivation + `CandleProvider` PIT contract
   (`availability_time ≤ as_of`, `interval_end ≤ window_end`, wrong-series guard
   `candle.interval == resolved_tf`) → look-ahead through windowing is
   impossible. This slice's tests assert compute-level behavior only; the
   window/PIT behavior is already locked by m3.1 tests. All 10 analytics are
   **pure bar-index math** — no wall-clock, no calendar, no session logic — so
   results depend only on the candle sequence: identical values across timeframes
   given the same bars.
7. **Gates use `<=`/`<` on 0-100 ranks and 0-1 ratios exactly as the book
   writes them** (e.g. B1 `atr_percentile_rank(250) <= 30 → skip` ⇔ pass `> 30`);
   no epsilon margins are introduced anywhere.

## §4 Shared conventions (all 10 files, pinned to sibling implementations)

- Shape: `NAME`, `REQUIREMENTS = DataRequirement(needs=("price",), ...)` (no
  dependencies — all price-only, no `provides_regime`), `def compute(candles, params) -> float`.
- **Param policy** (mirrors `atr_14._period` / `bb_percent._stddev` exactly):
  `params is None` → `ValueError`; non-number → `ValueError`; non-finite /
  non-integral / out-of-bound → `ValueError` (`isfinite` BEFORE `int()` — no
  `int(inf)` crash-class); message form `"{NAME} <param> must be ... , got {raw!r}"`.
  Bounds are §3.13 startup-sane.
- **Data policy:** empty `candles` → `ValueError`; any non-finite
  high/low/close in range → `math.nan`; insufficient bars for the *effective*
  (possibly overridden) period → `math.nan` (engine maps to `invalid:<name>`
  warning, never a crash; consistent with P18 override behavior).
- **Math:** float indicators (not money — §3.1 float ban is for settlement;
  P18 precedent "Money: none (indicator floats)"). **`ddof=0` population
  everywhere** (REV4 pin; Bollinger confirms population σ). Exact `==` goldens,
  `pytest.approx(abs=1e-12)` only for irrational results (√, ln).
- Pure `def`, no I/O, no imports beyond `math` + contract types; WHY-not-WHAT
  header per §4.2.

## §5 Per-analytic definitions

### 5.1 `efficiency_ratio` — Kaufman ER

Book: `Kaufman ER = |C - C[-n]| / sum(|C[k]-C[k-1]|). Straightness of the move, 0-1.`
Correct: Kaufman *New Trading Systems and Methods* (confirmed: Chart Manual,
TC2000 `100*(C-Cx)/SUM(ABS(C-C1),x)` ×100 variant, StockSharp, Wealth-Lab —
book uses the 0..1 form, gates ER 0.25/0.3/0.4).
- Params: `period` default 20.0, integral `>= 2`. `REQUIREMENTS.minimum_history=21`, warmup 0.
- Compute: `net = |c[-1] - c[-1-p]|`; `path = Σ_{t=N-p..N-1} |c[t]-c[t-1]|`;
  `path == 0 → 0.0` (no movement = no efficiency — gate `>0.25`/`>0.3` fails safe);
  else `net/path`. Output ∈ [0,1] (triangle inequality invariant; asserted).
- **Edges:** `len < p+1` → NaN; `period=1` → ValueError; flat closes → 0.0;
  non-finite close → NaN; one-way series → exactly 1.0; `period=1e9` → NaN.
- **Hand calc:** closes `[100,101,103,102,105]` p=4: net `|105-100|=5`,
  path `1+2+1+3=7` → `5/7 = 0.7142857142857143`.
- Adversarial: `period=1e9` → NaN (no crash, no partial window reuse).

### 5.2 `atr_percentile_rank` — ATR percentile rank (book gap-fill, §6 D3)

Book (usages only): B1 `atr_percentile_rank(bars, i, 250) <= 30 → skip`;
B3 `<= 40`; D1 `<= 50`.
Correct: **percentile rank of the current ATR over the last `window` ATR values,
TradingView `ta.percentrank` semantics — `100 * #{v <= cur} / window`, current
value included in the window, `na` anywhere → `na`** (Pine reference: "percentage
of values in the lookback window that are less than or equal to the current
source value"). ATR series = the pinned `atr_14` convention (TV `ta.tr(true)`:
`TR_0 = h0-l0`, then `max(h-l, |h-pc|, |l-pc|)`; Wilder α=1/p, seed = SMA of
first p TRs) computed over the provided candles — windowed semantics identical
to `atr_14` (re-seed at window start; declared: the rank is a property of the
provided window, as every analytic here is).
- Params: `period` default 14.0 integral `>= 1`; `window` default 250.0 integral `>= 2`.
- `minimum_history = window + period - 1` = **263** (derivation: ATR count =
  `N - p + 1` since TR exists at bar 0 → need `N-p+1 >= window`).
- **Edges:** `N < window+period-1` → NaN; `window=1` → ValueError;
  `period=0` → ValueError; constant TRs → **100.0** (TV-compatible: all ≤ equal —
  documented trap: B1 pairs this gate with `ER > 0.25`, so flat-vol+flat-price
  fails overall; declared in §6 D4); non-finite → NaN; empty → ValueError;
  `params=None` → ValueError.
- **Hand calc (fixture, exact):** highs `[10,16,24,27,33,34,36]`,
  lows `[0,5,10,15,20,25,28]`, closes `[5,10.5,17,21,26.5,29.5,32]` (each bar
  contains the prior close → `TR = h-l`), p=4 → TRs `[10,11,14,12,13,9,8]` →
  Wilder ATRs `[11.75, 12.0625, 11.296875, 10.47265625]`, window=4, cur
  `10.47265625` → `#{v<=cur} = 1` → **25.0**.
- Adversarial: `window=1e6` → NaN (no alloc/crash).

### 5.3 `ols_r_squared` — OLS R² of close on bar index

Book: `R-squared of an OLS regression of Close on bar index over the last n bars.`
Correct: simple OLS `y=close, x=0..p-1`; `R² = Sxy²/(Sxx·Syy)` (textbook; equals
Pearson r² for simple regression). Gate usage A1: `ols_r2(bars,i,50) > 0.6`.
- Params: `period` default 50.0, integral `>= 3`. `minimum_history=50`.
- Compute: full-precision sums; **`Syy == 0` (flat) → 0.0** (R² undefined;
  gate-safe: flat prices carry no trend ⇒ `>0.6` must fail — §3.3 safer
  assumption; declared §6 D5); `Sxx == 0` impossible for p≥3 distinct x —
  defensive `0.0`; clamp to `[0,1]` (float noise only; mathematically in-range).
- **Edges:** `period<3` → ValueError; `len < p` → NaN; flat → 0.0; perfectly
  monotone → 1.0; decreasing series → 1.0 (R² is sign-invariant); non-finite → NaN;
  `period=1e9` → NaN.
- **Hand calcs:** y=`[1,3,2,4]` p=4: means 1.5/2.5, `Sxy=4.0`, `Sxx=5.0`,
  `Syy=5.0` → `16/25 = 0.64`. y=`[1,2,3,4]` → `25/25 = 1.0`.
- Adversarial: `period=1e9` → NaN; all-equal closes → exactly `0.0` (specific value).

### 5.4 `variance_ratio` — VR(q), Lo–MacKinlay construction

Book: `Var(q-bar returns) / (q * Var(1-bar returns)). >1 trending, <1 mean-reverting.`
Correct: Lo & MacKinlay (1988) construction — returns are **log returns**
(`x_t = ln(p_t/p_{t-1})`; consistent with repo `returns.py` = ln, and with the
paper), **overlapping** q-bar returns (paper's efficiency refinement, eq. 10),
`VR(q) = Var(r_q)/(q·Var(r_1))` — the book's plain gate form. Declared deviation
(§6 D6): the paper's *test statistic* uses bias-adjusted estimators
(unbiased 1/(T-1), demean by `q·μ̂`); the book (and this gate) uses the plain
ratio of variances — it is a regime heuristic, not a hypothesis test. Both
variances population `ddof=0` (REV4), each around its own mean.
- Params: `period` default **5.0** (the book's `q`; param name `period` for
  profile-merge consistency), integral `>= 2`. `minimum_history = period + 2`
  = **7** (need ≥2 overlapping q-bar returns and ≥2 one-bar returns;
  `N-q >= 2` ⇔ `N >= q+2`, dominates `N>=3` for q≥2).
- Compute: `r1 = ln(c[t]/c[t-1])` t=1..N-1; `rq = ln(c[t]/c[t-q])` t=q..N-1;
  **`Var(r1) == 0` → 1.0** (no 1-bar dispersion ⇒ neither trending nor
  mean-reverting; gate `<1` fails safe — declared §6 D7); else `var_q/(q*var_1)`.
  `rq` domain: closes `<= 0` → NaN (log domain, same as `returns.py`).
- **Edges:** `q=1` → ValueError; `len < q+2` → NaN; flat prices → 1.0;
  perfect q-period alternation → 0.0; non-finite/`<=0` close → NaN;
  `q=1e9` → NaN.
- **Hand calc:** closes `[10,11,10,11,10,11]` q=2: r1 = ±ln(1.1) alternating,
  `Var(r1) = 0.008720669159359434`; rq = `[0,0,0,0]` → `Var(rq)=0` → **0.0**.
- **2-implementation cross-check (§3.5):** test recomputes VR via a second
  independent path (moment form `E[x²]-E[x]²`, demeaned sum form) over a
  deterministic 60-bar series; diff `<= 1e-9`.
- Adversarial: `q=1e9` → NaN.

### 5.5 / 5.6 `swing_high` / `swing_low` — fractal pivots

Book: `Fractal pivot: local extreme vs. k bars on each side (k=2 default).`
Correct: strict local extreme — index `j` is a confirmed pivot-high iff
`k <= j`, `j+k <= i` (**confirmation lag: only pivots confirmable at or before
the evaluated bar — no look-ahead**), and `high[j] > high[m]` for all
`m in [j-k, j+k], m != j` (strict: a tie is not a local extreme). Return the
**most recent** such level (nearest ≤ i), scanning newest-first.
`swing_low` mirrors with `<`.
- Params: `lookback` default 2.0 (book's k, "bars each side"), integral `>= 1`.
- `minimum_history = 2k+1` = **5** (earliest pivot `j=k` confirmed at `i=2k`).
- **Edges:** no confirmed pivot → NaN; `len < 5` → NaN; equal highs (flat) →
  NaN (strict); `lookback=0` → ValueError; non-finite highs/lows → NaN;
  `lookback=1e9` → NaN.
- **Hand calcs:** highs `[10,12,11,13,9,8]` k=2 i=5 → j=3 (window `[12,11,13,9,8]`,
  13 strict max) → **13.0**; same series first 4 bars → NaN (j=2 window
  `[0..4]` unavailable). lows `[10,7,8,5,11,12]` k=2 → **5.0**.
- Adversarial: all-equal highs → NaN; `lookback=1e9` → NaN.

### 5.7 `market_state` — structure state from tracked pivots (float encoding)

Book: `'bull' (HH/HL) | 'bear' (LH/LL) | 'chop', from the tracked pivot sequence.`
Correct: collect confirmed pivot highs `H` and pivot lows `L` (5.5/5.6 rules,
in bar order, up to i). `|H| < 2 or |L| < 2` → NaN (not enough structure —
engine `invalid:` warns, never a silent 'chop' that would block A1/A2/A3/D2/S1
entries without explanation). Else:
`H[-1] > H[-2] and L[-1] > L[-2] → +1.0` (HH/HL bull);
`H[-1] < H[-2] and L[-1] < L[-2] → -1.0` (LH/LL bear);
anything mixed or equal → `0.0` (chop).
**Encoding is a declared contract-driven deviation (§6 D1):** the frozen
`AnalyticsResult.features: dict[str, float]` cannot carry the book's strings;
M4 maps `+1/-1/0 → 'bull'/'bear'/'chop'` (strategy slice).
- Params: `lookback` default 2.0 integral `>= 1`. `minimum_history = 3k+2` = **8**
  (two confirmed pivots of each kind; earliest second pivot `j=2k+1` confirms at
  `i=3k+1`; adjacent same-type pivots are impossible — window overlap forces
  `high[j] > high[j']` and `high[j'] > high[j]` — hence the `2k+1` spacing).
- **Edges:** <2 pivots of either kind → NaN (incl. 7 bars of an 8-bar fixture);
  mixed (HH+LL or LH+HL) → 0.0; ties → strict rule removes pivots (may → NaN);
  `lookback=0` → ValueError; non-finite → NaN; `lookback=1e9` → NaN; flat → NaN.
- **Hand calcs (fixtures pinned, pivots verified by exact comparison):**
  - bull highs `[10,11,12,11,10,15,14,13]` lows `[9,8,7,9,9,8,9,10]` →
    `H=[12,15]` (HH), `L=[7,8]` (HL) → **+1.0**
  - bear highs `[10,14,15,12,11,13,10,9]` lows `[9,7,6,8,7,5,7,8]` →
    `H=[15,13]` (LH), `L=[6,5]` (LL) → **-1.0**
  - chop highs = bull highs, lows = bear lows → `H=[12,15]` HH, `L=[6,5]` LL
    → mixed → **0.0**
- Adversarial: `lookback=1e9` → NaN; 7-bar bull slice → NaN (boundary).

### 5.8 `bollinger_bandwidth` — normalized band width

Book: `(upper - lower) / mid, from bollinger_bands()` where
`bollinger_bands = SMA(n) +/- k*stdev(n)`.
Correct: official Bollinger BandWidth = `(Upper-Lower)/Middle`, equivalently
`2*k*sigma/Middle`, **population standard deviation (divide by n, not n-1)**
— confirmed against Bollinger's specification; matches REV4 `ddof=0`.
- Params: `period` default 20.0 integral `>= 1`; `stddev` default 2.0 finite
  `>= 0` (mirrors `bb_percent._stddev`; k=0 → numerator 0 → 0.0).
  `minimum_history = 20`.
- Compute: window = last p closes; `mid = mean`; `sigma = sqrt(population var)`;
  **`mid == 0` → NaN** (division guard; zero-centered series are not a price
  level — declared §6 D8); else `2*k*sigma/mid`.
- **Edges:** `len < p` → NaN; sigma=0 (flat) → exactly 0.0; `mid=0` → NaN;
  `period=1` → sigma=0 → 0.0; `stddev=-1` → ValueError; non-finite → NaN;
  `period=1e9` → NaN.
- **Hand calc:** closes `[1,2,3,4,5]` p=5 k=2: mean 3, pop var 2, sigma `√2`
  → `4√2/3 = 1.885618083164127` (approx, abs=1e-12).
- Adversarial: `stddev=-1` → ValueError; `period=1e9` → NaN.

### 5.9 `bollinger_bandwidth_percentile` — BBWP

Book: `Percentile rank of current Bollinger Bandwidth over the lookback window.`
Correct: build the bandwidth series (5.8 over successive windows), then
`ta.percentrank` semantics over the **last `lookback` bandwidths including the
current one**: `100 * #{v <= cur} / lookback`; `na` (any NaN bandwidth, e.g.
mid==0 inside the window) → NaN (Pine: na in window → na result — never drop
the sample silently).
- Params: `period` 20.0 integral `>= 1`; `stddev` 2.0 finite `>= 0`;
  `lookback` default 100.0 (book usages pass 100) integral `>= 2`.
- `minimum_history = lookback + period - 1` = **119** (bandwidth count =
  `N - p + 1 >= lookback`).
- **Edges:** `N < lookback+period-1` → NaN; `lookback=1` → ValueError;
  constant bandwidths → **100.0** (all ≤ cur — TV-compatible, same trap class
  as 5.2, gates pair it: A3 `bbwp < 25`, E1 `< 20`); NaN bandwidth in window →
  NaN; `lookback=1e6` → NaN.
- **Hand calc:** closes `[10,12,10,11,10]` p=2 k=1 lookback=4 → bandwidths
  `[2/11, 2/11, 1/10.5, 1/10.5]` = `[0.18181818181818182, 0.18181818181818182,
  0.09523809523809523, 0.09523809523809523]`, cur = last, `#{<=} = 2` → **50.0**
  (exact: both 0.0952… values are the identical float; both 0.1818… identical).
- Adversarial: `lookback=1e6` → NaN; closes containing 0.0 mid → NaN.

### 5.10 `anchored_twap` — mean close since anchor

Book: `Mean(Close) since the session/anchor open -- the volume-free VWAP substitute.`
Correct: arithmetic mean of closes over the provided window. **Declared deviation
(§6 D2):** the book's "session open" anchor requires M2b `TradingCalendar`
session boundaries — Day-1 anchor = **first bar of the request window** (the
engine window already starts at `window_start` derived from the strategy's
`as_of`; a session-open anchor is a data dependency this module must not reach
for — Isolation Law). `TODO(correctness)` logged in BUILD_STATUS Open Questions
until the M2b-anchored variant lands (own slice, additive param).
- Params: none (`defaults={}`); `params is None` → ValueError (shape contract),
  empty dict OK, unknown keys ignored (nothing to validate — declared: no
  silent-accept risk because there is no valid parameter to mis-accept).
  `minimum_history = 1`.
- **Edges:** 1 bar → that close; non-finite close → NaN; empty → ValueError.
- **Hand calc:** closes `[10,11,12]` → `(10+11+12)/3 = 11.0` exact (dyadic).
- Adversarial: `params={"period": -5}` (a param this analytic does not have) →
  still `11.0` — asserts unknown keys cannot alter a paramless compute.

## §6 Declared deviations (recorded here, never silent — §3.14)

- **D1** `market_state` encodes book strings as `+1.0/-1.0/0.0` — frozen
  `AnalyticsResult.features` is `dict[str, float]`; M4 maps to labels.
- **D2** `anchored_twap` anchors at request-window start, not session open
  (needs M2b) — `TODO(correctness)`.
- **D3** `atr_percentile_rank` is used but never defined by the book — filled
  with TV `ta.percentrank` over the pinned `atr_14` ATR series.
- **D4** constant windows rank **100.0** (TV `<=` semantics) — not a bug; gates
  must pair rank gates with ER/AD gates as the book does.
- **D5** flat R² → 0.0 (undefined → gate-safe falsy), flat VR → 1.0 (null
  random-walk value → `<1` fails safe), ER flat → 0.0 — all three safer-assumption
  choices (§3.3).

## 1. Purpose

Classify every missing minute as **one of four states**, so that a shut market is never
mistaken for lost data, and a permanently-unfillable window is never requested twice.

## 2. Why — the four states

The research standard is a `known_gaps` table: *"buckets the provider confirms are missing
(weekends, holidays, exchange downtime) get recorded to `known_gaps` so they aren't
re-requested forever."* It names exactly the three categories that break naive gap
detection. So:

| State | Meaning | Backfill? | Blocks calculation? |
|---|---|---|---|
| `COMPLETE` | candle present | no | no |
| `FILLING` | open market, awaiting repair | **yes** | **yes** |
| `PERMANENTLY_MISSING` | venue has no data; unrecoverable | **never again** | **yes** |
| `CLOSED` | market was shut — **not a gap** | no | no |

`CLOSED` is the state this whole slice exists to add. Without it, a 25-asset mixed universe
records ~17 h of "lost data" every weekend, per instrument, forever.

## 3. The standard, applied

| Standard practice | Here |
|---|---|
| `known_gaps` so impossible windows are not re-requested | `PERMANENTLY_MISSING` + persisted ledger |
| Idempotent writes, `ON CONFLICT` | ledger keyed `(instrument, broker, start_at)` |
| Watermark bounds reprocessing | backfill horizon; beyond it → `PERMANENTLY_MISSING` |
| Source is authoritative on overlap | broker value wins, `source` recorded |
| Never serve corrupt state | `FILLING` blocks calculation rather than computing across |

## 3a. AUTHORITY AND FALLBACK — corrected by the human 2026-09-27

**The broker's own state is authoritative.** The static calendar is a *configured fact that
rots*; the venue is the only thing that knows whether it traded. Every `GapRun` therefore
carries `evidence`, and evidence is never silently upgraded.

| Rank | Source | `evidence` | When used |
|---|---|---|---|
| 1 | **Broker** — `exchange_is_open` (now), data-availability probe (past window) | `broker` | always preferred |
| 2 | Configured `TradingCalendar` | `calendar` | broker **unverifiable** |
| 3 | Asset-class default (24/7 vs session-based) | `default` | broker **and** config unavailable |
| 4 | Terminal `PERMANENTLY_MISSING` | — | unverifiable past the horizon |

### 3a.1 The fallback bias is deliberate, and it is asymmetric

When the broker cannot be verified, the fallback assumes **the market was OPEN** — i.e. it
produces a candidate `FILLING` gap, not a silent `CLOSED`.

- A **false gap** is self-healing: backfill asks the broker, the broker returns nothing, the
  window is recorded `PERMANENTLY_MISSING` with `source=learned`, and it is never asked
  again. Cost: one wasted request.
- A **false closure** is permanent and silent: real data loss is never repaired, because the
  system believes the market was shut. Cost: undetected, unbounded.

`AGENTS.md` §3.3 states the rule — *unknown/ambiguous state defaults to the safer
assumption*. Here the safer assumption is "assume we lost data", because only one of the two
errors is self-announcing.

### 3a.2 `UNKNOWN` is never `CLOSED`

A broker **error, timeout, rate-limit or unreachable host** is `UNKNOWN`, not `CLOSED`. Only
two things legitimately mean closed:

1. the broker states the session is shut, or
2. the broker served a well-formed response containing **no bars** for that window.

Conflating "I could not ask" with "there is nothing there" is the single most dangerous bug
available in this module, and it has an explicit test.

### 3a.3 An unverified gap is a *different kind* of gap

`needs_verification=True` marks a `FILLING` run produced without broker confirmation. It is
not queued for ordinary backfill — it is escalated to a verification pass, because we do not
yet know whether it is real. This is what keeps an outage from turning into a retry storm.


## 4. Signatures

```python
class GapState(str, Enum): ...

def classify_window(instrument_id, broker, start, end) -> list[GapRun]
def missing_slots(instrument_id, broker, start, end) -> list[GapRun]   # DB-backed
def record_permanent(runs, *, reason, source) -> int
def coverage_of(instrument_id, broker, start, end) -> CoverageVerdict
```

`sentiment` is sync where it is pure computation; the DB-backed readers are `async` because
they are I/O. **Hot-path rule preserved:** nothing here runs per-tick.

## 5. Invariants

1. **`CLOSED` is never a gap.** A window inside market hours is a candidate gap; a window
   outside them is not.
2. **A gap never spans a closed period** in its output — runs are split at session boundaries
   so a Friday→Sunday hole is not reported as one 3-day gap.
3. **`PERMANENTLY_MISSING` is terminal.** Once recorded, the same window is never enqueued
   again. It is only cleared by an explicit human action, never by a scan.
4. **Idempotent.** Recording the same gap twice is a no-op, not a duplicate row.
5. **A gap on an unknown instrument or broker is a typed error**, never silently empty.
6. **Fail closed on coverage:** a `FILLING` window must not yield a number to analytics.

## 6. Edge cases

| # | Case | Required behaviour |
|---|---|---|
| E1 | window fully inside market hours, all present | `COMPLETE` |
| E2 | window fully inside market hours, one minute missing | one `FILLING` run of 1 minute |
| E3 | window fully on a weekend | **`CLOSED`**, no gap at all |
| E4 | Friday close → Sunday open, nothing stored | `CLOSED` only — **no gap emitted** |
| E5 | Tuesday hole of 341 minutes | one `FILLING` run |
| E6 | hole adjacent to a session boundary | run clipped to the boundary, never past it |
| E7 | crypto (always open), any window | always a gap candidate; never `CLOSED` |
| E8 | broker confirms no data for a window | `PERMANENTLY_MISSING`, never re-enqueued |
| E9 | already `PERMANENTLY_MISSING`, rescanned | unchanged, no duplicate, no re-enqueue |
| E10 | `end <= start` | `ValueError` |
| E11 | zero-length window | `ValueError` |
| E12 | window far in the past | still classified, no clock read |
| E13 | window in the future | `ValueError` — the future has no coverage |
| E14 | holiday inside session hours | `CLOSED` for that day |
| E15 | overlapping runs | merged, never double-counted |
| E16 | adjacent runs (touching) | merged into one |
| E17 | unknown instrument | typed error |
| E18 | unknown broker | typed error |
| E19 | coverage queried over a mix of states | reports the WORST state present |
| E20 | re-running a full scan | idempotent, identical output |

## 7. Adversarial

| Input | Must |
|---|---|
| window of 10 years | `ValueError` or bounded, never OOM |
| `start` naive | `ValueError` |
| negative/overflow timestamps | `ValueError` |
| 1M-minute window on an always-open asset | bounded, no unbounded list build |
| `known_gaps` row for a different broker | never matched — broker is part of the key |
| concurrent record of the same gap | idempotent, single row |
| reason string > 500 chars | truncated or rejected, never unbounded |

## 8. Definition of correct

- A weekend produces **zero** gaps for all 25 assets.
- A real 341-minute hole on a 24/7 asset produces **exactly one** run.
- A window the venue cannot serve becomes `PERMANENTLY_MISSING` once and is never
  re-requested.
- `coverage_of` over a mixed window reports the worst state, so a caller cannot accidentally
  compute across a hole.

## 9. Tests required before implementation

`tests/m2_market_data/test_m2.6_gap_spec.py` — one test per §6 edge, the §7 adversarial
cases, and a **property sweep**: 25 assets × 14 days hourly, assert the count of
`CLOSED` minutes for forex/commodity is non-zero and for crypto is zero. That property is
the regression that matters — it is what a naive detector gets wrong.

## 11. Open questions

1. **Holiday source — DECIDED under the human's mandate: both.** A maintained
   `config/calendars/holidays.yaml` now, **plus** reconciliation may *append* a discovered
   closure with `source=learned`. Config alone rots; learning alone misclassifies the first
   outage after any closure.
2. **Retain `PERMANENTLY_MISSING` forever?** Recommendation **yes**, with an explicit
   human `reopen` action — a terminal record is the whole point, and auto-expiry would
   reintroduce the retry storm this prevents.

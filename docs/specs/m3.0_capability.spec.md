## Scope

**In (Day-1):**
- `CapabilityRegistry` load from YAML once (constructor / `from_yaml`)
- `get(feature, broker)` → status + reason + requires + warning
- `is_available(feature, broker)` → bool (`FULLY_SUPPORTED` or `DERIVED` only)
- `is_strategy_eligible(strategy_id, broker)` → `(bool, reason)` — every required feature available else fail with `needs <feature> UNAVAILABLE` (or first failing feature)
- Module: `financial_analyst_app/modules/m3_analytics/capability/` (`capability_registry.py`, `capability_types.py` as needed)
- Config: `financial_analyst_app/config/capabilities.yaml` (versioned)
- Tests (after LGTM): `financial_analyst_app/tests/m3_analytics/test_m3.0_spec.py`
- P15 gate test name: `test_order_book_unavailable_on_deriv`

**Out:**
- Computing RSI/ATR or any `M3.2` formula
- Feature engine / Redis cache (`M3.1`)
- Lake / PIT / Temporal Resolver (those gate *data*, not *capability*)
- Mutating `AnalyticsResult` or `TradePlan` (callers stamp fields later)
- DB, network, async I/O in `get`/`is_available` (sync pure after load)
- New shared contract — reuse frozen `CapabilityStatus` in `shared/contracts/market_data.py`
- Per-user vault, market-data storage, watermark

## Inputs

- `feature: str` — non-empty key (`"rsi_14"`, `"order_book_imbalance"`, …)
- `broker: str` — `"deriv" | "mt5" | "headway"` (Day-1; unknown broker → fail-closed see Edges)
- `strategy_id: str` + static `strategy_requirements` map (YAML or in-module dict — Day-1 dict in YAML under `strategies:`)
- Optional `user_id` reserved for Day-2 per-tenant override — **Day-1: signature accepts `user_id: str | None = None` but does not branch** (WHY: bible says per-tenant gate later; Day-1 broker-only keeps tests pure)

## Outputs

1. **`CapabilityEntry`** (in-module frozen/pydantic model, not shared package):
   - `status: CapabilityStatus`
   - `reason: str | None`
   - `requires: tuple[str, ...]`
   - `warning: str | None` (e.g. `"tick_count ≠ volume"`)
   - `method: str | None` (e.g. `"tick_count_proxy"` for DERIVED/PROXY)
2. **`is_available` → `bool`** — `True` iff status in `{FULLY_SUPPORTED, DERIVED}`. **`PROXY_LIMITED` is available with warning only if caller opts in** — Day-1: `is_available` returns **`False` for `PROXY_LIMITED`** unless `allow_proxy=True` (default `False`) — WHY: fail-closed; M3.1 must not silently treat proxy as full.
3. **`is_strategy_eligible` → `(True, "eligible")` or `(False, "needs <feature> <status>")`** — iterate required features in declared order; first unavailable wins.

**Never** returns `None` for a known feature; unknown feature → see Edges (raise or synthetic UNAVAILABLE — freeze: **synthetic `CapabilityEntry(UNAVAILABLE, reason="unknown_feature")`** for `get`, and `is_available` → `False`; do **not** raise on unknown feature in hot path — missing config is fail-closed, not crash).

## YAML shape (frozen Day-1)

```yaml
# config/capabilities.yaml
version: "1.0"
features:
  rsi_14:
    status: FULLY_SUPPORTED
    requires: [price]
  ema_20:
    status: FULLY_SUPPORTED
    requires: [price]
  tick_rate:
    status: PROXY_LIMITED
    method: tick_count_proxy
    warning: "tick_count ≠ volume"
    requires: [tick_count]
  order_book_imbalance:
    status: UNAVAILABLE          # default global; broker overrides below
    reason: "needs bid_levels"
    requires: [bid_levels, ask_qty]
brokers:
  deriv:
    # Day-1: only explicit overrides; absence of feature under broker = use features: default
    overrides:
      order_book_imbalance:
        status: UNAVAILABLE
        reason: "Deriv has_depth:false"
      # rsi_14 not listed → inherit FULLY_SUPPORTED
  mt5:
    overrides:
      order_book_imbalance:
        status: FULLY_SUPPORTED   # depth available on MT5 when adapter present
strategies:
  rsi_overbought_oversold:
    requires_analytics: [rsi_14]
  donchian_breakout:
    requires_analytics: [ema_20]   # Day-1 stub — full manifest is M4.2
  microstructure_flow:
    requires_analytics: [order_book_imbalance]
```

- Load once: missing file → `FileNotFoundError` at construction (**fail-loud startup**, not silent empty registry).
- Malformed YAML / missing `version` / missing `features` → `ValueError` at load.
- Invalid `status` string → `ValueError` at load (must match `CapabilityStatus` values).
- Broker override merge: override fields replace default entry fields; status always present.

## Correct

1. Fresh registry from valid YAML → `get("rsi_14", "deriv").status == FULLY_SUPPORTED`.
2. `is_available("rsi_14", "deriv") is True`.
3. `get("order_book_imbalance", "deriv").status == UNAVAILABLE` and `is_available(...) is False` → **P15 gate**.
4. `get("order_book_imbalance", "mt5").status == FULLY_SUPPORTED` (override) → `is_available` True.
5. `is_strategy_eligible("rsi_overbought_oversold", "deriv") == (True, "eligible")`.
6. `is_strategy_eligible("microstructure_flow", "deriv")[0] is False` and reason mentions `order_book_imbalance`.
7. `get("tick_rate", "deriv")` → `PROXY_LIMITED`; `is_available("tick_rate", "deriv") is False` (default no proxy); `is_available(..., allow_proxy=True) is True` with `warning` preserved.
8. `get("unknown_feature_xyz", "deriv")` → `UNAVAILABLE`, `reason` contains `unknown_feature`; `is_available` False — **no exception**.
9. Registry is pure after load — two calls same args → equal status (deterministic).
10. `user_id=None` and `user_id="42"` same broker/feature → same Day-1 result (no tenant branch yet).

## Edges

- Empty `feature=""` or `broker=""` → treat as unknown → UNAVAILABLE / False / ineligible (fail-closed).
- Unknown `broker="ctrader"` (not in YAML) → use **global `features:` defaults only** (no overrides) — still works for `rsi_14`; `order_book_imbalance` stays global default UNAVAILABLE unless default says otherwise.
- Strategy id missing from `strategies:` → `(False, "unknown_strategy <id>")`.
- Strategy requires empty list → `(True, "eligible")` (vacuous — document; M4 will not ship empty requires).
- YAML `features.order_book_imbalance` missing but broker override present → load-time `ValueError` (override without base).
- Status value `"CURRENTLY_UNAVAILABLE"` in prose → must be written as enum value `UNAVAILABLE` (map if needed: load accepts only enum values; reject aliases Day-1).
- Nested override that sets `requires` without `status` → merge keeps base `status`, replaces `requires`.

## Adversarial

- `status: "FULLY"` (truncated) → load `ValueError`.
- `features: []` (list not dict) → load `ValueError`.
- Hostile `feature="'; DROP TABLE"` → unknown → UNAVAILABLE, no SQL (there is no DB).
- `strategy requires_analytics: null` → load `ValueError`.
- Same feature listed under two brokers with conflicting status → allowed (per-broker override is intentional); assert both via `get`.

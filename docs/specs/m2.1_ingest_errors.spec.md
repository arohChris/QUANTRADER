# Spec: M2.1 Ingest Error Contract (loudness + reconnect serialization + outage record)

Purpose: Every failure on the ingest path is **loud and recorded**, never silently discarded; exactly **one** reconnect runs per broker per outage; and every outage is recorded with an honest start/end so a repair job can later ask the broker for the missing window.

Governs: `modules/m2_market_data/ingestion.py` (the `IngestionManager` socket lifecycle).
Sibling spec: `docs/specs/m2.1_connection.spec.md` (owns connect/subscribe/heartbeat happy path). This spec owns **what happens when that path fails**. It does not re-specify `TickIngestor` parsing (`m2.1_ingestion.spec.md`, `complete`) nor `ConnectionManager` backoff math.

Layering unchanged: async I/O only, no vault, no `user_id`, no business math. **Not money path** - no hand-calc sheet required (AGENTS 2.8 money review does not apply), but the outage record is a **ledger input** and must be exact.

Review status: **DRAFT 2026-09-29. Awaiting human LGTM (Step 1). No tests written, no code written.**

## 0. WHY this slice exists (the two defects, with evidence)

Defect D34 in `BUILD_STATUS.md` named only `ingestion.py:196 try/except/pass`. Reading the whole file found **four** distinct defects in the same failure path, and measured the exception surface rather than assuming it.

### D-A — the named defect: a discarded close failure (`ingestion.py:194-197`)

```python
handle.state = "degraded"
try:
    await handle.ws.close()
except Exception:
    pass                       # <-- discards everything, logs nothing
handle.state = "reconnecting"
await self._reconnect(broker, state, handle)
```

**MEASURED, not assumed.** `websockets` 17.0.1 `ClientConnection.close()` source, read directly:

```python
try:
    async with self.send_context():
        ...
        self.protocol.send_close(code, reason)
except ConnectionClosed:
    # Ignore ConnectionClosed exceptions raised from send_context().
    # They mean that the connection is closed, which was the goal.
    pass
```

Consequences of that measurement:

1. **The library already swallows `ConnectionClosed`.** So our `except Exception: pass` never sees the "already closed" case. It is not load-bearing for the benign path - it is a no-op there.
2. **What it DOES catch is the interesting case.** `close()` awaits the closing handshake, so a peer that never completes it raises **`TimeoutError`**. A socket-level failure raises **`OSError`**. Both are `Exception` subclasses. Both are currently **discarded with no log and no counter**.
3. **The operator-visible result is a lie.** The log sequence reads `heartbeat_timeout` then `reconnected` - indistinguishable from a clean recovery. A socket that refused to die looks exactly like one that closed politely.
4. **MEASURED, and it means today's code is right by accident:** `asyncio.CancelledError` is a `BaseException` in Python 3.14 (`not issubclass(CancelledError, Exception) == True`), so cancellation correctly escapes the bare `except Exception`. **A test MUST pin this**, because the natural-looking "fix" (`except BaseException`) would silently break shutdown.

### D-B — the unlogged, unreported defect: two concurrent reconnect loops

`_start_lock` (`:66`) guards `start`/`stop` **only**. Both of these call `_reconnect`, which takes **no lock at all** (`:201`):

- `_recv_loop` - `:157`
- `_heartbeat_loop` - `:199`

They are **separate `asyncio.Task`s** (`:107-108`). Derived from the code, not hypothesised:

| Step | Line | Two concurrent runs produce |
|---|---|---|
| create socket | `:210` | **2 sockets** from one outage |
| swap into pool | `:217` | the 2nd overwrites the 1st; **socket #1 is orphaned and never closed** - leaked TCP connection **plus a live Deriv subscription the broker still pushes to** |
| re-subscribe | `:222-223` | 2 subscribe rounds |
| failure counting | `:213`/`:226` | `consecutive_failures` double-increments, so backoff grows ~2x faster than configured |

**This is not an exotic race - it is the expected path for any outage longer than ~35s.** The recv loop detects a dead socket immediately (`:153`) and enters `_reconnect`, which sleeps `backoff_delay` (`:206`, up to 30s) **without updating `last_inbound_at`**. After `heartbeat_timeout_s` (35s default) the heartbeat loop independently sees stale inbound and enters `_reconnect` too. Both then race for the whole backoff.

Direct link to the reported symptom: an orphaned socket keeps a subscription alive, so the feed looks partly alive; the doubled backoff stretches the outage; and **no outage window is ever recorded** (D-D), so a repair job has nothing to ask the broker for.

### D-C — a socket that failed to subscribe is left in the pool looking usable

`:217` calls `replace_socket(..., state="connected")` **before** the resubscribe loop at `:221-223`. If resubscribe then fails, `:227` sets `state="reconnecting"` - but the **new, unsubscribed socket is still the pool's live handle**, and `:219` already stamped `last_inbound_at = now`, so it looks fresh. `ConnectionManager.get_or_create` (`connection.py:56-58`) returns any handle whose state is not `"closed"`, so a later `start()` can adopt a socket with **zero subscriptions** - a silent, permanent no-data feed that produces no error and therefore no gap.

### D-D — the outage itself is never recorded (this is the "gaps created undetected" part)

When the socket dies at `T1` and reconnects at `T2`, every tick in `(T1, T2)` is gone. Nothing in this module records that window.

*Partially* mitigated already: the `QualityGate` watermark-jump detector (`quality.py:59-80`, wired at `pipeline.py:149`, committed `df84bd1`) will mark the first tick after the jump `gapped`, so the resulting candle is stamped `GAP_AFFECTED`. **Detection of the symptom exists.** What does not exist is a queryable outage record, so:

- an operator cannot answer "when was the feed down for CRYPTO.BTCUSD?"
- the repair slice (BUILD_STATUS item #2) has no window to request from the broker

**Scope boundary:** this spec defines the **record**. The repair loop that consumes it is item #2 and is NOT in this slice.

---

### D-E — the injected clock is dead, so this slice cannot be tested deterministically (found while designing the Step 3 tests)

`ingestion.py:64` accepts `clock: Any | None = None` and stores `self._clock = clock`. **It is then never read.** All four timestamp sites call the module-level `_now()` (`:95`, `:160`, `:187`, `:219`), which is hard-wired to `datetime.now(timezone.utc)` (`:240-241`).

Two consequences, and the second is disqualifying for this slice:

1. **The parameter is a lie.** A caller who injects a clock — precisely to make behaviour reproducible — gets wall-clock time instead, with no error. This is the "works, and is quietly wrong" mode `AGENTS.md` §3.14 forbids.
2. **It makes the heartbeat untestable without real sleeping.** `AGENTS.md` §3.5 bans time-dependent tests and mandates a simulated clock. Every edge in this spec that depends on the heartbeat timeout (E1-E7, E8) currently has **no way to be tested deterministically** — a test would either sleep for the real 35s or race the scheduler.

**Required:** `_now()` becomes an instance read of the injected clock, defaulting to the real UTC clock, so a test can pin time. A clock that is injected must be **used**; a clock that is accepted and discarded must be **rejected** instead.

### Read path for the ledger (spec gap, closed before Step 3)

The spec originally declared `OutageRecord` as an output without saying how it is read, which would have left the test contract undefined. Chosen now, and the tests encode it:

```python
IngestionManager.outages(broker: str) -> tuple[OutageRecord, ...]
```

`tuple`, not `list`: an immutable snapshot, so a caller cannot mutate recorded history. Empty tuple when that broker has had no outage. **Never raises** for an unknown broker — an unknown broker has no outages, which is empty, not an error.

## 1. Inputs / Outputs / Invariants

### Inputs
- `broker: str` - canonical broker name (e.g. `deriv`).
- `exc: BaseException` - any exception raised by socket teardown.
- outage instants - **UTC, tz-aware, never naive** (AGENTS 3.8).

### Outputs
- `OutageRecord` (new, **in-module frozen model**, not a `shared/contracts` type - precedent: `recovery.RecoveryResult` is explicitly "not a shared contract until M8/M12 consume it"). Fields: `broker: str`, `started_at: datetime`, `ended_at: datetime | None`, `reason: str`, `close_failures: int`. Read via `IngestionManager.outages(broker)`.

### Invariants (each is separately testable)
- **I1 NO SILENT DISCARD.** No exception on this path is discarded without either (a) propagating, or (b) emitting a structured log record carrying `broker`, exception **type**, and reason. Swallowing-and-not-logging is banned outright.
- **I2 CANCELLATION PROPAGATES.** `asyncio.CancelledError` is never caught. Shutdown must not hang.
- **I3 ONE RECONNECT PER BROKER PER OUTAGE.** Concurrent outage detection from N loops yields exactly **one** socket creation and one resubscribe round.
- **I4 ORPHANS ARE IMPOSSIBLE.** A socket that is replaced or that fails to subscribe is closed (loudly, per I1), never left referenced by a live pool entry.
- **I5 THE OUTAGE IS ALWAYS RECORDED.** An outage with a known end carries `ended_at`; an outage still open carries `ended_at=None`. **An end time is never invented.**
- **I6 NO SECRET IN ANY LOG.** Exception text passes the existing redaction before it reaches a log line (AGENTS 3.7). A Deriv token must not reach a log via an exception message.

## 2. Edge cases (one test per row, named after the row)

### D-A close-failure handling
| ID | Condition | Required behaviour |
|----|-----------|---------------------|
| E1 | `close()` raises `TimeoutError` (peer never completes handshake) | log WARNING `broker`+`TimeoutError`+reason; increment `close_failures`; **reconnect still proceeds** - a failed close must never wedge recovery |
| E2 | `close()` raises `ConnectionClosed` | library already handles this internally; our layer logs at **DEBUG** (not WARNING) so the common case does not cry wolf |
| E3 | `close()` raises `OSError`/socket error | log WARNING; increment; proceed to reconnect |
| E4 | `close()` raises `asyncio.CancelledError` | **propagate** (pins I2) |
| E5 | `ws` has no `close` attribute (already torn down / test double) | `getattr` guard; log at DEBUG; proceed - never `AttributeError` |
| E6 | `close()` succeeds | no error log emitted |
| E7 | `close()` returns a **non-awaitable** (sync double) | handle without `TypeError`; mirrors `connection.py:99-100` |

### D-B reconnect serialization
| ID | Condition | Required behaviour |
|----|-----------|---------------------|
| E8 | recv-loop **and** heartbeat-loop detect the same outage in the same tick | exactly **one** `connect_factory` call, one `replace_socket`, one resubscribe round (I3) |
| E9 | 100 concurrent outage detections for one broker | still exactly **1** socket created |
| E10 | second detector arrives while the first is mid-backoff | second waits for, then observes, the first's result; must **not** create a socket |
| E11 | `stop()` called while `_reconnect` is sleeping in backoff | reconnect loop exits, no orphan task, no socket leak |
| E12 | first reconnect succeeds, second arrives after | second sees a live connected handle and does nothing |

### D-C socket hygiene
| ID | Condition | Required behaviour |
|----|-----------|---------------------|
| E13 | `replace_socket` succeeds, then resubscribe **fails** | the unsubscribed socket is **closed** (loudly) and **removed** from the pool; it must never be adoptable by a later `get_or_create` |
| E14 | resubscribe fails for symbol 2 of 5 | same as E13 - partial subscription is still an unusable socket |
| E15 | resubscribe fails, then a later retry succeeds | pool ends with exactly one subscribed socket; failure count reset to 0 |

### D-D outage record
| ID | Condition | Required behaviour |
|----|-----------|---------------------|
| E16 | outage opens and closes | `OutageRecord(started_at, ended_at, reason, close_failures)` with both instants UTC |
| E17 | outage still open at shutdown | `ended_at is None` - honest "unknown", never a fabricated end (I5) |
| E18 | reconnect attempts exceed any bound | outage stays **open**; reason records the failure count. The system does **not** invent a terminal end |
| E19 | zero-length outage (`started_at == ended_at`) | rejected as `ValueError` - a zero-length outage is a clock bug, not an outage |
| E20 | `started_at` or `ended_at` naive | rejected - AGENTS 3.8 |
| E21 | `ended_at < started_at` | rejected |
| E22 | two outages for one broker, sequential | two distinct records; the second `started_at` >= first `ended_at` |

### D-E the injected clock must be honoured
| ID | Condition | Required behaviour |
|----|-----------|---------------------|
| E26 | a clock is injected into `IngestionManager` | every timestamp in the module comes from **that clock**; no call to the real wall clock |
| E27 | no clock injected | real UTC wall clock is used (existing behaviour preserved) |
| E28 | injected clock returns a naive datetime | rejected - AGENTS 3.8; a clock is the one place a naive value must never enter |

### Log/redaction
| ID | Condition | Required behaviour |
|----|-----------|---------------------|
| E23 | exception `str()` **itself raises** | the log call must not explode; fall back to the exception **type name** only |
| E24 | exception message contains a token-looking string | redacted before logging (I6) |
| E25 | `broker` contains quotes/newlines | log line remains well-formed (no log injection) |

## 3. Adversarial cases (NOT in the defect list - fail-closed, typed error)

| ID | Input | Required behaviour |
|----|-------|---------------------|
| A1 | `close()` raises a `BaseException` that is **not** `CancelledError` (e.g. `KeyboardInterrupt`) | **propagate**; never converted to a logged-and-ignored warning |
| A2 | `close()` raises a custom exception whose `__init__` raises | log path must not raise; degraded but alive |
| A3 | `broker=""` or `None` when recording an outage | rejected as `ValueError` - an outage with no broker is unroutable |
| A4 | `OutageRecord` given an `ended_at` when `reason` is empty | rejected - an unexplained outage is worse than none |
| A5 | reconnect called for a broker that is not in `self._running` | returns immediately, no socket created, no exception |
| A6 | 1e6 spurious outage triggers in one tick | bounded work per tick (AGENTS 4.1 `<50ms`); the ingest hot path must not degrade |

## 4. Definition of correct

1. **Loudness** - every swallowed exception leaves a structured log record with `broker`, `type(exc).__name__`, and a redacted message. Verified by asserting on emitted log records, not on "no exception raised".
2. **Cancellation** - `asyncio.CancelledError` propagates out of `_heartbeat_loop` and `_reconnect`; `stop()` completes without hanging. Verified by a real `task.cancel()` + `asyncio.wait_for` with a timeout.
3. **Serialization** - with N concurrent detectors, `connect_factory` is called **exactly once** and `replace_socket` **exactly once**, per outage. Verified by a counting fake, not by inspecting logs.
4. **Hygiene** - after any failure sequence, the pool holds either **zero** handles or **one** subscribed, connected handle. Never a zero-subscription handle.
5. **Record** - one `OutageRecord` per outage, UTC, with an honest `ended_at` or an explicit `None`.

**Cross-check required (AGENTS 3.1, highest-risk formula rule):** the socket-count invariant (3) must be verified by a **second independent implementation** of the counter - a real `asyncio.Event`-driven two-loop race, diffed against the counting-fake result. A lock bug is exactly the class a single test shape can miss.

## 6. Verification plan (Step 7, real data)

`scripts/verify_m2.1_ingest_errors.py` against the **live** Deriv endpoint plus fakes:

1. **Live socket-kill**: connect for real, kill the socket, assert exactly one reconnect and one `OutageRecord` with a real start/end.
2. **Real close-handshake timeout**: hold a socket open without completing the handshake, force `TimeoutError`, assert the WARNING record exists (E1) - the exact case the library does NOT handle internally.
3. **Two-loop race, real tasks**: let both loops detect one outage, count sockets.
4. **Redaction proof** (E24): assert a token-shaped string in an exception message never appears in any emitted log record.
5. **Cancellation proof** (E4): `task.cancel()` mid-backoff, assert prompt exit.
6. **Outage ledger dump**: printed `OutageRecord`s for the session, human-eyeballed.

Honesty rule: any check that cannot run live (e.g. a genuine peer that never answers the close handshake) is reported **SKIPPED with the consequence spelled out**, never silently passed.

## Purpose

Take OHLC for 1-minute bars **from the broker**, which is the authority on its own prices, instead of
accumulating it in-process from ticks. One producer for both live and backfill, so a backtest and a
live session cannot trade on two different OHLC series for the same minute.

**The three sinks are peers, not subordinates.** M2.13 emits and forgets.

Concretely, and each of these is a **hard prohibition** on this slice:

1. **No storage policy.** M2.13 does not choose a retention period, a compression policy, a chunk
   interval, or a table. It does not know that `candles_1m` is a hypertable or that Valkey holds a
   ring of 240. Those are `m2.10` (frozen) and `M2.9` (frozen) decisions. If M2.13 later needs a
   different retention, that is **not** an M2.13 change.
2. **No direct Valkey client, no direct `asyncpg` pool, no `LakeWriter`, no filesystem.** M2.13 is a
   pure function of `(frame, received_at)` Ã¢â€ â€™ `Candle | Drop | None`, plus a `close()`. It is
   `def`, not `async def`, because it does no I/O Ã¢â‚¬â€ a `async def` here would be a lie about work
   that does not happen. Wiring it to a sink is the *caller's* job, and that wiring is out of this
   slice (see **Out of scope**).
3. **No read-back, no reconciliation, no repair.** M2.13 never queries a store to decide what to
   write. The only state it holds is the single currently-buffered candle plus two counters. That is
   what makes the finality rule below implementable at all: there is nothing else it could consult.
4. **No policy decisions leaking downstream, either.** Equally, M2.13 must not encode "how long the
   broker takes to finalise" or "how many bars to buffer" as a tunable that a storage concern might
   later want to move. `1` buffered candle is a *correctness* requirement (it is what makes
   `T, T, T+60` collapse to one bar), not a capacity knob.
5. **Independence is testable.** A test that can pass only by touching a real Valkey or a real
   `asyncpg` pool is a test of the wrong thing. The 43 tests in
   `tests/m2_market_data/test_m2.13_spec.py` construct the ingestor with no I/O at all Ã¢â‚¬â€ that is
   deliberate evidence of this boundary, not an accident of test convenience.

**Why this matters concretely, not architecturally:** the M2.9Ã¢â€ â€™M2.10 flush-path question is already
open and unresolved in `BUILD_STATUS.md` (ruling A52: *"On eviction (4h later)"* vs flush-on-close,
with `m2.11`'s frozen `pipeline.py` currently doing the latter). If M2.13 owned storage it would
have to take a position on that open question, and it would be taking a position on a question that
is not about candle correctness. Because M2.13 emits and forgets, **that dispute stays where it is**
and neither answer breaks this slice.

## Invariants

1. **The broker is the sole OHLC authority.** No OHLC value in this slice is computed, averaged, interpolated or carried forward.
2. **A minute the broker does not return is left missing.** No repair, no interpolation, no carry-forward, no synthesised bar.
3. **Canonical durable output is emitted only on finality.** A minute becomes final when a frame
   arrives carrying a **later** `open_time`, or on `close()`. Until then the minute is *forming* and
   M2.13 emits nothing for it. **This invariant is about M2.13's OUTPUT and says nothing about any
   downstream store** Ã¢â‚¬â€ see Ã‚Â§ Finality is three states, not one, which is where the hot/durable split
   is pinned down.
3a. **Hot state MAY advance on a forming candle.** A downstream hot consumer (Valkey, M2.9) is
   *permitted* to be updated as each frame arrives, so an operator watching a live minute sees it
   move. M2.13 neither performs nor forbids this Ã¢â‚¬â€ it is a consumer's choice. What M2.13 guarantees
   is only that the **canonical `Candle` it emits** corresponds to a final minute.
3b. **A final minute is never silently rewritten.** Once emitted, a minute is immutable. A later
   frame for the same `open_time` is **ignored and counted** (`late_frame_count`), never re-emitted.
   This holds even though the sink is `ON CONFLICT DO NOTHING`, which would drop the rewrite anyway:
   a write that is accepted-then-discarded makes the producer believe it corrected a bar that it
   did not.
4. **Comparison is Decimal, never string.** `Decimal("83589.140") == Decimal("83589.14")` is `True` and must not be reported as a mismatch.
5. **OHLC arrive as JSON *strings* on the live feed** (`"close": "83654.167"`) and as JSON *numbers* on the history feed. Both must parse to `Decimal` exactly; `parse_float=Decimal` alone does not cover the string case.
6. **Prices are never negative, never zero, never inverted** (`low <= high`), else the bar is dropped as bad data.

## Finality is three states, not one

> **This section is the second condition of the human's conditional LGTM.** REV0 said only *"Write
> only on finality"*, which is correct but **ambiguous in a dangerous direction**: read as a statement
> about the *application* rather than about *this module's output*, it forbids the hot cache from
> showing a live minute, i.e. it would force a UI to sit blank for up to 60 s and then jump. The
> intent was never that. Three distinct states, stated once, each with its own owner:

| State | What it is | Who may write it | When | Reversible? |
|---|---|---|---|---|
| **1. Forming** | the broker is still revising the current minute; `open_time = T`, re-sent ~60Ãƒâ€” | **Hot state only** (Valkey/M2.9) Ã¢â‚¬â€ M2.13 emits **nothing** | on every frame for `T` | yes Ã¢â‚¬â€ by definition, it is being replaced ~60Ãƒâ€”/min |
| **2. Canonical durable** | the finished minute, agreed by the venue | **Timescale (M2.10) only**, via M2.13's one emission | once, when a frame with `open_time > T` arrives, or on `close()` | **no** Ã¢â‚¬â€ see state 3 |
| **3. Already final** | state 2, already written | **nobody** | Ã¢â‚¬â€ | **never silently rewritten**; a contradicting frame is counted (`late_frame_count`) and dropped |

**The three-way split, stated as rules so it cannot be misread:**

- **Hot state is not a record.** A forming candle in Valkey is operational state with a TTL. It is
  *not* evidence, it is *not* queryable history, and it must never be promoted into durable history
  as though it had been finalised. The only route from forming Ã¢â€ â€™ durable is M2.13's own emission.
- **Durable is final-only, always.** There is no "provisional row" in Timescale for this slice. A
  durable row means *the venue finished this minute*. This is the whole historical-correctness
  guarantee, and it is why state 2 is written exactly once per `open_time`.
- **No third path.** A forming candle reaching a durable store by any route other than M2.13's
  emission is a defect, regardless of which component did it.

**Real-time visibility is therefore not sacrificed** Ã¢â‚¬â€ it is simply *separated* from historical
correctness instead of being traded against it. An operator sees the live minute move in the hot
cache; the durable series contains only finished minutes; and the two can never be confused because
they are different stores with different rules. This is also the same separation the project already
applies to `ticks_live` (ephemeral) vs `candles_1m` (store of record, ruling A42).

## Edges

### Bucket / finality
- `open_time` not a multiple of 60 Ã¢â€ â€™ **drop** (`invalid_timestamp`); a 1m bar cannot start mid-minute
- `open_time` in the future (> `received_at` + 5s) Ã¢â€ â€™ **drop** (`future_timestamp`)
- First frame seen is already mid-minute (we connected at `:37`) Ã¢â€ â€™ **accepted**; the broker's `open` is authoritative for the minute, we do not "fill" the missing seconds
- A frame arrives for an **already-emitted** `open_time` Ã¢â€ â€™ **ignored** (late/revised frame). Under `ON CONFLICT DO NOTHING` a rewrite would be silently dropped anyway, so acceptance would create a lie. Logged, counted.
- A frame arrives for an `open_time` **older than the buffered one** (out-of-order) Ã¢â€ â€™ **drop**, never re-open a closed bucket
- Two consecutive minutes, no gap Ã¢â€ â€™ emits the earlier one, buffers the later
- `close()` with one candle buffered Ã¢â€ â€™ emits it
- `close()` with nothing buffered Ã¢â€ â€™ returns `None`, not an error

### Bad data
- `low > high` Ã¢â€ â€™ drop
- any of O/H/L/C `<= 0` Ã¢â€ â€™ drop
- missing `open_time` or any OHLC field Ã¢â€ â€™ drop
- non-numeric / NaN / Infinity price Ã¢â€ â€™ drop, never coerced
- `epoch` missing or non-int Ã¢â€ â€™ **not fatal**; the bar is still valid, because `open_time` is the key

### Broker behaviour
- Broker returns **fewer** bars than requested (closure, weekend) Ã¢â€ â€™ accept what came, leave the rest missing
- Broker returns **zero** bars for an open window Ã¢â€ â€™ **reported as a `Discrepancy`**, never as a permanent gap and never as success
- `adjust_start_time` re-anchors the response outside the requested window Ã¢â€ â€™ every such bar falls outside the caller's window and is **dropped by the clip**; counted and surfaced
- Broker `MarketIsClosed` error on a subscribe Ã¢â€ â€™ halt that symbol, do not retry-storm

## Contract (PROVISIONAL — consumed by M4.1 registry later)

Each file exposes exactly:
- `NAME: str` — snake_case id == its capabilities.yaml `strategies:` key (eligibility
  lookups key on it: `is_strategy_eligible(NAME, broker)`).
- `FEATURE_SLOTS: dict[str, tuple[str, dict[str, float]]]` — `slot -> (analytic_name,
  param_overrides)`. The M4.1 runner builds ONE `FeatureRequest` from the union of
  slot analytics (overrides passed as `param_overrides[analytic]`) and hands
  `evaluate` a dict keyed by **slot name**. **All slot analytics within one file must
  be DISTINCT names** (the engine computes one value per analytic per request — two
  slots on the same analytic with different overrides are impossible Day-1; tested).
- `PARAM_DEFAULTS: dict[str, float]` — strategy params; effective params =
  request overrides > `PARAM_DEFAULTS` (mirrors analytic precedence; runner's job).
- `evaluate(features: dict[str, float], params: dict[str, float]) -> float` —
  signature exactly `["features", "params"]`; returns **signed strength in
  `[-1.0, +1.0]`**: positive = long, negative = short, `0.0` = no signal.
  `|value|` = strength in `[0, 1]`.
- Pure sync, deterministic, no I/O/clock/RNG/state — same Isolation Law flavor as
  analytics (no provider/clock/as_of attribute; no candles — strategies consume
  FEATURES, never raw bars).

### House strength ramp (one definition, all files)

`strength = 0.5 + 0.5 * min(1.0, progress)` — at the exact trigger threshold
`strength = 0.5`, at "full" excursion `strength = 1.0`. WHY: a trigger sitting at
exactly 0.0 would be indistinguishable from "no signal" (both `0.0`) — the ramp floor
removes that ambiguity; monotone magnitude above the threshold. `progress` is
per-file (gap %, threshold overshoot, etc.), always clamped to `1.0` at full scale.

### Input contract (all files)

`features` must contain every slot key with a **finite** value → else `ValueError`
(fail loud — a missing/NaN feature is a wiring bug, never a silent `0.0` that reads
as "flat"). `params=None` → `ValueError`; unknown param keys ignored; `params={}` →
`PARAM_DEFAULTS` applied **inside evaluate** via `params.get(key, default)` (direct
call must work, mirrors analytic defaults path). Param values validated per file
(finite, bounds) → `ValueError` (§3.13).

## Per-strategy definitions

1. **`trend_following`** (D5 family: trend_following)
   - Slots: `fast -> (ema_20, {"period": 10.0})`, `slow -> (sma_20, {"period": 20.0})`,
     `rsi -> (rsi_14, {})` — all distinct analytics ✓.
   - Params: `rsi_threshold` default 60.0 (0..100, must be > 50), `divergence_full_pct`
     default 1.0 (> 0) — gap % that maps to full strength.
   - Long: `fast > slow AND rsi >= rsi_threshold`; short: `fast < slow AND rsi <=
     100 - rsi_threshold`; else `0.0`. `progress = |fast-slow|/slow / (div/100)`.
   - Hand: `fast=101, slow=100, rsi=65` → gap 1% = full → `+1.0` exact;
     `fast=99, slow=100, rsi=35` → `−1.0` exact; `rsi=50` → `0.0`.
2. **`rsi_overbought_oversold`** (D5: momentum; A27 id — capabilities entry unchanged)
   - Slots: `rsi -> (rsi_14, {})`. Params: `overbought` 70.0, `oversold` 30.0
     (finite, `0 < oversold < overbought < 100` else ValueError).
   - Short: `rsi >= overbought`, `progress = (rsi-ob)/(100-ob)`;
     Long: `rsi <= oversold`, `progress = (os-rsi)/os`; else `0.0`.
   - Hand: `rsi=85` → `−0.75` (progress 15/30=0.5); `rsi=15` → `+0.75`;
     `rsi=100` → `−1.0`; `rsi=0` → `+1.0`; `rsi=50` → `0.0`.
3. **`mean_reversion`** (D5: mean_reversion)
   - Slots: `z -> (zscore_20, {})`. Params: `entry` 2.0 (> 0, finite).
   - `|z| >= entry` → direction `−sign(z)` (over-extended → fade it); else `0.0`.
     `progress = (|z| - entry)/entry`.
   - Hand: `z=3` → `−0.75` (progress 1/2); `z=−3` → `+0.75`; `z=4` → `−1.0`;
     `z=1` → `0.0`.
4. **`donchian_breakout`** (D5: volatility_breakout; A27 id — manifest stub fulfilled)
   - Slots: `chan -> (donchian_20, {})`, `chop -> (choppiness, {})`.
     Params: `chop_max` 38.0 (0..100 — bible regime line: chop < 38 = trending).
   - `chop >= chop_max` → `0.0` (chop regime filters breakouts — no trend to break);
     `chan > 100` → long, `progress = (chan-100)/100`;
     `chan < 0` → short, `progress = (0-chan)/100`; else `0.0`.
   - Hand: `chan=150, chop=20` → `+0.75`; `chan=150, chop=50` → `0.0`;
     `chan=−50, chop=20` → `−0.75`; `chan=50` → `0.0`; `chan=200` → `+1.0`.
5. **`pullback`** (D5: pullback) — **LONG-only Day-1, documented** (ADX measures
   strength, not direction — without a DI/price-direction feature a short-pullback
   rule would be a coin flip; honest gap, flagged for M4.1 when direction features land).
   - Slots: `trend -> (adx_14, {})`, `entry -> (zscore_20, {})`.
     Params: `adx_min` 25.0 (finite 0..100), `pullback` 1.0 (> 0).
   - `trend < adx_min` → `0.0` (no trend to pull back within);
     `entry <= -pullback` → long, `progress = (|entry| - pullback)/pullback`;
     `entry >= +pullback` → `0.0` (day-1: no short); else `0.0`.
   - Hand: `trend=30, entry=−2` → `+1.0`; `trend=30, entry=−1` → `+0.5`;
     `trend=20, entry=−3` → `0.0`; `trend=30, entry=+3` → `0.0`.
6. **`regime_based`** (D5: regime_based) — regime classifier expressed as a signed
   signal: `+1.0` = trend regime ON (deploy trend families), `−1.0` = chop regime ON
   (deploy mean-reversion families), `0.0` = neutral/mixed. Consumers (M4.1+) gate
   family selection on the sign — strength is exact `1.0`, no ramp (regime is
   categorical, not a magnitude — documenting the deliberate ramp exception).
   - Slots: `chop -> (choppiness, {})`, `hurst -> (hurst, {})`.
     Params: `chop_trend_max` 38.0, `chop_chop_min` 61.0 (both 0..100 with
     `chop_trend_max < chop_chop_min` else ValueError), `hurst_trend_min` 0.5,
     `hurst_chop_max` 0.5 (finite; `hurst_trend_min >=hurst_chop_max` enforced —
     the zones must not overlap).
   - `chop < chop_trend_max AND hurst > hurst_trend_min` → `+1.0`;
     `chop > chop_chop_min AND hurst < hurst_chop_max` → `−1.0`; else `0.0`.
   - Hand: `chop=30, hurst=0.7` → `+1.0`; `chop=70, hurst=0.3` → `−1.0`;
     `chop=30, hurst=0.4` → `0.0` (hurst disagrees — no regime); `chop=50` → `0.0`.
7. **`microstructure_flow`** (A27 id; D5 microstructure — capability-gated)
   - Slots: `imb -> (order_book_imbalance, {})` (UNAVAILABLE@deriv — the STRATEGY
     file exists and is testable; M4.1 eligibility gate returns False on deriv
     (`needs order_book_imbalance UNAVAILABLE`), so it can never be selected there.
   - Params: `long` 0.6 (finite, `0 <= long < 1`), `short` −0.6 (finite,
     `-1 < short <= 0`, must be < `long`).
   - `imb >= long` → long, `progress = (imb-long)/(1-long)`;
     `imb <= short` → short, `progress = (short-imb)/(1+short)`; else `0.0`.
   - Hand: `imb=0.8` → `+0.75` (0.2/0.4); `imb=1.0` → `+1.0` exact;
     `imb=−0.8` → `−0.75`; `imb=0.6` → `+0.5` (threshold floor); `imb=0` → `0.0`.

## Edges (one test each)

- Every file: `evaluate([], {})`-class → `ValueError` for each missing slot key
  (name the slot in the message); slot value `nan`/`inf` → `ValueError`.
- Every file: `params=None` → `ValueError`; `params={}` → defaults path produces the
  hand value; unknown param keys ignored (same result).
- Every file: out-of-range params → `ValueError` (per-file bounds above;
  `trend_following rsi_threshold=50` (not > 50), `donchian chop_max=150`,
  `mean_reversion entry=0`, `microstructure long=1.0`, `regime_based` overlapping
  hurst zones, `rsi_overbought oversold >= overbought`).
- Every file: result always within `[-1.0, 1.0]` (range invariant on goldens +
  adversarial large inputs e.g. `chan=1e9`, `z=1e6` → clamped by `min(1.0, …)`).
- Slot-analytics distinctness: `FEATURE_SLOTS` values' analytic names are unique per
  file (engine one-value-per-analytic law).
- Contract: `NAME` non-empty snake_case == capabilities key; `PARAM_DEFAULTS` all
  finite floats; `evaluate` signature exactly `["features", "params"]`; modules
  expose no `provider`/`clock`/`as_of`/`candles` attribute (Isolation flavor);
  `evaluate` deterministic (same inputs → same output, called twice).
- Discovery: iterate `strategies/` package modules (skip `_`-prefixed) → exactly the
  7 names, each passes the contract checks above (local scan in the test — M4.1 will
  own the production registry).
- Capabilities manifest (real yaml): all 7 keys present; `requires_analytics` sets
  match the slot unions; `is_strategy_eligible(..., "deriv")` → 6 × `(True, …)`,
  `microstructure_flow` → `(False, reason contains "order_book_imbalance")`.
- **Adversarial:** `features=None` → `ValueError`; hostile extra feature keys ignored
  (only slot keys read); `evaluate` called with valid inputs after a ValueError input
  still works (no state — failure never poisons the next call).

Purpose: One process-wide account mode (`demo` | `live`) shared by the auto-trading bot and (later) the frontend button. **Default = demo.** Bot/API call the same service to switch; switch back anytime.

Bible: Manual §2b Customer Runtime (“which account demo/live”); M10.2 thin API. Extends `config/accounts.yaml` + `AccountsConfig` (already complete). Frontend page is **M10.4, separate slice** — not in this backend spec.

## Scope
- In (backend only): `AccountModeService` (runtime singleton), thin FastAPI `GET/POST /api/v1/account/mode` (JSON only), backend tests in `tests/test_account_switch.py`.
- Out: real broker order routing (M6), vault token insert (placeholders already in `.env.example`), full M10 dashboard, **frontend page (deferred to M10.4)** — lives at project-root `frontend/` (outside `financial_analyst_app/`) with tests in `frontend/tests/` (moved 2026-09-25).
- **Decoupling rule:** frontend has zero backend code; backend never serves HTML/static (no FileResponse/StaticFiles). CORS allows local origins only so a future separate UI can call the API.

## Inputs / Outputs
- **Default:** `demo` on process start (bot and UI both start on demo).
- **Switch request:** `POST /api/v1/account/mode` body `{"mode": "live"|"demo"}`.
- **Hard gate:** `live` only if `settings.accounts` has at least one broker with `live.enabled: true` **or** a platform-level allow — else `409` + typed error. Switching to `demo` always allowed.
- **Permission:** `account.switch` — role `trader` or `admin` (viewer denied). Header `X-Role: trader|admin|viewer` Day-1 (JWT later).
- **Output:** JSON `{"mode": "demo", "source": "default|api|env", "live_armed": bool}`.
- **Bot path:** `AccountModeService.get_mode()` — same singleton the API mutates; no separate bot config.

## Correct
1. Fresh process → mode `demo`, source `default`.
2. `set_mode("demo")` idempotent → still demo.
3. `set_mode("live")` with live not armed → `ValueError` / HTTP 409; mode stays demo.
4. `set_mode("live")` with live armed → mode live; bot `get_mode()` sees live without restart.
5. Switch back `set_mode("demo")` → demo; source `api`.
6. Viewer POST → 403. Trader POST live armed → 200.
7. Frontend button calls POST; UI shows current mode from GET; default badge “DEMO”.

## Edges
- Concurrent POSTs → last-write-wins on mode string (atomic under lock).
- `ACCOUNT_MODE` env at boot seeds initial mode if valid; still default demo if unset.
- Invalid mode string → 422/ValueError.
- No secrets in API response.

## Adversarial
- Viewer role cannot switch.
- Live without `live.enabled` → refuse, stay demo.
- Double-click button → second POST is idempotent OK.
